> 목적: `ai_review_lab`에서 나쁜 설계와 좋은 설계를 비교하고, 메타데이터·업무 정합성·반례·경계값·최종 자동 검증 결과를 기록한다.

## 16. LEFT JOIN과 NULL 검증을 직접 설명합니다

**화면 구성**

문제 표현:

```sql
p.payment_status <> '결제완료'
```

NULL 안전 표현:

```sql
p.payment_status IS DISTINCT FROM '결제완료'
```

**발표 스크립트**

레프트 조인에서 결제 행이 없으면 payment 컬럼은 널입니다.

그런데 널과 문자열을 `<>`로 비교하면 TRUE가 아니라 UNKNOWN이 됩니다. 그래서 누락된 결제를 놓칠 수 있습니다.

워크북에는 `IS 디스팅트 FROM`이 왜 필요한지 자신의 말로 적게 합니다.

승인 상태:

```text

```

**발표 스크립트**

실습의 마지막은 실행 결과가 아니라 승인 기록입니다.

에이아이나 코덱스가 파일을 수정했다면 디프를 확인합니다. 요청하지 않은 파일이나 스키마가 바뀌었는지, 위험한 DROP이나 딜리트가 들어갔는지 봅니다.

검증 결과와 남은 가정을 근거로 승인, 조건부 승인, 보류, 거절 중 하나를 명시합니다. 검증하지 않은 항목은 통과로 표시하지 않습니다.
