## 18. Python 공통 검증은 자료형 오류를 숨기지 않습니다

**화면 구성**

검증:

```text

행 수 24
enrollment_id 중복 0
날짜 strict 변환
recorded_amount 숫자
completion_days 숫자 또는 NULL
is_completed boolean
분석 기간 안의 행
```

주의:

```text
errors='coerce' 금지
원인 없는 dropna·drop_duplicates 금지
```

**발표 스크립트**

파이썬에서 데이터를 읽은 뒤 가장 먼저 공통 검증을 합니다.

잘못된 문자열이 있을 때 `errors='coerce'`로 NaN으로 바꾸면 오류가 숨겨질 수 있습니다.

중복이나 널을 발견했을 때도 원인을 확인하지 않고 `dropna`나 `drop_duplicates`로 제거하면 분석 결과를 왜곡할 수 있습니다.

## 19. pandas 결과와 SQL 결과를 직접 비교합니다

**화면 구성**

비교 대상:

```text
상태별 집계
월별 date spine 집계
완료 기간 집계
```

PostgreSQL 경로:

```text
같은 읽기 전용 REPEATABLE READ 스냅샷
SQL DataFrame ↔ pandas DataFrame
```

CSV 경로:

```text
CSV + manifest + reference_metrics.json
```

**발표 스크립트**

판다스 분석 결과는 에스큐엘 기준 결과와 비교해야 합니다.

포스트그레스큐엘 경로에서는 같은 읽기 전용 스냅샷에서 에스큐엘 집계와 판다스 집계를 모두 읽어 직접 비교합니다.

씨에스브이 경로에서는 manifest의 해시와 기준 결과 파일을 확인합니다. 단순히 파이썬 코드 안에 기대값을 복사해 넣는 것만으로는 실제 에스큐엘 결과 검증이라고 보기 어렵습니다.

## 20. 관찰·해석·한계와 AI 코드 검토까지 기록합니다

**화면 구성**

최종 기록:

```text
관찰
해석
한계
다음 질문
AI 생성 코드 검토
최종 상태: 완료 / 조건부 완료 / 재검토 필요 / 미실행
```

AI 코드 검토:

```text
기간 조건
JOIN 경로
COUNT 단위
date spine
recorded_amount 의미
읽기 전용 연결
비밀 정보 없음
실제 SQL 결과 비교
```

**발표 스크립트**

실습의 마지막은 그래프가 아니라 해석 기록입니다.

관찰은 데이터에서 실제로 본 내용이고, 해석은 그 관찰에 대한 설명입니다. 한계는 일반화하면 안 되는 부분입니다.

에이아이가 만든 에스큐엘이나 파이썬 코드도 검토합니다. 기간 조건, 조인 경로, 카운트 단위, 비밀 정보, 읽기 전용 연결, 에스큐엘·판다스 비교가 모두 맞아야 최종 완료로 기록할 수 있습니다.
