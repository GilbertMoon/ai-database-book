## STEP 1. 데이터란 무엇일까요?

데이터(Data)는 우리가 관찰하거나 기록한 값과 사실입니다.

예를 들어 온라인 강의 서비스를 생각해 보겠습니다.

| 데이터 | 의미 |
| --- | --- |
| 김민지 | 학생 이름 |
| 20260001 | 학번 |
| 데이터베이스 입문 | 강의 이름 |
| 2026-03-02 | 수강신청일 |
| 신청 | 수강 상태 |

각각은 단순한 값이지만 서로 연결하면 하나의 의미 있는 사실이 됩니다.

```text
학번 20260001인 김민지 학생이
2026년 3월 2일에
데이터베이스 입문 강의를 신청했다.
```

데이터베이스에서는 이런 데이터를 일정한 구조로 저장하고 서로의 관계를 관리합니다.

---

## STEP 2. 데이터베이스와 DBMS는 무엇이 다를까요?

처음 데이터베이스를 공부할 때 가장 많이 헷갈리는 부분입니다.

### 데이터베이스(Database)

관련된 데이터를 일정한 구조로 저장하는 **논리적인 공간**입니다.

이번 과정에서는 뒤에서 다음과 같은 데이터베이스를 만들어 사용합니다.

```text
ai_database_book
```

### DBMS(Database Management System)

DBMS는 데이터베이스를 만들고 저장하고 조회하고 관리하는 **소프트웨어**입니다.

대표적인 DBMS에는 다음과 같은 제품이 있습니다.

- PostgreSQL
- MySQL
- MariaDB
- Oracle Database
- Microsoft SQL Server
- SQLite

이번 수업에서는 **PostgreSQL**을 사용합니다.

쉽게 구분하면 다음과 같습니다.

```text
데이터       → 실제 기록된 값
데이터베이스 → 데이터를 담는 논리적 공간
DBMS         → 데이터베이스를 관리하는 프로그램
```

즉 PostgreSQL은 데이터 자체가 아니라 데이터를 관리해 주는 DBMS입니다.

---

## STEP 3. DBeaver와 PostgreSQL은 같은 프로그램일까요?

아닙니다.

초보자가 특히 많이 혼동하는 부분입니다.

| 구성 요소 | 역할 |
| --- | --- |
| 사용자 | 질문과 SQL을 작성하고 결과를 판단 |
| DBeaver | PostgreSQL에 접속하는 클라이언트 프로그램 |
| PostgreSQL | 데이터를 저장하고 SQL을 실행하는 DBMS |
| SQL | DBMS에 전달하는 명령 언어 |

전체 흐름을 보면 더 쉽습니다.

```text
사용자
↓
DBeaver에서 SQL 작성
↓
PostgreSQL로 SQL 전달
↓
PostgreSQL이 SQL 실행
↓
결과 반환
↓
DBeaver 화면에서 결과 확인
```

따라서 **DBeaver를 설치했다고 PostgreSQL이 설치된 것은 아닙니다.**

DBeaver는 PostgreSQL을 편리하게 사용할 수 있도록 도와주는 클라이언트 도구입니다.

DBeaver를 종료해도 PostgreSQL 서버가 정상적으로 동작하고 있다면 데이터는 그대로 유지됩니다.

---

## STEP 4. PostgreSQL의 구조를 이해해 봅시다

PostgreSQL을 처음 실행하면 데이터베이스, 스키마, 테이블 같은 용어가 계속 등장합니다.

다음 구조를 먼저 기억하면 됩니다.

```text
PostgreSQL 서버
└── 데이터베이스
    └── 스키마
        └── 테이블
            ├── 행(Row)
            └── 열(Column)
```

이번 책에서 실제로 만들어 갈 구조를 단순화하면 다음과 같습니다.

```text
PostgreSQL 서버
└── ai_database_book
    ├── public
    │   └── students
    └── course_project
        ├── students
        ├── instructors
        ├── courses
        └── enrollments
```

여기에서 `ai_database_book`은 데이터베이스이고 `public`, `course_project`는 스키마입니다.

PostgreSQL에서는 다음처럼 `스키마.테이블` 형태로 테이블을 정확하게 지정할 수 있습니다.

```text
public.students
course_project.students
```

같은 `students`라는 이름의 테이블이라도 서로 다른 스키마에 존재할 수 있습니다.

---

## STEP 5. 테이블, 행, 열을 이해해 봅시다

학생 정보를 저장하는 테이블을 예로 들어 보겠습니다.

| id | name | email | major |
| ---: | --- | --- | --- |
| 1 | 김민지 | minji@example.com | 컴퓨터공학 |
| 2 | 이준호 | junho@example.com | 데이터사이언스 |
| 3 | 박서연 | seoyeon@example.com | 경영학 |

이 표 전체가 하나의 **테이블(Table)** 입니다.

### 행(Row)

가로 한 줄은 하나의 기록입니다.

```text
students 테이블의 한 행 = 학생 한 명
```

예를 들어 다음 한 줄은 김민지 학생 한 명을 나타냅니다.

```text
1 | 김민지 | minji@example.com | 컴퓨터공학
```

### 열(Column)

세로 방향의 항목은 데이터의 속성을 나타냅니다.

```text
id
name
email
major
```

### 셀(Cell)

행과 열이 만나는 하나의 값입니다.

예를 들어 김민지 학생의 `major` 값인 `컴퓨터공학`이 하나의 셀입니다.

데이터베이스를 설계할 때 가장 먼저 생각해야 하는 질문은 이것입니다.

```text
이 테이블의 한 행은 무엇을 의미하는가?
```

한 행의 의미가 명확해야 이후 SQL 결과도 정확하게 해석할 수 있습니다.

---

## STEP 6. 기본키(PK)와 외래키(FK)를 이해해 봅시다

### 기본키 Primary Key

기본키는 테이블에서 각 행을 유일하게 구분하기 위한 값입니다.

학생 테이블을 예로 들면 다음과 같습니다.

| id | name |
| ---: | --- |
| 1 | 김민지 |
| 2 | 이준호 |
| 3 | 박서연 |

여기서 `id`를 기본키로 사용하면 학생마다 서로 다른 값이 있어야 합니다.

```text
id = 1 → 김민지
id = 2 → 이준호
id = 3 → 박서연
```

이름은 같은 사람이 있을 수 있으므로 이름만으로 학생을 구분하는 것은 위험합니다.

### 외래키 Foreign Key

외래키는 다른 테이블의 행을 참조하여 **테이블 사이의 관계를 표현**하는 데 사용합니다.

예를 들어 수강신청 데이터를 생각해 보겠습니다.

```text
students
id = 1 → 김민지

courses
id = 10 → 데이터베이스 입문

 enrollments
student_id = 1
course_id = 10
```

이렇게 하면 다음 의미를 표현할 수 있습니다.

```text
학생 1번 김민지가
강의 10번 데이터베이스 입문을 신청했다.
```

핵심은 다음 두 문장입니다.

```text
기본키(PK) → 자신의 테이블에서 행을 구분한다.
외래키(FK) → 다른 테이블과의 관계를 연결한다.
```

자세한 제약조건과 관계 설계는 뒤의 Chapter에서 직접 PostgreSQL로 실습합니다.

## STEP 7. 테이블에 저장된 순서를 믿으면 안 됩니다

데이터를 표로 보면 위에서 아래로 순서가 있는 것처럼 보입니다.

하지만 관계형 데이터베이스에서는 조회할 때 원하는 순서를 명시하지 않으면 결과 순서를 보장한다고 생각하면 안 됩니다.

예를 들어 학생을 이름순으로 보고 싶다면 나중에 다음과 같은 SQL을 사용하게 됩니다.

```sql
SELECT id, name, email, major
FROM students
ORDER BY name;
```

지금은 SQL 문법을 외우지 않아도 됩니다.

다음 원칙만 기억하면 됩니다.

```text
원하는 조회 순서가 있다면 ORDER BY로 명시한다.
```

## STEP 8. AI가 만든 테이블 구조도 그대로 믿으면 안 됩니다

ChatGPT나 Codex에게 다음처럼 요청할 수 있습니다.

```text
온라인 강의 서비스에 필요한 학생, 강의,
수강신청 테이블을 PostgreSQL 기준으로 설계해 주세요.
```

AI는 매우 빠르게 테이블 구조를 제안할 수 있습니다.

하지만 결과를 받으면 최소한 다음을 확인해야 합니다.

```text
1. 각 테이블의 한 행은 무엇을 의미하는가?
2. 각 행을 구분하는 기본키가 있는가?
3. 테이블 사이의 관계가 외래키로 적절하게 표현됐는가?
4. 같은 데이터를 불필요하게 반복 저장하고 있지 않은가?
5. 필수값과 중복 허용 여부가 업무 요구사항과 맞는가?
```

AI가 SQL을 작성해 주는 시대에는 SQL을 빨리 작성하는 능력만큼 **AI가 만든 구조를 검증하는 능력**이 중요합니다.

```text
나는 데이터베이스를 처음 배우는 초보자입니다.

데이터, 데이터베이스, DBMS의 차이를
```

## AI 활용 실습 2. 테이블 구조를 검토해 보기

다음과 같은 간단한 테이블을 AI에게 보여 주세요.

```text
students
- id
- name
- email

courses
- id
- title

 enrollments
- id
- student_id
- course_id
```

그리고 다음과 같이 질문합니다.


## 오늘의 핵심 정리

이번 Chapter에서 꼭 기억할 내용은 다음과 같습니다.

```text
데이터
→ 기록된 값과 사실

데이터베이스
→ 관련 데이터를 구조적으로 저장하는 논리적 공간

DBMS
→ 데이터베이스를 관리하는 소프트웨어

DBeaver
→ PostgreSQL에 접속해 SQL을 실행할 수 있게 도와주는 클라이언트

테이블의 한 행
→ 하나의 업무 기록

기본키(PK)
→ 자신의 테이블에서 행을 구분

외래키(FK)
→ 다른 테이블과의 관계를 연결
```

그리고 AI 시대에는 다음 질문을 습관처럼 하는 것이 중요합니다.

```text
이 테이블의 한 행은 무엇을 의미하는가?
이 값은 어떻게 구분되는가?
다른 데이터와 어떤 관계가 있는가?
AI가 만든 구조가 실제 업무 규칙과 맞는가?
```
