# AI 시대의 데이터베이스 입문 · 네이버 블로그 발행 체크리스트

이 문서는 `blog/chapter01`~`blog/chapter15`의 네이버 블로그용 Markdown 파일을 실제 네이버 블로그에 게시할 때 사용하는 공통 발행·검수 체크리스트입니다.

목표는 단순히 글을 올리는 것이 아니라 **15강 전체를 하나의 일관된 수업 시리즈로 게시하고, 독자가 그대로 따라 실습할 수 있는 상태인지 마지막으로 확인하는 것**입니다.

관련 문서:

- 전체 목차: [`index.md`](index.md)
- 썸네일 문구 가이드: [`thumbnail_guide.md`](thumbnail_guide.md)

# 1. 게시 전 준비

각 Chapter를 게시하기 전에 다음 항목을 확인합니다.

- [ ] 게시할 Chapter 번호를 확인했다.
- [ ] 해당 `chapterXX_naver.md`가 최신 버전인지 확인했다.
- [ ] 이전 Chapter와 다음 Chapter의 순서를 확인했다.
- [ ] 썸네일 문구를 `thumbnail_guide.md`에서 확인했다.
- [ ] 본문에서 사용하는 SQL, Python, 파일명, 테이블명이 실제 수업 자료와 일치하는지 확인했다.
- [ ] 실습 순서가 초보자도 위에서 아래로 그대로 따라갈 수 있게 구성되어 있는지 확인했다.

# 2. 게시 제목 규칙

게시물 제목은 다음 형식을 기본으로 사용합니다.

```text
[AI 시대의 데이터베이스 입문 01] AI 시대에도 데이터베이스를 배워야 할까?
```

공통 규칙:

- [ ] Chapter 번호는 `01`~`15`의 두 자리 숫자로 작성했다.
- [ ] 제목 앞부분의 시리즈명을 통일했다.
- [ ] 검색을 위해 해당 Chapter의 핵심 키워드를 제목에 자연스럽게 포함했다.
- [ ] 제목이 지나치게 길거나 같은 단어를 반복하지 않는지 확인했다.

# 4. Markdown을 네이버 에디터로 옮긴 뒤 확인할 항목

Markdown 파일을 네이버 블로그 에디터로 옮기면 서식이 그대로 유지되지 않을 수 있으므로 다음 항목을 다시 확인합니다.

## 제목과 소제목

- [ ] 본문 최상단의 제목이 게시물 제목과 중복되어 어색하지 않은지 확인했다.
- [ ] 큰 단락과 작은 단락의 단계가 시각적으로 구분된다.
- [ ] 소제목 사이에 충분한 여백이 있다.

## 본문 문단

- [ ] 한 문단이 지나치게 길지 않다.
- [ ] 핵심 개념은 굵게 표시되어 있다.
- [ ] 중요한 설명은 모바일에서도 쉽게 읽힌다.
- [ ] 불필요한 Markdown 기호(`#`, `**`, 백틱 등)가 본문에 그대로 노출되지 않는다.

## 코드

- [ ] SQL 코드가 일반 본문과 명확히 구분된다.
- [ ] Python 코드가 일반 본문과 명확히 구분된다.
- [ ] 들여쓰기와 줄바꿈이 깨지지 않았다.
- [ ] 긴 SQL 문장이 가독성 있게 줄바꿈되어 있다.
- [ ] 복사해서 실행하는 코드에 설명용 가짜 값이나 생략 기호가 섞여 있지 않다.

## 표와 목록

- [ ] Markdown 표가 네이버 에디터에서 읽기 어렵게 깨지지 않았다.
- [ ] 표가 복잡하면 목록 또는 이미지로 바꾸는 것이 더 좋은지 확인했다.
- [ ] 번호 목록의 순서가 깨지지 않았다.
- [ ] 체크리스트나 글머리표가 중복 표시되지 않는다.

# 5. 실습 코드 최종 검수

데이터베이스 수업 글은 설명보다 **실제로 실행되는지**가 중요합니다.

- [ ] SQL 키워드와 식별자에 오타가 없다.
- [ ] PostgreSQL 문법 기준으로 작성되어 있다.
- [ ] 테이블 생성 순서가 FK 관계와 맞는다.
- [ ] 데이터 입력 순서가 FK 관계와 맞는다.
- [ ] `INSERT`, `UPDATE`, `DELETE` 실행 전후의 상태가 설명과 일치한다.
- [ ] 트랜잭션 예제에서 `COMMIT`과 `ROLLBACK`의 의미가 명확하다.
- [ ] `EXPLAIN` 또는 `EXPLAIN ANALYZE` 예제의 설명이 실행 결과와 모순되지 않는다.
- [ ] 보안·백업·복구 명령은 실행 위치와 전제조건이 설명되어 있다.
- [ ] Python 코드의 패키지 import와 변수명이 앞뒤 코드와 일치한다.

---

# 6. AI 활용 내용 검수

이 시리즈는 ChatGPT와 Codex를 활용하지만, AI가 만든 결과를 그대로 정답으로 취급하지 않는 것이 핵심입니다.

- [ ] AI에게 맡길 작업과 사람이 판단할 작업이 구분되어 있다.
- [ ] AI 생성 SQL은 실행 결과로 검증하도록 안내한다.
- [ ] AI가 요구사항에 없는 제약조건이나 컬럼을 임의로 추가할 수 있음을 설명한다.
- [ ] 중요한 설계 판단에는 이유 또는 검증 기준이 제시되어 있다.
- [ ] AI 답변을 복사하는 것보다 질문 → 실행 → 검증 흐름이 강조되어 있다.

# 7. 링크 확인

- [ ] 외부 링크가 정상적으로 열린다.
- [ ] GitHub 링크가 올바른 파일 또는 폴더를 가리킨다.
- [ ] 이미지 링크가 깨지지 않는다.
- [ ] 이전 글 링크가 정상적으로 열린다.
- [ ] 다음 글이 이미 게시되었다면 다음 글 링크가 정상적으로 열린다.
- [ ] 전체 목차 글 링크가 정상적으로 열린다.

첫 글과 마지막 글은 예외 처리합니다.

```text
Chapter 01: 이전 글 없음
Chapter 15: 다음 글 없음
```

# 8. 글 하단 공통 구성

각 Chapter의 마지막에는 가능하면 다음 흐름을 유지합니다.

```text
이번 Chapter 핵심 정리
→ 직접 확인할 실습 포인트
→ 다음 Chapter 예고
→ 전체 목차 또는 시리즈 안내
→ 태그
```

확인 항목:

- [ ] 이번 Chapter에서 배운 내용을 3~5개 핵심 포인트로 정리했다.
- [ ] 다음 Chapter로 자연스럽게 연결되는 문장이 있다.
- [ ] 시리즈 전체 목차로 돌아갈 수 있는 안내가 있다.
- [ ] 같은 홍보 문구를 지나치게 반복하지 않는다.

# 9. 태그 확인

태그는 너무 많이 넣기보다 글의 실제 내용과 관련된 핵심어를 우선합니다.

공통 후보:

```text
#데이터베이스
#PostgreSQL
#SQL
#DBeaver
#ChatGPT
#Codex
#AI활용
#데이터모델링
#Python
#pandas
```

Chapter에 따라 다음처럼 교체하거나 추가할 수 있습니다.

```text
#ERD
#정규화
#JOIN
#트랜잭션
#인덱스
#EXPLAIN
#데이터베이스백업
#NoSQL
#데이터분석
```

- [ ] 글 내용과 직접 관련된 태그를 선택했다.
- [ ] 같은 의미의 태그를 과도하게 반복하지 않았다.
- [ ] Chapter 핵심 키워드가 태그에 포함되어 있다.

# 완료 기준

각 Chapter는 단순히 Markdown 파일이 존재한다고 완료된 것이 아닙니다.

다음 네 가지가 모두 충족되었을 때 실제 발행 완료로 봅니다.

```text
1. 내용과 코드가 검수되었다.
2. 썸네일과 본문 서식이 준비되었다.
3. 네이버 블로그에 정상 게시되었다.
4. 공개 페이지에서 링크와 모바일 화면까지 확인했다.
```

15개 Chapter 모두 이 기준을 통과하면 **네이버 블로그용 수업 시리즈 발행 작업 완료**입니다.
