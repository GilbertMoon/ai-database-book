# [AI 시대의 데이터베이스 입문 04] PostgreSQL로 SQL CRUD 처음부터 실습하기

안녕하세요. 아토믹데브입니다.

앞의 Chapter 03에서는 PostgreSQL과 DBeaver를 설치하고 `ai_database_book` 데이터베이스까지 준비했습니다.

이번 시간부터는 실제로 테이블을 만들고 데이터를 입력·조회·수정·삭제해 봅니다. SQL을 처음 배우는 분도 그대로 따라 할 수 있도록 **CREATE TABLE → INSERT → SELECT → UPDATE → DELETE** 순서로 진행하겠습니다.

이번 장에서 가장 중요한 것은 문법을 외우는 것이 아닙니다.

```text
SQL 읽기
→ 실행 전 예상하기
→ 실행 범위 확인하기
→ 실행하기
→ 실제 결과 확인하기
```

이 흐름을 익히면 이후 JOIN, 트랜잭션, 인덱스 실습도 훨씬 안전하게 진행할 수 있습니다.

## 오늘 배울 내용

이번 글을 끝까지 따라오면 다음 작업을 할 수 있습니다.

- `public.students` 테이블 생성
- 학생 데이터 입력
- 필요한 데이터 조회
- 조건 검색과 정렬
- `NULL` 처리
- 데이터 수정
- 데이터 삭제
- 기본키와 제약조건 이해
- AI가 만든 SQL을 실행 전에 검토

## STEP 1. 먼저 현재 연결을 확인합니다

SQL을 실행하기 전에 가장 먼저 확인해야 하는 것은 **어느 데이터베이스에 연결되어 있는가**입니다.

DBeaver에서 SQL Editor를 열고 다음 SQL을 실행합니다.

```sql
SELECT current_database();
SELECT current_user;
SELECT current_schema();
SHOW search_path;
```

다음 내용을 확인합니다.

```text
현재 데이터베이스가 ai_database_book인가?
예상한 사용자로 접속되어 있는가?
현재 스키마는 무엇인가?
search_path는 어떻게 설정되어 있는가?
```

초보자에게 가장 흔한 실수 중 하나가 **다른 데이터베이스에서 SQL을 실행하는 것**입니다.

SQL이 맞아도 실행 위치가 틀리면 원하는 결과가 나오지 않습니다.

---

## STEP 2. SQL의 기본 작성 규칙을 익혀 봅시다

이번 과정에서는 다음 스타일을 사용합니다.

```text
SQL 키워드       → 대문자
테이블/열 이름   → 소문자 snake_case
문자열           → 작은따옴표
숫자             → 따옴표 없이 작성
문장 끝          → 세미콜론
주석             → --
```

예를 들어 다음과 같습니다.

```sql
SELECT *
FROM public.students
WHERE major = '컴퓨터공학'
  AND grade = 2;
```

문자열은 작은따옴표를 사용합니다.

```text
'김민지'
'컴퓨터공학'
```

숫자는 따옴표 없이 작성합니다.

```text
1
2
100
```

## STEP 3. 첫 번째 테이블을 만들어 봅시다

이번 실습에서는 학생 정보를 저장할 `students` 테이블을 사용합니다.

```text
테이블: public.students
한 행: 학생 한 명
```

다음 SQL을 실행합니다.

```sql
CREATE TABLE public.students (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    major VARCHAR(100),
    grade INTEGER,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

각 항목의 의미를 살펴보겠습니다.

| 구성 | 의미 |
| --- | --- |
| `CREATE TABLE` | 새 테이블 생성 |
| `public.students` | public 스키마의 students 테이블 |
| `INTEGER` | 정수 타입 |
| `VARCHAR(50)` | 최대 50자의 문자열 |
| `PRIMARY KEY` | 각 행을 고유하게 구분 |
| `NOT NULL` | NULL 값 저장 금지 |
| `UNIQUE` | 중복값 제한 |
| `DEFAULT` | 값을 생략했을 때 사용할 기본값 |
| `IDENTITY` | 번호 자동 생성 |

테이블 생성 후 DBeaver에서 다음 위치를 새로고침합니다.

```text
Schemas
→ public
→ Tables
→ students
```

`students` 테이블이 보이면 성공입니다.

---

## STEP 4. 테이블의 열을 읽어 봅시다

이번 테이블의 구조는 다음과 같습니다.

| 열 | 타입 | 의미 |
| --- | --- | --- |
| `id` | INTEGER | 학생 내부 식별자 |
| `name` | VARCHAR(50) | 이름 |
| `email` | VARCHAR(100) | 이메일 |
| `major` | VARCHAR(100) | 전공 |
| `grade` | INTEGER | 학년 |
| `created_at` | TIMESTAMPTZ | 등록 시각 |

여기에서 가장 중요한 열은 `id`입니다.

```text
id = 학생 한 명을 데이터베이스 내부에서 구분하는 값
```

`name`은 같은 사람이 있을 수 있기 때문에 기본키로 사용하기 어렵습니다.

`email`에는 `UNIQUE`가 있으므로 같은 이메일을 중복해서 저장하는 것을 제한합니다.

---

## STEP 5. INSERT로 첫 데이터를 입력합니다

다음 SQL을 실행합니다.

```sql
INSERT INTO public.students (name, email, major, grade)
VALUES ('김민지', 'minji@example.com', '컴퓨터공학', 2);
```

`id`와 `created_at`은 직접 입력하지 않았습니다.

PostgreSQL이 자동으로 값을 생성합니다.

입력 후 확인합니다.

```sql
SELECT *
FROM public.students;
```

정상적으로 입력되었다면 김민지 학생 한 행이 조회됩니다.

---

## STEP 6. 여러 행을 한 번에 입력해 봅시다

다음과 같이 여러 학생을 한 번에 입력할 수도 있습니다.

```sql
INSERT INTO public.students (name, email, major, grade)
VALUES
    ('이준호', 'junho@example.com', '데이터사이언스', 3),
    ('박서연', 'seoyeon@example.com', '경영학', 1),
    ('최유진', 'yujin@example.com', '컴퓨터공학', 4),
    ('정민수', 'minsu@example.com', NULL, 2);
```

여기에서 정민수 학생의 `major`는 `NULL`입니다.

`NULL`은 빈 문자열과 다릅니다.

```text
NULL
→ 값이 없거나 아직 정해지지 않은 상태
```

---

## STEP 7. SELECT로 데이터를 조회합니다

모든 학생을 조회해 봅시다.

```sql
SELECT *
FROM public.students;
```

필요한 열만 조회할 수도 있습니다.

```sql
SELECT id, name, major
FROM public.students;
```

SQL에서 `*`는 모든 열을 의미합니다.

하지만 실무에서는 필요한 열을 명시적으로 선택하는 것이 더 좋은 경우가 많습니다.

---

## STEP 8. WHERE로 원하는 데이터만 찾습니다

컴퓨터공학 전공 학생만 조회합니다.

```sql
SELECT id, name, major, grade
FROM public.students
WHERE major = '컴퓨터공학';
```

2학년 학생만 조회합니다.

```sql
SELECT id, name, major, grade
FROM public.students
WHERE grade = 2;
```

두 조건을 모두 만족해야 한다면 `AND`를 사용합니다.

```sql
SELECT id, name, major, grade
FROM public.students
WHERE major = '컴퓨터공학'
  AND grade = 2;
```

둘 중 하나만 만족해도 된다면 `OR`를 사용합니다.

```sql
SELECT id, name, major, grade
FROM public.students
WHERE major = '컴퓨터공학'
   OR major = '데이터사이언스';
```

---

## STEP 9. IN을 사용하면 조건을 더 읽기 쉽게 만들 수 있습니다

다음 SQL은 앞의 `OR` 조건과 비슷한 의미입니다.

```sql
SELECT id, name, major
FROM public.students
WHERE major IN ('컴퓨터공학', '데이터사이언스');
```

값이 여러 개인 조건에서는 `IN`이 더 읽기 쉬운 경우가 많습니다.

---

## STEP 10. NULL은 `=`로 비교하지 않습니다

전공이 없는 학생을 찾는다고 가정해 보겠습니다.

다음처럼 작성하면 안 됩니다.

```sql
SELECT *
FROM public.students
WHERE major = NULL;
```

`NULL`은 일반 값과 다르게 처리합니다.

다음처럼 작성해야 합니다.

```sql
SELECT *
FROM public.students
WHERE major IS NULL;
```

반대로 NULL이 아닌 행은 다음과 같습니다.

```sql
SELECT *
FROM public.students
WHERE major IS NOT NULL;
```

핵심은 다음입니다.

```text
NULL 확인
→ IS NULL
→ IS NOT NULL
```

---

## STEP 11. ORDER BY로 정렬합니다

학생 이름순으로 조회합니다.

```sql
SELECT id, name, major, grade
FROM public.students
ORDER BY name;
```

학년을 높은 순서로 정렬하려면 `DESC`를 사용합니다.

```sql
SELECT id, name, major, grade
FROM public.students
ORDER BY grade DESC;
```

낮은 순서는 `ASC`이며 기본값입니다.

```sql
ORDER BY grade ASC;
```

관계형 데이터베이스에서는 원하는 순서를 보장받으려면 `ORDER BY`를 명시하는 습관이 중요합니다.

---

## STEP 12. LIMIT으로 조회 개수를 제한합니다

처음 3행만 보고 싶다면 다음과 같이 작성합니다.

```sql
SELECT id, name, major, grade
FROM public.students
ORDER BY id
LIMIT 3;
```

데이터가 많은 테이블을 확인할 때 유용합니다.

---

## STEP 13. UPDATE 전에 반드시 SELECT로 대상을 확인합니다

예를 들어 김민지 학생의 학년을 3학년으로 수정한다고 가정하겠습니다.

먼저 대상을 확인합니다.

```sql
SELECT id, name, grade
FROM public.students
WHERE email = 'minji@example.com';
```

정확한 학생이 조회되는 것을 확인한 뒤 수정합니다.

```sql
UPDATE public.students
SET grade = 3
WHERE email = 'minji@example.com';
```

다시 확인합니다.

```sql
SELECT id, name, grade
FROM public.students
WHERE email = 'minji@example.com';
```

변경 SQL은 항상 다음 순서를 권장합니다.

```text
SELECT로 대상 확인
→ UPDATE 실행
→ 다시 SELECT로 결과 확인
```

---

## STEP 14. WHERE 없는 UPDATE는 특히 주의합니다

다음 SQL을 생각해 보겠습니다.

```sql
UPDATE public.students
SET grade = 1;
```

`WHERE` 조건이 없습니다.

이 SQL은 **모든 학생의 grade를 1로 변경할 수 있습니다.**

따라서 UPDATE와 DELETE를 실행하기 전에는 반드시 영향받을 행을 먼저 확인해야 합니다.

AI가 만든 SQL도 마찬가지입니다.

실행 전에 다음 질문을 확인합니다.

```text
WHERE 조건이 있는가?
몇 행이 영향을 받는가?
내가 의도한 행만 변경되는가?
```

---

## STEP 15. DELETE도 먼저 SELECT로 확인합니다

예를 들어 특정 학생을 삭제한다고 가정하겠습니다.

먼저 확인합니다.

```sql
SELECT id, name, email
FROM public.students
WHERE email = 'seoyeon@example.com';
```

정확한 행인지 확인한 뒤 삭제합니다.

```sql
DELETE FROM public.students
WHERE email = 'seoyeon@example.com';
```

다시 확인합니다.

```sql
SELECT *
FROM public.students
WHERE email = 'seoyeon@example.com';
```

조회 결과가 없다면 삭제된 것입니다.

---

## STEP 16. CRUD를 한 번에 정리해 봅시다

데이터베이스의 기본 작업은 CRUD라고 부릅니다.

| CRUD | SQL | 의미 |
| --- | --- | --- |
| Create | `INSERT` | 데이터 추가 |
| Read | `SELECT` | 데이터 조회 |
| Update | `UPDATE` | 데이터 수정 |
| Delete | `DELETE` | 데이터 삭제 |

여기서 헷갈리기 쉬운 점이 있습니다.

```text
CRUD의 Create
→ INSERT
```

`CREATE TABLE`은 데이터를 추가하는 것이 아니라 **데이터를 저장할 구조를 만드는 SQL**입니다.

---

## STEP 17. 제약조건이 왜 필요한지 확인해 봅시다

이번 테이블에는 다음 제약조건이 있습니다.

```text
PRIMARY KEY
NOT NULL
UNIQUE
DEFAULT
```

예를 들어 같은 이메일을 다시 입력해 보겠습니다.

```sql
INSERT INTO public.students (name, email, major, grade)
VALUES ('다른학생', 'minji@example.com', '경영학', 1);
```

`email`에 `UNIQUE` 제약조건이 있기 때문에 중복 입력 오류가 발생할 수 있습니다.

이 오류는 나쁜 것이 아닙니다.

오히려 데이터베이스가 잘못된 데이터를 막아 주고 있다는 의미입니다.

```text
제약조건
→ 데이터 오류를 예방하는 규칙
```

## 오늘의 핵심 정리

이번 Chapter에서는 SQL의 가장 기본적인 CRUD 흐름을 직접 다뤘습니다.

```text
CREATE TABLE
→ 데이터를 저장할 구조 생성

INSERT
→ 데이터 추가

SELECT
→ 데이터 조회

UPDATE
→ 데이터 수정

DELETE
→ 데이터 삭제
```

그리고 변경 SQL에서는 다음 원칙을 꼭 기억합니다.

```text
UPDATE/DELETE 실행 전
→ SELECT로 대상 행 확인

실행 후
→ 다시 SELECT로 결과 확인
```

AI가 SQL을 만들어 주더라도 다음 세 가지는 사람이 직접 확인해야 합니다.

```text
어느 데이터베이스에서 실행하는가?
어떤 행이 영향을 받는가?
실행 결과가 실제 요구사항과 맞는가?
```
