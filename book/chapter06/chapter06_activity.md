## 정규화와 데이터 무결성으로 좋은 테이블 만들기

## 1. 워크북 활용 방법

이 장의 핵심 흐름은 다음과 같습니다.

```text
한 행의 의미 확인
→ 컬럼의 주인 찾기
→ 이상 현상 분석
→ 1NF·2NF·3NF 이해
→ 정규화 구조 작성
→ 미확정 정책 확인
→ 확정 규칙과 제약조건 연결
→ 정상·경계·오류 데이터 테스트
→ AI 설계 검토
```

사용 파일:


## 26. 권장 해설

### 위험한 중복과 이상 현상

```text
회원 이메일이나 도서 제목을 여러 대여 행에 복사해 관리하는 것은 위험한 중복이다.
member_id가 여러 대여 행에 반복되는 것은 정상적인 관계 표현이다.
삽입·수정·삭제 이상은 SQL 문법이 아니라 테이블 경계의 문제다.
```

### 정규형

```text
1NF: 한 셀의 다중값과 반복 열을 피한다.
2NF: 복합키 일부에만 의존하는 컬럼을 주인 테이블로 옮긴다.
3NF: 일반 컬럼이 다른 일반 컬럼을 결정하는 업무 규칙을 확인한다.
```

### 함수적 종속

```text
X → Y는 같은 X 값이면 업무 규칙상 Y도 항상 같아야 한다는 뜻이다.
샘플 값의 우연한 반복만으로는 함수적 종속을 확정할 수 없다.
```

### 제약조건과 활성 대여

```text
PRIMARY KEY: 행 식별
NOT NULL: 필수값 누락 차단
UNIQUE: 확정된 고유값 중복 차단
CHECK: 한 행의 값 범위와 순서 확인
FOREIGN KEY: 존재하는 부모 참조
부분 고유 인덱스: returned_at IS NULL인 대여만 book_id 고유성 적용
RESTRICT: 참조 중 부모 삭제 차단
```

### 오류 후 트랜잭션

```sql
ROLLBACK;
```

수동 커밋이나 명시적 트랜잭션 안에서 오류 후 실패 상태가 되었다면 `ROLLBACK`으로 종료한 뒤 다음 테스트를 진행합니다.

### 주문 당시 가격

```text
products.current_price는 현재 사실이고,
order_items.unit_price는 주문 사건 당시 사실이다.
의미와 변경 시점이 다르므로 두 값을 별도로 저장할 수 있다.
```
