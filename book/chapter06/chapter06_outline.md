## 이 장의 역할

Chapter 06은 정규형 이름을 암기하거나 가능한 제약조건을 모두 추가하는 장이 아니다. 같은 사실의 복사본이 불일치하는 위험을 줄이고, 확정된 업무 규칙이 정상값은 허용하면서 잘못된 값과 관계는 차단하는지 검증하는 장이다.

```text
한 행의 의미 확인
→ 위험한 중복과 이상 현상 분석
→ 열의 주인 결정
→ 1NF·2NF·3NF 질문 적용
→ 정규화된 구조 작성
→ 정책 확정
→ 기존 데이터 검사
→ 제약조건 추가
→ 정상·경계·오류 테스트
```

## 이 장을 마치면

- 위험한 중복과 정상적인 반복을 구분한다.
- 삽입·수정·삭제 이상을 설명한다.
- 각 열의 주인 테이블을 판단한다.
- 1NF·2NF·3NF의 핵심 질문을 적용한다.
- 확정 규칙을 적절한 제약조건과 연결한다.
- 정규화와 무결성 제약조건의 역할을 구분한다.
- 정상·경계·오류 데이터로 규칙을 검증한다.
- 기존 데이터가 있는 테이블에 규칙을 추가하기 전 영향 범위를 확인한다.

## 정규형 편집 기준

```text
1NF
→ 각 속성의 도메인과 반복 그룹을 확인하고, 독립적으로 다룰 반복값을 쉼표 목록·반복 열에 묶지 않음

2NF
→ 비키 속성이 후보키 일부에만 의존하는 부분 종속을 분리

3NF
→ 비키 속성이 다른 비키 속성을 통해 후보키에 전이적으로 의존하는지 확인
```

JSON·배열을 무조건 1NF 위반이라고 단정하지 않고 저장 목적과 조회 패턴에 따라 판단하며 Chapter 12로 연결한다.

## NULL 설명 기준

- `NOT NULL`은 열의 최종 저장값이 `NULL`이 되는 것을 막는다. 열을 생략해도 `DEFAULT`가 있으면 저장될 수 있다.
- PostgreSQL `CHECK`는 결과가 `TRUE` 또는 `NULL`이면 통과하므로 필수값에는 `NOT NULL`이 별도로 필요하다.
- PostgreSQL의 기본 `UNIQUE`는 여러 `NULL`을 허용하며, 필요하면 `NULLS NOT DISTINCT`를 검토할 수 있다.
