# Chapter 06 구성안

## 제목

정규화와 데이터 무결성으로 좋은 테이블 만들기

## 권장 분량

26~30페이지

## 이 장의 역할

Chapter 05에서 만든 데이터 모델을 대상으로 중복과 이상 현상을 분석하고, 제1·제2·제3정규형 수준에서 구조를 개선한다. 이어서 Chapter 05의 미확정 정책 가운데 실습에 필요한 규칙을 확정하고, `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`, 부분 고유 인덱스와 삭제 정책으로 구현한다.

```text
사실이 잘못된 테이블에 저장되는 문제
+ 잘못된 값과 관계가 저장되는 문제
+ 미확정 정책을 임의로 제약조건화하는 문제
```

## 핵심 질문

```text
한 행은 하나의 분명한 사실을 나타내는가?
각 컬럼의 주인은 누구인가?
같은 사실의 복사본이 여러 곳에 저장되는가?
어떤 정책이 확정되었고 어떤 정책이 범위 밖인가?
정상값과 경계값은 허용되고 오류값은 차단되는가?
같은 도서의 활성 대여를 한 건으로 제한할 수 있는가?
삭제 정책에 업무 근거가 있는가?
```

## 독자가 얻게 될 것

- 위험한 중복과 정상적인 반복을 구분할 수 있다.
- 삽입·수정·삭제 이상을 설명할 수 있다.
- 컬럼의 주인과 한 행의 의미를 판단할 수 있다.
- 함수적 종속의 기초를 설명할 수 있다.
- 제1·제2·제3정규형의 핵심 질문을 구분할 수 있다.
- 수강 예제의 단순화 가정과 재수강·학기·분반 확장을 구분할 수 있다.
- 도서 대여 원시 테이블을 회원·도서·대여 테이블로 분리할 수 있다.
- 미확정 정책과 확정 규칙을 구분할 수 있다.
- `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`를 적용할 수 있다.
- 부분 고유 인덱스로 미반납 대여 중복을 차단할 수 있다.
- 정상·경계·오류 데이터로 제약조건을 검증할 수 있다.
- 명시적 ID 입력 뒤 IDENTITY 시작값을 조정할 수 있다.
- `RESTRICT`, `NO ACTION`, `CASCADE`, `SET NULL`을 업무 관점에서 검토할 수 있다.
- 실패한 트랜잭션 상태에서 `ROLLBACK`이 필요한 상황을 설명할 수 있다.
- 과도한 테이블 분리와 AI 제약조건 제안을 검토할 수 있다.

## 단순화 범위

```text
- 이메일 대소문자·별칭 정규화는 다루지 않는다.
- 동일 ISBN 복본을 별도 사본으로 관리하는 모델은 다루지 않는다.
- 여러 저자 관계는 다루지 않는다.
- 과거 대여 기간 전체의 중첩 검사는 다루지 않는다.
- 현재 미반납 대여의 중복만 차단한다.
- 운영 데이터 정제·병합·마이그레이션은 다루지 않는다.
- BCNF·4NF·5NF는 입문 범위에서 제외한다.
```

## 실습 테이블

```text
public.library_records_raw
public.members_nf
public.books_nf
public.loans_nf
```

| 테이블 | 역할 |
| --- | --- |
| `library_records_raw` | 회원·도서·대여 사실이 섞인 정규화 전 구조 |
| `members_nf` | 회원의 현재 정보 |
| `books_nf` | 도서의 현재 정보 |
| `loans_nf` | 회원과 도서를 연결하는 대여 사건 |

## 핵심 DDL

```sql
CREATE TABLE public.members_nf (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    joined_at DATE NOT NULL,
    CONSTRAINT uq_members_nf_email UNIQUE (email),
    CONSTRAINT chk_members_nf_name_not_blank
        CHECK (char_length(trim(name)) > 0)
);

CREATE UNIQUE INDEX uq_loans_nf_active_book
ON public.loans_nf (book_id)
WHERE returned_at IS NULL;
```

`published_year >= 1000`처럼 요구사항 근거가 없는 `CHECK`는 제거한다.

## 샘플 기준

| 테이블 | 행 수 | ID |
| --- | ---: | --- |
| `library_records_raw` | 3 | 1001~1003 |
| `members_nf` | 2 | 101, 102 |
| `books_nf` | 2 | 201, 202 |
| `loans_nf` | 3 | 1001~1003 |

```text
대여 1001: 도서 201, 4월 2일 반납
대여 1002: 도서 202, 미반납
대여 1003: 도서 201, 4월 3일 시작·미반납
```

따라서 회원 101과 도서 201의 대여 기록은 각각 2건이고, 미반납은 2건이며 동일 도서의 동시 활성 대여는 없다.

## 오류·경계 테스트

```text
허용: due_at = borrowed_at
허용: returned_at = borrowed_at
허용: returned_at = NULL
허용: published_year = NULL
허용: 한 글자 이름
실패: 이름 NULL
실패: 중복 이메일·ISBN
실패: 공백 이름·제목
실패: 없는 회원 참조
실패: 잘못된 날짜 순서
실패: 두 번째 미반납 대여
실패: 참조 중 부모 삭제
```

수동 커밋 상태에서 오류 후 트랜잭션이 실패 상태가 되면 `ROLLBACK;`을 실행하도록 안내한다.

## 편집 원칙

- 모든 위치 확인에 `current_database()`, `current_schema()`, `SHOW search_path`를 사용한다.
- 모든 주요 객체에 `public` 스키마를 명시한다.
- 정책 후보와 확정 규칙을 구분한다.
- 제약조건마다 규칙 ID와 검증 테스트를 연결한다.
- 동일 도서의 동시 미반납 샘플을 만들지 않는다.
- 명시적 ID 입력 뒤 IDENTITY 시작값을 조정한다.
- 자동 `DROP TABLE`을 생성·샘플·검증 파일에 넣지 않는다.
- 초기화는 보호 구문이 있는 별도 파일에서 수행한다.
- 오류 SQL은 기본 주석 상태로 제공하고 한 테스트씩 실행한다.
- JOIN 문법은 관계 검증용 최소 예제만 유지한다.
- 자기 확인 문제에 권장 해설을 제공한다.
- SVG에는 전체 SQL·샘플·검증 체크리스트를 과도하게 넣지 않는다.
