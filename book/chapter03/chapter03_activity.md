# Chapter 03 독자 워크북

## PostgreSQL과 DBeaver로 실습 환경 만들기

> 이 워크북은 Chapter 03을 읽은 뒤 자신의 PostgreSQL 환경을 점검하고 실행 결과를 기록하기 위한 선택형 보조 자료입니다. 테이블 생성이나 데이터 입력보다 연결 대상, 데이터베이스, 스키마와 SQL 실행 상태를 정확히 확인하는 데 집중합니다.

이 책의 필수 실습 경로는 다음과 같습니다.

```text
로컬 PostgreSQL
→ DBeaver 연결
→ ai_database_book 생성
→ public 스키마 확인
→ setup_check.sql 실행
```

Supabase는 관리형 PostgreSQL을 이해하기 위한 선택 활동입니다. Supabase 선택 활동은 로컬 필수 경로의 완료 기준을 대체하지 않습니다.

비밀번호, 전체 접속 URL, 실제 `.env` 값, API Key와 Access Token은 이 워크북이나 공개 저장소에 기록하지 않습니다.

## 1. 워크북 활용 방법

Chapter 03의 로컬 필수 흐름은 다음과 같습니다.

```text
PostgreSQL 서버 준비
→ DBeaver 연결
→ ai_database_book 생성
→ 새 데이터베이스로 다시 연결
→ current_database() 확인
→ current_schema()와 search_path 확인
→ 환경 검증 SQL 7개 실행
→ setup_check.sql 저장
```

다음 질문에 자신의 환경을 기준으로 답해 봅니다.

```text
PostgreSQL 서버는 실제로 실행 중인가?
DBeaver는 어느 데이터베이스에 연결되어 있는가?
현재 스키마와 검색 경로는 무엇인가?
SQL 한 문장과 전체 스크립트 실행을 구분할 수 있는가?
자동 커밋 상태를 확인했는가?
같은 환경 확인 파일을 여러 번 안전하게 실행할 수 있는가?
비밀번호와 접속 정보가 공개 파일에서 분리되어 있는가?
```

## 19. 권장 해설

### PostgreSQL과 DBeaver

```text
PostgreSQL은 데이터를 저장하고 SQL을 실행하는 DBMS이다.
DBeaver는 PostgreSQL에 SQL을 보내고 결과를 표시하는 클라이언트이다.
DBeaver를 종료해도 PostgreSQL의 데이터 저장소는 유지된다.
```

### `CREATE DATABASE`

```text
CREATE DATABASE는 권한이 있는 사용자가
트랜잭션 블록 밖에서 실행해야 한다.
생성 후 기존 편집기의 연결 대상은 자동으로 바뀌지 않는다.
```

### 스키마와 검색 경로

```text
current_database()는 현재 데이터베이스를 확인한다.
current_schema()는 현재 스키마를 확인한다.
SHOW search_path는 스키마 이름을 생략했을 때 객체를 찾는 순서를 보여 준다.
```

### 전체 스크립트 실행

```text
전체 스크립트가 항상 하나의 트랜잭션으로 실행되는 것은 아니다.
자동 커밋 상태에서는 앞의 변경이 이미 저장된 뒤 뒤 문장에서 오류가 날 수 있다.
```

### Supabase

```text
Supabase는 실제 PostgreSQL을 중심으로 구성된다.
프로젝트의 기본 데이터베이스는 postgres이다.
DBeaver에는 Direct 또는 Session pooler 연결을 사용할 수 있다.
실제 Storage 파일은 객체 저장소에 있고 PostgreSQL에는 메타데이터와 정책이 연결된다.
secret key와 service_role 키는 공개 클라이언트에 넣지 않는다.
```
