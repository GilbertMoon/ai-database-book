# Chapter 15 최종 프로젝트/평가 자료

## 최종 프로젝트 또는 최종 평가

> 용도: 수업 평가 안내문 / 프로젝트 과제지 / 시험형 평가 문제지 / 제출 안내 자료

## 1. 평가 개요

Chapter 15 평가는 이 책 전체에서 학습한 내용을 종합하는 최종 평가입니다.

평가 방식은 수업 상황에 따라 다음 중 하나를 선택할 수 있습니다.

| 평가 방식 | 설명 | 권장 상황 |
| --- | --- | --- |
| 프로젝트형 평가 | DB 기반 미니 서비스를 설계하고 일부 구현 또는 시연 | 실습 중심 수업, 팀 프로젝트 가능 수업 |
| 시험형 평가 | 요구사항을 읽고 ERD, DDL, SQL, 검토 답안을 작성 | 개인 평가, 시간 제한 평가 |
| 혼합형 평가 | 프로젝트 제출 후 짧은 구술 또는 필기 점검 추가 | AI 활용 여부와 본인 이해도 확인 필요 |

## 2. 프로젝트형 평가 안내

### 2.1 프로젝트 목표

프로젝트형 평가는 단순히 화면을 만드는 것이 아니라, 요구사항을 데이터베이스 설계와 SQL로 연결하는 능력을 확인합니다.

```text
요구사항 분석
→ ERD 작성
→ PostgreSQL DDL 작성
→ 샘플 데이터 입력
→ 핵심 SQL 작성
→ AI 생성 결과 검토
→ 선택 기능 구현 또는 시연
→ 최종 보고서 작성
```

### 2.2 프로젝트 주제 후보

아래 주제 중 하나를 선택하거나, 교수자와 협의해 다른 주제를 선택할 수 있습니다.

| 번호 | 주제 | 필수 테이블 예시 | 선택 확장 |
| ---: | --- | --- | --- |
| 1 | AI 튜터링 서비스 | students, tutors, questions, answers, learning_materials | RAG 자료 검색 |
| 2 | 온라인 강의 플랫폼 | students, instructors, courses, enrollments, payments | 강의 리뷰, 환불 규정 |
| 3 | RAG 기반 문서 검색 시스템 | documents, chunks, embeddings, questions, search_logs | 답변 근거성 검토 |
| 4 | 쇼핑몰 주문/결제/재고 시스템 | users, products, orders, order_items, payments, inventory | 재고 차감, 매출 집계 |
| 5 | 병원 예약 시스템 | patients, doctors, departments, appointments, medical_notes | 중복 예약 방지 |
| 6 | 도서 대여 시스템 | members, books, loans, returns, penalties | 연체료 계산 |
| 7 | 출석 관리 시스템 | members, meetings, attendances, roles, notifications | 결석자 조회, 월별 통계 |

### 2.3 필수 산출물

프로젝트 제출 시 다음 파일을 포함해야 합니다.

```text
final_project/
├── README.md
├── requirements.md
├── erd.png 또는 erd.md
├── schema.sql
├── seed.sql
├── queries.sql
├── ai_review_report.md
├── final_report.md
└── screenshots/
```

| 파일 | 필수 여부 | 내용 |
| --- | --- | --- |
| `README.md` | 필수 | 프로젝트 개요, 실행/확인 방법 |
| `requirements.md` | 필수 | 요구사항 정의서 |
| `erd.png` 또는 `erd.md` | 필수 | ERD 또는 테이블 관계도 |
| `schema.sql` | 필수 | 테이블 생성 DDL |
| `seed.sql` | 필수 | 샘플 데이터 INSERT |
| `queries.sql` | 필수 | 핵심 SELECT/JOIN/집계/검증 SQL |
| `ai_review_report.md` | 필수 | AI 활용 및 검토 보고서 |
| `final_report.md` | 필수 | 최종 보고서 |
| `screenshots/` | 선택 | 실행 결과 캡처 또는 웹 화면 캡처 |

## 3. 프로젝트형 평가 루브릭

총점 100점 기준입니다.

| 평가 항목 | 배점 | 평가 기준 |
| --- | ---: | --- |
| 요구사항 분석 | 15 | 문제 정의, 사용자, 기능, 핵심 데이터가 명확한가 |
| ERD 및 테이블 설계 | 20 | 엔터티, 관계, PK/FK, 정규화가 적절한가 |
| DDL 및 제약조건 | 15 | 데이터 타입, NOT NULL, UNIQUE, CHECK, FK가 적절한가 |
| 샘플 데이터와 핵심 SQL | 15 | INSERT, SELECT, JOIN, 집계, 검증 쿼리가 포함되었는가 |
| AI 활용 및 검토 보고서 | 15 | AI 결과의 오류와 수정 근거를 설명했는가 |
| 선택 확장 또는 구현 검증 | 10 | 웹 CRUD, NoSQL, RAG, API, 테스트 중 하나 이상을 검증했는가 |
| 발표/보고서 완성도 | 10 | 결과를 논리적으로 설명하고 제출 형식을 지켰는가 |

### 주요 감점 기준

```text
- 핵심 테이블에 PRIMARY KEY가 없음: 큰 감점
- 필요한 FOREIGN KEY가 누락됨: 큰 감점
- 모든 컬럼을 TEXT로 처리함: 감점
- 요구사항과 테이블 구조가 맞지 않음: 큰 감점
- 샘플 데이터 또는 핵심 SQL이 없음: 감점
- AI 생성 결과를 검토 없이 그대로 제출함: 큰 감점
- SQL 실행 결과 또는 검증 근거가 없음: 감점
- 제출 파일이 누락됨: 항목별 감점
```

## 4. 시험형 평가 안내

프로젝트 대신 시험형 평가로 운영할 경우 다음 문제를 사용할 수 있습니다.

### 4.1 시험 문제: AI 튜터링 질문 관리 시스템

다음 요구사항을 읽고 데이터베이스 설계와 검토 답안을 작성하세요.

```text
- 학생은 이름, 이메일, 가입일을 가진다.
- 튜터는 이름, 이메일, 전문 분야를 가진다.
- 학생은 질문을 등록할 수 있다.
- 질문은 제목, 본문, 상태, 등록일을 가진다.
- 튜터는 질문에 답변할 수 있다.
- 하나의 질문에는 여러 답변이 달릴 수 있다.
- 질문에는 관련 학습 자료를 연결할 수 있다.
- 하나의 질문은 여러 학습 자료와 연결될 수 있고, 하나의 학습 자료는 여러 질문에 연결될 수 있다.
- 질문 상태는 open, answered, closed 중 하나만 허용한다.
```

### 4.2 작성할 답안

```text
1. 핵심 엔터티 목록
2. 테이블 설계
3. PK/FK 설명
4. N:M 관계 처리 방법
5. PostgreSQL DDL 일부
6. 핵심 SELECT/JOIN 쿼리 1개
7. AI가 만든 설계라고 가정하고 검토할 항목 5개
8. 보안 또는 개인정보 관점 주의사항 2개
9. Vector DB/RAG 확장 가능성 1가지
```

### 4.3 시험형 평가 루브릭

| 평가 항목 | 배점 | 평가 기준 |
| --- | ---: | --- |
| 요구사항 이해 | 15 | 핵심 엔터티와 기능을 정확히 파악했는가 |
| 테이블 설계 | 25 | 테이블 분리, PK/FK, N:M 관계 처리가 적절한가 |
| DDL 작성 | 20 | PostgreSQL 문법, 데이터 타입, 제약조건이 적절한가 |
| SQL 작성 | 15 | JOIN 또는 조건 조회 쿼리가 요구사항에 맞는가 |
| AI 설계 검토 | 15 | AI 결과를 검토할 기준을 구체적으로 제시했는가 |
| 보안/확장 검토 | 10 | 개인정보, RAG/NoSQL 확장 가능성을 적절히 설명했는가 |

## 5. AI 활용 허용 범위

AI 활용은 허용합니다. 다만 AI 사용 사실과 검토 과정을 반드시 기록해야 합니다.

| 활용 항목 | 허용 여부 | 조건 |
| --- | --- | --- |
| 주제 아이디어 도출 | 허용 | 최종 주제는 본인이 선택하고 수정 |
| 요구사항 정리 | 허용 | 본인이 요구사항을 검토하고 보완 |
| ERD 초안 생성 | 허용 | 관계와 누락 테이블을 직접 검토 |
| DDL 초안 생성 | 허용 | PostgreSQL 문법과 제약조건 직접 확인 |
| SQL 오류 수정 | 허용 | 오류 원인과 수정 내용을 기록 |
| 보고서 문장 다듬기 | 허용 | 본인 결과와 해석을 반영 |
| 전체 결과물 자동 생성 후 무검토 제출 | 불가 | 큰 감점 또는 재제출 대상 |

6. 최종 설계를 선택한 이유

## 7. 발표 안내

발표 시간은 5~7분을 권장합니다.

| 순서 | 발표 내용 | 권장 시간 |
| --- | --- | ---: |
| 1 | 프로젝트 주제와 목적 | 1분 |
| 2 | 요구사항과 핵심 데이터 | 1분 |
| 3 | ERD와 테이블 설계 | 1~2분 |
| 4 | 핵심 SQL 또는 화면 시연 | 1~2분 |
| 5 | AI 활용 및 검토 결과 | 1분 |
| 6 | 한계와 개선 방향 | 1분 |

발표에서는 구현 화면보다 **설계 판단과 검증 근거**를 중심으로 설명합니다.

## 9. 교수자 운영 메모

```text
- 팀 프로젝트일 경우 팀원별 역할과 기여도를 반드시 제출하게 한다.
- AI 활용을 금지하기보다 AI 결과 검토 능력을 평가한다.
- 구현 완성도보다 DB 설계, SQL, 검증 근거를 우선 평가한다.
- 발표 후 ERD, FK, 제약조건, AI 수정 내역에 대해 1~2개 구술 질문을 할 수 있다.
- 웹 CRUD는 선택 사항으로 두되, DB 연결 확인 캡처가 있으면 가산점 또는 선택 확장 점수로 반영할 수 있다.
```
