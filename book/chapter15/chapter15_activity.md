# Chapter 15 독자 프로젝트 워크북

## 실전 프로젝트 2: AI 기반 데이터베이스 서비스 완성하기

> 이 워크북은 Chapter 15의 프로젝트를 단계별로 진행하고, 설계 판단과 실행 결과를 기록하기 위한 선택형 보조 자료입니다. 모든 항목을 채우는 것보다 요구사항, ERD, SQL과 실행 결과가 서로 일치하는지 확인하는 것이 중요합니다.

## 1. 프로젝트 전체 흐름

```text
문제를 정의한다.
→ 사용자와 핵심 기능을 정한다.
→ 포함할 범위와 제외할 범위를 나눈다.
→ 엔터티, 속성, 관계를 찾는다.
→ ERD와 PostgreSQL 스키마를 만든다.
→ 샘플 데이터로 실제 상황을 구성한다.
→ JOIN, 집계와 검증 쿼리로 설계를 확인한다.
→ 정규화, 트랜잭션, 인덱스와 보안을 검토한다.
→ AI가 제안한 결과와 사람이 수정한 결과를 비교한다.
→ 필요한 경우 웹 CRUD, API, NoSQL 또는 RAG로 확장한다.
→ 다른 사람이 다시 실행할 수 있도록 문서화한다.
```

이 프로젝트의 결과는 정답 하나를 맞히는 문서가 아닙니다. **왜 이런 구조를 선택했는지 설명할 수 있고 실제로 실행되는 작은 데이터베이스 서비스**여야 합니다.

## 16. 재현 가능한 프로젝트 구조

다음 구조를 참고해 필요한 파일을 정리합니다.

```text
project/
├── README.md
├── requirements.md
├── erd.md 또는 erd.png
├── schema.sql
├── seed.sql
├── queries.sql
├── ai_review.md
├── project_notes.md
└── screenshots/
```

| 파일 | 확인할 내용 |
| --- | --- |
| `README.md` | 프로젝트 목적과 실행 순서 |
| `requirements.md` | 사용자, 기능, 데이터와 규칙 |
| `erd.md` | 테이블과 관계 설명 |
| `schema.sql` | 재실행 가능한 DDL |
| `seed.sql` | 관계를 검증할 샘플 데이터 |
| `queries.sql` | 핵심 조회와 검증 SQL |
| `ai_review.md` | AI 제안과 수정 근거 |
| `project_notes.md` | 한계와 다음 버전 계획 |

비밀번호, API 키, 실제 `.env` 파일, 개인정보가 포함된 데이터는 프로젝트 폴더나 공개 저장소에 넣지 않습니다.
