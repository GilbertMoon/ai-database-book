# Chapter 15 편집 구성안

## 제목

실전 프로젝트 2: AI 기반 데이터베이스 서비스 완성하기

## 권장 분량

35~45페이지

## 이 장의 역할

책에서 다룬 데이터베이스 개념과 AI 활용 방법을 하나의 작은 서비스에 연결하는 종합 프로젝트 장이다. 독자는 문제를 정의하고, 요구사항을 데이터 구조로 바꾸고, PostgreSQL에서 실행 가능한 SQL로 구현한 뒤, 샘플 데이터와 핵심 쿼리로 설계를 검증한다.

웹 CRUD, NoSQL, Vector DB와 RAG는 프로젝트의 목적에 따라 선택적으로 확장한다. 화면의 화려함보다 데이터 구조와 검증 근거를 우선한다.

## 핵심 질문

- 해결하려는 문제와 주요 사용자는 누구인가?
- 어떤 데이터를 저장해야 하며 서로 어떻게 연결되는가?
- 관계형 데이터베이스가 핵심 데이터를 관리하기에 적합한가?
- 기본키, 외래키와 제약조건이 데이터의 오류를 충분히 막는가?
- 샘플 데이터와 핵심 SQL이 실제 요구사항을 증명하는가?
- 트랜잭션, 인덱스, 권한과 백업을 어디까지 고려해야 하는가?
- NoSQL이나 Vector DB/RAG가 필요한 부분과 필요하지 않은 부분은 무엇인가?
- AI가 만든 설계와 코드를 어떤 기준으로 검토했는가?

## 프로젝트 완성도 점검 기준

- 요구사항과 테이블 구조가 일치하는가?
- 모든 핵심 테이블을 안정적으로 식별할 수 있는가?
- 관계와 제약조건이 데이터 정합성을 보호하는가?
- 정상·경계·오류 상황을 확인할 샘플 데이터가 있는가?
- JOIN과 집계가 사용자가 필요로 하는 결과를 만드는가?
- 위험한 수정과 삭제를 통제할 수 있는가?
- 인덱스가 실제 조회 패턴과 연결되는가?
- 비밀정보와 개인정보가 노출되지 않는가?
- 백업과 복구 가능성을 설명할 수 있는가?
- AI 결과에서 무엇을 수정했는지 근거가 남아 있는가?
- 다른 사람이 프로젝트를 다시 실행할 수 있는가?

## 편집 원칙

- `최종 평가`, `시험`, `배점`, `감점`, `제출`을 본문의 중심 표현으로 사용하지 않는다.
- 독자가 스스로 완성하는 실전 프로젝트로 설명한다.
- 산출물은 채점용 문서가 아니라 설계와 실행을 재현하는 기록으로 제시한다.
- 웹 화면은 데이터베이스 동작을 확인하는 선택 수단으로 다룬다.
- NoSQL과 RAG는 유행을 위한 추가가 아니라 요구사항에 따른 기술 선택으로 설명한다.
- AI가 생성한 결과보다 검토 기준과 수정 근거를 강조한다.
- 운영 환경에 바로 적용하도록 유도하지 않고 테스트 환경에서 검증하도록 안내한다.

## 마무리 연결

책 전체의 개념을 하나의 프로젝트 흐름으로 다시 연결하고, 백엔드 API, ORM, 클라우드 운영, 성능 튜닝, 데이터 파이프라인, RAG 시스템 등 이후 학습 방향을 제시한다.
