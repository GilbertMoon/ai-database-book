> 이 워크북은 Chapter 04를 읽은 뒤 PostgreSQL에서 첫 테이블을 만들고 기본 SQL을 실행하며, 예상 결과와 실제 결과를 비교하기 위한 선택형 보조 자료입니다.

## 1. 워크북 활용 방법

이 장의 핵심 흐름은 다음과 같습니다.

```text
현재 데이터베이스·스키마·search_path 확인
→ students 테이블 생성
→ 샘플 데이터 입력
→ 조회·조건·NULL·정렬
→ 수정과 삭제
→ 데이터 상태 체크포인트 확인
→ AI SQL 검토
```

모든 SQL을 한꺼번에 실행하지 않고 현재 학습 중인 구간만 선택해 실행합니다.

```text
SQL 읽기
→ 예상 결과 작성
→ 자동 커밋과 실행 범위 확인
→ 실행
→ 반환 행 또는 영향받은 행 수 확인
→ 예상과 실제 비교
```

## 11. `<>`와 NULL 비교하기

다음 SQL의 결과를 예상합니다.

```sql
SELECT id, name, major
FROM public.students
WHERE major <> '경영학'
ORDER BY id ASC;
```

| 질문 | 답변 |
| --- | --- |
| 윤서진이 포함되는가? |  |
| 포함되거나 제외되는 이유는? |  |
| 조건 결과가 `UNKNOWN`이면 `WHERE`에서 남는가? |  |

`NULL`도 포함하도록 수정합니다.

```sql
SELECT id, name, major
FROM public.students
WHERE major <> '경영학'
   OR major IS NULL
ORDER BY id ASC;
```

PostgreSQL의 다른 표현도 실행해 봅니다.

```sql
SELECT id, name, major
FROM public.students
WHERE major IS DISTINCT FROM '경영학'
ORDER BY id ASC;
```

## 26. 권장 해설

### 핵심 개념

```text
PostgreSQL은 ORDER BY가 없는 결과 순서를 보장하지 않는다.
DESC 정렬에서 NULL 위치를 명시하려면 NULLS LAST를 사용한다.
LIMIT을 안정적으로 사용하려면 동률을 구분하는 보조 정렬 기준이 필요하다.
CURRENT_TIMESTAMP는 현재 트랜잭션의 시작 시각을 반환한다.
IDENTITY 값은 행 식별용이며 빈틈없는 순번이나 행 수가 아니다.
```

### NULL 비교

```text
major = NULL과 major <> NULL의 결과는 TRUE나 FALSE가 아니라 UNKNOWN이다.
WHERE에서는 TRUE인 행만 남으므로 해당 행은 반환되지 않는다.
NULL 여부는 IS NULL 또는 IS NOT NULL로 확인한다.
```

### 체크포인트

```text
A: 학생 6명, 이준호 grade 3, 박서연 존재
B: 학생 6명, 이준호 grade 4, 박서연 존재
C: 학생 5명, 이준호 grade 4, 박서연 삭제
```

### AI 삭제 SQL 사전 확인

```sql
SELECT id, name, email, major
FROM public.students
WHERE major = '컴퓨터공학'
ORDER BY id ASC;
```

체크포인트 C 기준 예상 대상은 김민지와 최현우 두 명입니다. 실제 삭제가 허용된 업무인지 확인하기 전에는 `DELETE`를 실행하지 않습니다.
