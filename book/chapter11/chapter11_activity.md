# Chapter 11 독자 워크북

## 데이터베이스를 안전하게 지키고 복구하는 방법

> 이 워크북은 Chapter 11을 읽은 뒤 계정, 권한, 입력값 처리, 비밀정보, 백업과 복구 계획을 직접 점검하기 위한 선택형 보조 자료입니다. 운영 데이터베이스가 아닌 별도의 로컬 또는 테스트 환경에서만 명령을 확인하세요.

## 1. 워크북 활용 방법

데이터베이스 보안과 백업은 명령어를 많이 외우는 문제가 아닙니다. 다음 질문에 구체적으로 답할 수 있어야 합니다.

```text
누가 접속하는가?
그 계정에 꼭 필요한 권한은 무엇인가?
불필요한 권한은 무엇인가?
사용자 입력값을 SQL과 분리했는가?
접속 정보가 코드나 저장소에 노출되지 않는가?
백업 파일은 어디에 보관되는가?
별도 환경에서 복구를 확인했는가?
```

### 안전 주의

```text
- 운영 데이터베이스에서 권한 변경이나 복구 연습을 하지 않는다.
- 예시 비밀번호를 실제 계정에 사용하지 않는다.
- 비밀번호, 접속 URL, API 키를 문서나 공개 저장소에 기록하지 않는다.
- CREATE ROLE, GRANT, REVOKE는 관리자 권한이 필요한 작업임을 확인한다.
- pg_dump와 psql 명령은 DBeaver SQL Editor가 아니라 터미널에서 실행한다.
- 복구는 원본 DB가 아닌 별도의 복구 확인용 DB에서 시작한다.
```

관련 SQL 예제:

```text
code/chapter11/security_backup_check.sql
```


## 6. GRANT, REVOKE와 권한 확인

다음 명령의 실행 전후를 예상해 보세요.

```sql
GRANT SELECT ON courses TO readonly_user;
REVOKE SELECT ON courses FROM readonly_user;
```

| 단계 | 예상 상태 |
| --- | --- |
| GRANT 전 |  |
| GRANT 후 |  |
| REVOKE 후 |  |

역할을 실제로 만든 테스트 환경이라면 다음과 같은 방식으로 권한을 확인할 수 있습니다.

```sql
SELECT has_table_privilege(
    'readonly_user',
    'courses',
    'SELECT'
);
```

> 존재하지 않는 역할 이름으로 권한 확인 함수를 실행하면 오류가 발생할 수 있습니다. 역할 생성 여부를 먼저 확인하세요.

## 8. SQL Injection 위험 구분하기

### 위험한 개념 패턴

```text
SQL 문자열 + 사용자 입력값 + SQL 문자열
```

### 안전한 방향

```text
SQL 문장 구조와 사용자 입력값을 분리하고,
사용하는 드라이버나 프레임워크의 파라미터 바인딩을 사용한다.
```

| 확인 질문 | 답변 |
| --- | --- |
| 사용자 입력을 문자열로 이어 붙이는가? |  |
| placeholder를 사용하는가? |  |
| DB 드라이버가 제공하는 바인딩 기능을 사용하는가? |  |
| 입력값 검증만으로 충분하다고 오해하고 있지 않은가? |  |
| DB 계정 권한도 제한되어 있는가? |  |

다음 placeholder는 환경에 따라 표현이 다를 수 있습니다.

```text
?
$1
:name
```

핵심은 특정 기호를 외우는 것이 아니라 사용 중인 라이브러리의 안전한 바인딩 API를 사용하는 것입니다.

## 10. 백업 명령 읽기

다음 명령은 터미널에서 실행하는 논리 백업 예시입니다.

```bash
pg_dump -U postgres -d ai_database_book -f ai_database_book_backup.sql
```

| 구성 | 의미 |
| --- | --- |
| `pg_dump` |  |
| `-U postgres` |  |
| `-d ai_database_book` |  |
| `-f ai_database_book_backup.sql` |  |

SQL 텍스트 형식이 아니라 사용자 정의 형식을 사용할 때는 다음과 같은 형태도 가능합니다.

```bash
pg_dump -U postgres -d ai_database_book -Fc -f ai_database_book.backup
```

형식에 따라 복구 도구가 달라질 수 있으므로 백업 명령과 복구 명령을 한 쌍으로 문서화해야 합니다.

## 11. 복구 명령 읽기

SQL 텍스트 백업의 복구 예시:

```bash
psql -U postgres -d ai_database_book_restore -f ai_database_book_backup.sql
```

사용자 정의 형식 백업의 복구 예시:

```bash
pg_restore -U postgres -d ai_database_book_restore ai_database_book.backup
```

### 용어 메모

- **RPO**: 장애가 발생했을 때 어느 시점까지의 데이터 손실을 허용할 수 있는지를 나타내는 목표입니다.

## 14. AI가 만든 명령 검토하기

AI가 다음과 같이 제안했다고 가정합니다.

```text
서비스 계정에 SUPERUSER 권한을 준다.
비밀번호는 예시 문자열을 그대로 사용한다.
모든 테이블에 ALL PRIVILEGES를 부여한다.
운영 데이터베이스에 백업 파일을 바로 복구한다.
백업 파일은 프로젝트 공개 저장소에 올린다.
```

| 제안 | 위험 요소 | 수정 방향 |
| --- | --- | --- |
| SUPERUSER 부여 |  |  |
| 예시 비밀번호 사용 |  |  |
| ALL PRIVILEGES 부여 |  |  |
| 운영 DB에 직접 복구 |  |  |
| 공개 저장소에 백업 저장 |  |  |

AI 결과를 검토할 때는 다음 순서를 사용할 수 있습니다.

```text
대상 환경 확인
→ 명령의 변경 범위 확인
→ 계정과 권한 확인
→ 비밀정보 노출 여부 확인
→ 삭제·덮어쓰기 가능성 확인
→ 되돌리는 방법 확인
→ 테스트 환경에서 검증
→ 실행 결과 기록
```
