# Chapter 11. 데이터베이스 보안과 백업

> 상태: 초안

## 이 장에서 배울 내용

이 장에서는 데이터베이스를 안전하게 사용하는 기본 원칙을 학습합니다.

- SQL Injection
- 안전한 SQL 작성 방식
- 계정과 권한 관리
- 개인정보 보호
- 백업과 복구

## 왜 이 내용을 배우는가

데이터베이스에는 회원 정보, 주문 정보, 결제 내역처럼 중요한 데이터가 저장될 수 있습니다. 따라서 기능 구현만큼 보안과 백업도 중요합니다.

## 핵심 개념

### SQL Injection

SQL Injection은 사용자가 입력한 값이 SQL 명령처럼 실행되어 데이터가 유출되거나 변경될 수 있는 공격 방식입니다.

### 백업

백업은 데이터 손실에 대비해 데이터를 별도로 복사해 두는 작업입니다.

## 위험한 예시

> 주의: 아래 코드는 SQL Injection에 취약한 예시입니다. 실제 서비스에서는 사용하면 안 됩니다.

```sql
SELECT * FROM users WHERE email = '" + user_input + "';
```

## 검토 질문

- 사용자 입력값이 SQL 문자열에 직접 결합되어 있지 않은가?
- DB 계정에 과도한 권한이 부여되어 있지 않은가?
- 백업과 복구 계획이 있는가?

## 자주 하는 실수

- 개발용 관리자 계정을 그대로 서비스에서 사용한다.
- 백업은 하지만 복구 테스트를 하지 않는다.
- AI가 만든 SQL 문자열 결합 코드를 그대로 사용한다.

## 정리

데이터베이스 보안은 선택 사항이 아닙니다. AI가 코드를 만들어 주더라도 사용자는 위험한 SQL과 권한 문제를 반드시 검토해야 합니다.
