## 3. 강화한 내용

| 항목 | 반영 내용 |
| --- | --- |
| 트랜잭션 경계 | 업무 단위와 외부 작업의 경계 설명 |
| 조건부 UPDATE | 좌석 0행과 SQL 오류 구분 |
| CTE 연결 | 좌석 성공 결과가 있을 때만 신청·결제 INSERT |
| COMMIT 전 검증 | 신청·결제·좌석을 한 결과로 확인 |
| ROLLBACK | 임시 변경과 원상 복구 비교 |
| 오류 상태 | PostgreSQL aborted transaction 설명 |
| SAVEPOINT | 부분 복구 경계의 기본 개념 추가 |
| Lock | SELECT FOR UPDATE와 같은 행 대기 설명 |
| Deadlock | 단순 대기와 순환 대기 구분 |
| 장기 트랜잭션 | 외부 API 대기 위험 설명 |
| AI 검토 | 정상 경로뿐 아니라 실패·복구·재실행 검토 |

## 5. 스키마와 제약조건

```text
course_inventory.course_id → course_project.courses.id
lab enrollments.student_id → course_project.students.id
lab enrollments.course_id → course_project.courses.id
payments.enrollment_id → lab enrollments.id (UNIQUE)
capacity > 0
0 <= remaining_seats <= capacity
status IN ('수강중', '취소')
금액 >= 0
```

## 8. 도식 처리

기존 Mermaid·SVG 8종은 트랜잭션 필요성, 기본 흐름, ACID, COMMIT·ROLLBACK, Lock과 AI 검토의 일반 메시지가 새 본문과 호환되어 유지한다.

도식 문서에서는 `transaction_lab`과 `course_project`의 역할을 구분하고, 구체적 ID·행 수는 본문과 SQL에서 관리한다.
