## 이 장에서 배울 내용

이 장에서는 여러 데이터베이스 작업을 하나의 단위로 처리하는 **트랜잭션**을 학습합니다.

Chapter 07과 Chapter 08에서는 온라인 강의 수강신청 시스템을 설계하고, JOIN과 집계 쿼리로 데이터를 조회했습니다. 이제는 실제 서비스에서 매우 중요한 문제를 다룹니다.

```text
수강신청 정보는 저장되었는데 결제 기록은 저장되지 않으면 어떻게 될까?
결제 기록은 저장되었는데 수강신청 정보가 없으면 어떻게 될까?
잔여 좌석은 줄었는데 수강신청은 실패하면 어떻게 될까?
```

이런 문제를 막기 위해 트랜잭션을 사용합니다.

## 1. 왜 트랜잭션을 배워야 하는가

데이터베이스 작업은 하나의 SQL로 끝나지 않는 경우가 많습니다.

온라인 강의 수강신청을 예로 들어 보겠습니다.

한 학생이 강의를 신청하면 다음 작업이 함께 일어날 수 있습니다.

```text
1. 수강신청 정보를 enrollments 테이블에 저장한다.
2. 결제 정보를 payments 테이블에 저장한다.
3. 강의의 잔여 좌석 수를 줄인다.
4. 수강신청 상태를 수강중 또는 결제완료로 변경한다.
```

이 중 일부만 성공하면 데이터가 맞지 않습니다.

| 상황 | 문제 |
| --- | --- |
| 수강신청은 저장되었지만 결제 기록이 없음 | 실제 결제 여부를 알 수 없음 |
| 결제는 저장되었지만 수강신청이 없음 | 학생이 강의를 볼 수 없음 |
| 잔여 좌석은 줄었지만 수강신청이 실패함 | 실제보다 좌석이 적게 보임 |
| 두 학생이 동시에 마지막 좌석을 신청함 | 좌석 수가 음수가 될 수 있음 |

트랜잭션은 이런 여러 작업을 **모두 성공하거나 모두 취소되는 하나의 작업 단위**로 묶습니다.

---

## 2. 트랜잭션이란 무엇인가

트랜잭션은 데이터베이스에서 여러 SQL 실행을 하나의 논리적 작업 단위로 묶는 방법입니다.

가장 기본적인 구조는 다음과 같습니다.

```sql
BEGIN;

-- 여러 SQL 실행

COMMIT;
```

문제가 발생하면 다음처럼 되돌릴 수 있습니다.

```sql
BEGIN;

-- 여러 SQL 실행

ROLLBACK;
```

트랜잭션을 쉽게 표현하면 다음과 같습니다.

```text
BEGIN: 이제부터 하나의 작업 단위로 처리하겠다.
COMMIT: 지금까지의 변경을 확정하겠다.
ROLLBACK: 지금까지의 변경을 취소하겠다.
```

---

## 3. 데이터 정합성이란 무엇인가

데이터 정합성은 데이터가 서로 모순 없이 맞는 상태를 의미합니다.

예를 들어 다음 상태는 정합성이 맞지 않습니다.

```text
payments에는 결제 기록이 있는데 enrollments에는 수강신청 기록이 없다.
강의 잔여 좌석이 -1이다.
수강신청 상태는 결제완료인데 결제 금액은 0원이다.
```

데이터 정합성은 단순히 SQL 문법이 맞는 것과 다릅니다.

SQL이 실행되더라도 업무 규칙에 맞지 않는 데이터가 저장되면 정합성이 깨질 수 있습니다.

---

## 4. COMMIT 이해하기

`COMMIT`은 트랜잭션 안에서 실행한 변경 내용을 확정합니다.

다음 예시는 수강신청과 결제 기록을 함께 저장합니다.

```sql
BEGIN;

INSERT INTO enrollments (student_id, course_id, enrolled_at, status, paid_amount)
VALUES (1, 1, CURRENT_DATE, '결제완료', 100000);

INSERT INTO payments (student_id, course_id, amount, paid_at)
VALUES (1, 1, 100000, CURRENT_DATE);

COMMIT;
```

`COMMIT`이 실행되면 두 INSERT 결과가 데이터베이스에 확정됩니다.

---

## 5. ROLLBACK 이해하기

`ROLLBACK`은 트랜잭션 안에서 실행한 변경 내용을 취소합니다.

예를 들어 결제 기록 저장 중 문제가 있다고 판단되면 다음처럼 전체 작업을 되돌립니다.

```sql
BEGIN;

INSERT INTO enrollments (student_id, course_id, enrolled_at, status, paid_amount)
VALUES (1, 1, CURRENT_DATE, '결제대기', 100000);

-- 결제 검증 실패 상황이라고 가정

ROLLBACK;
```

이 경우 `enrollments`에 INSERT한 내용도 취소됩니다.

트랜잭션의 핵심은 다음입니다.

```text
중간에 실패하면 처음부터 없었던 일처럼 되돌릴 수 있어야 한다.
```

## 6. ACID 특성

트랜잭션은 보통 ACID라는 네 가지 특성으로 설명합니다.

| 항목 | 의미 | 쉬운 설명 |
| --- | --- | --- |
| Atomicity | 원자성 | 모두 성공하거나 모두 실패해야 함 |
| Consistency | 일관성 | 작업 후 데이터 규칙이 깨지면 안 됨 |
| Isolation | 격리성 | 동시에 실행되는 작업이 서로 이상하게 섞이면 안 됨 |
| Durability | 영속성 | 확정된 결과는 사라지면 안 됨 |

초급 단계에서는 먼저 원자성과 일관성을 확실히 이해하는 것이 중요합니다.

## 7. 수강신청과 결제 테이블 만들기

트랜잭션 실습을 위해 결제 테이블을 추가합니다.

```sql
CREATE TABLE payments (
    id SERIAL PRIMARY KEY,
    student_id INT NOT NULL REFERENCES students(id),
    course_id INT NOT NULL REFERENCES courses(id),
    amount INT NOT NULL,
    paid_at DATE NOT NULL
);
```

또한 강의의 잔여 좌석을 관리하기 위해 `courses` 테이블에 `capacity`와 `remaining_seats`를 둘 수 있습니다.

```sql
CREATE TABLE courses (
    id SERIAL PRIMARY KEY,
    instructor_id INT NOT NULL REFERENCES instructors(id),
    title VARCHAR(200) NOT NULL,
    price INT NOT NULL,
    capacity INT NOT NULL,
    remaining_seats INT NOT NULL
);
```

이 구조에서는 수강신청이 성공하면 `remaining_seats`가 1 줄어야 합니다.

---

## 8. 성공하는 트랜잭션 예제

다음 예제는 수강신청, 결제 기록, 잔여 좌석 차감을 하나의 트랜잭션으로 처리합니다.

```sql
BEGIN;

INSERT INTO enrollments (student_id, course_id, enrolled_at, status, paid_amount)
VALUES (1, 1, CURRENT_DATE, '결제완료', 100000);

INSERT INTO payments (student_id, course_id, amount, paid_at)
VALUES (1, 1, 100000, CURRENT_DATE);

UPDATE courses
SET remaining_seats = remaining_seats - 1
WHERE id = 1
  AND remaining_seats > 0;

COMMIT;
```

이 트랜잭션은 다음 세 작업이 함께 확정됩니다.

```text
- 수강신청 저장
- 결제 기록 저장
- 잔여 좌석 감소
```

## 9. 실패 상황과 ROLLBACK

실제 서비스에서는 중간에 문제가 발생할 수 있습니다.

예를 들어 결제 검증이 실패했다면 수강신청도 저장되면 안 됩니다.

```sql
BEGIN;

INSERT INTO enrollments (student_id, course_id, enrolled_at, status, paid_amount)
VALUES (2, 1, CURRENT_DATE, '결제대기', 100000);

-- 결제 검증 실패라고 가정

ROLLBACK;
```

이 경우 수강신청 기록은 확정되지 않습니다.

실습에서는 ROLLBACK 전후로 SELECT를 실행해 변경이 취소되는지 확인해야 합니다.

---

## 10. 잔여 좌석 검증하기

수강신청 시스템에서는 좌석 수가 음수가 되면 안 됩니다.

따라서 좌석 차감 SQL에는 조건을 포함하는 것이 좋습니다.

```sql
UPDATE courses
SET remaining_seats = remaining_seats - 1
WHERE id = 1
  AND remaining_seats > 0;
```

이 SQL은 잔여 좌석이 0보다 큰 경우에만 차감합니다.

실행 후 실제로 좌석이 줄었는지 확인해야 합니다.

```sql
SELECT id, title, remaining_seats
FROM courses
WHERE id = 1;
```

## 11. 트랜잭션 안에서 확인해야 할 것

트랜잭션을 작성할 때는 다음 질문을 확인해야 합니다.

| 확인 항목 | 확인 질문 |
| --- | --- |
| 작업 단위 | 어떤 SQL들이 반드시 함께 성공해야 하는가? |
| 실패 처리 | 중간에 실패하면 어디까지 되돌려야 하는가? |
| 정합성 | 작업 후 데이터가 업무 규칙과 맞는가? |
| 검증 쿼리 | COMMIT 전후로 확인할 SELECT가 있는가? |
| 조건 처리 | 좌석 수, 금액, 상태 같은 조건이 SQL에 반영되었는가? |

트랜잭션은 SQL을 묶는 것만이 아니라 업무 규칙을 지키는 장치입니다.

## 12. Isolation 맛보기

격리성은 동시에 실행되는 트랜잭션이 서로에게 이상한 영향을 주지 않도록 하는 특성입니다.

예를 들어 한 강의에 잔여 좌석이 1개만 남아 있다고 가정합니다.

```text
학생 A가 마지막 좌석을 신청한다.
동시에 학생 B도 같은 좌석을 신청한다.
둘 다 성공하면 잔여 좌석은 -1이 될 수 있다.
```

이런 상황을 막기 위해 데이터베이스는 잠금과 격리 수준을 제공합니다.

초급 단계에서는 다음 정도만 이해해도 충분합니다.

```text
동시에 같은 데이터를 바꾸는 상황에서는 트랜잭션 충돌을 고려해야 한다.
```

## 13. Lock과 Deadlock 맛보기

Lock은 한 트랜잭션이 데이터를 수정하는 동안 다른 트랜잭션이 같은 데이터를 동시에 수정하지 못하게 하는 장치입니다.

하지만 여러 트랜잭션이 서로 상대방의 작업이 끝나기를 기다리면 교착 상태가 생길 수 있습니다. 이를 Deadlock이라고 합니다.

예를 들어 다음과 같은 상황입니다.

```text
트랜잭션 A는 강의 1을 수정한 뒤 강의 2를 기다린다.
트랜잭션 B는 강의 2를 수정한 뒤 강의 1을 기다린다.
서로 기다리기 때문에 진행되지 않는다.
```

초급 단계에서는 Deadlock을 깊게 다루기보다, 트랜잭션을 짧고 단순하게 유지해야 한다는 원칙을 기억하면 됩니다.

## 14. AI가 만든 트랜잭션 SQL 검토하기

AI에게 다음처럼 요청할 수 있습니다.

```text
PostgreSQL에서 수강신청, 결제 기록, 잔여 좌석 차감을 하나의 트랜잭션으로 처리하는 SQL 예제를 작성해 주세요.
실패 시 ROLLBACK이 필요한 이유도 설명해 주세요.
```

AI가 만든 SQL은 다음 기준으로 검토해야 합니다.

| 검토 항목 | 확인 질문 |
| --- | --- |
| 작업 범위 | 함께 성공해야 하는 SQL이 모두 트랜잭션 안에 있는가? |
| BEGIN/COMMIT | 트랜잭션 시작과 확정이 명확한가? |
| 실패 처리 | 실패 시 ROLLBACK을 고려했는가? |
| 좌석 조건 | remaining_seats > 0 조건이 있는가? |
| 금액 검증 | 결제 금액과 강의 가격이 맞는가? |
| 상태 값 | 수강신청 상태가 업무 흐름과 맞는가? |
| 실행 검증 | SELECT로 결과를 확인했는가? |

AI가 만든 SQL은 구조가 그럴듯해 보여도 실제 업무 규칙을 빠뜨릴 수 있습니다. 반드시 사람이 정합성 기준으로 검토해야 합니다.

## 15. 자주 하는 실수

### 실수 1. 여러 작업을 트랜잭션으로 묶지 않는다

수강신청 저장과 결제 저장이 따로 실행되면 한쪽만 성공할 수 있습니다.

### 실수 2. COMMIT을 너무 빨리 실행한다

검증하기 전에 COMMIT하면 잘못된 데이터가 확정될 수 있습니다.

### 실수 3. ROLLBACK을 테스트하지 않는다

성공 상황만 확인하면 실패 상황에서 데이터가 어떻게 되는지 알 수 없습니다.

### 실수 4. 좌석 조건을 확인하지 않는다

잔여 좌석이 0인데도 차감하면 음수가 될 수 있습니다.

### 실수 5. AI가 만든 트랜잭션 SQL을 그대로 사용한다

AI는 업무 규칙을 정확히 모를 수 있으므로 반드시 사람이 검토해야 합니다.

## 17. 정리

이번 장에서는 트랜잭션과 데이터 정합성을 학습했습니다.

핵심 내용을 정리하면 다음과 같습니다.

```text
1. 트랜잭션은 여러 SQL을 하나의 작업 단위로 묶는 방법이다.
2. COMMIT은 변경을 확정하고 ROLLBACK은 변경을 취소한다.
3. 트랜잭션은 모두 성공하거나 모두 실패해야 한다.
4. 데이터 정합성은 데이터가 업무 규칙과 모순되지 않는 상태이다.
5. ACID는 트랜잭션의 중요한 특성을 설명한다.
6. 동시에 같은 데이터를 수정하면 충돌이 생길 수 있다.
7. 트랜잭션은 가능한 짧고 명확하게 유지하는 것이 좋다.
8. AI가 만든 트랜잭션 SQL도 반드시 사람이 업무 규칙 기준으로 검토해야 한다.
```

이 장에서 가장 중요한 문장은 다음입니다.

```text
트랜잭션은 여러 SQL을 함께 실행하는 문법이 아니라, 데이터 정합성을 지키기 위한 안전 장치이다.
```
