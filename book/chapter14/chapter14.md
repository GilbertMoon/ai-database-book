# Chapter 14. Vector DB와 RAG 기초

> 상태: 초안

## 이 장에서 배울 내용

이 장에서는 AI 서비스에서 자주 사용되는 Vector DB와 RAG의 기본 개념을 학습합니다.

- Embedding
- Vector DB
- pgvector
- 의미 기반 검색
- RAG 기본 흐름

## 왜 이 내용을 배우는가

일반 SQL 검색은 정확히 일치하는 값을 찾는 데 강합니다. 반면 AI 서비스에서는 질문의 의미와 비슷한 문서를 찾아야 하는 경우가 많습니다.

## 핵심 개념

### Embedding

Embedding은 문장이나 문서를 숫자 벡터로 바꾸는 과정입니다. 의미가 비슷한 문장은 벡터 공간에서도 가깝게 표현됩니다.

### RAG

RAG는 사용자의 질문과 관련된 문서를 먼저 검색한 뒤, 그 문서를 바탕으로 답변을 생성하는 방식입니다.

## 기본 흐름

```text
문서 저장
→ 문서를 embedding으로 변환
→ Vector DB에 저장
→ 질문을 embedding으로 변환
→ 유사 문서 검색
→ 검색 결과를 바탕으로 답변 생성
```

## 검토 질문

- 일반 DB 검색과 Vector DB 검색의 차이를 설명할 수 있는가?
- RAG가 단순 LLM 답변과 다른 점을 이해했는가?
- 검색된 문서가 답변 근거로 적절한지 확인했는가?

## 자주 하는 실수

- Vector DB를 일반 DB의 대체재로 오해한다.
- Embedding 품질과 검색 품질의 관계를 고려하지 않는다.
- 검색 결과 검토 없이 LLM 답변을 신뢰한다.

## 정리

Vector DB와 RAG는 AI 서비스에서 데이터베이스의 역할이 확장되는 대표적인 사례입니다. PostgreSQL에 pgvector를 추가하면 기존 DB 학습 흐름과 자연스럽게 연결할 수 있습니다.
