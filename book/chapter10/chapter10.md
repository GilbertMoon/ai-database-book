# Chapter 10. 인덱스와 성능 기초

> 상태: 초안

## 이 장에서 배울 내용

이 장에서는 데이터 검색 속도를 높이는 인덱스의 기본 개념을 학습합니다.

- 인덱스가 필요한 이유
- WHERE 조건과 인덱스
- EXPLAIN 실행 계획
- 인덱스의 장단점
- AI 추천 인덱스 검토

## 왜 이 내용을 배우는가

데이터가 적을 때는 대부분의 쿼리가 빠르게 실행됩니다. 하지만 데이터가 많아지면 같은 SQL도 느려질 수 있습니다.

## 핵심 개념

### 인덱스

인덱스는 데이터베이스에서 원하는 데이터를 더 빠르게 찾기 위한 구조입니다.

### 실행 계획

실행 계획은 DBMS가 SQL을 어떤 방식으로 실행할지 보여 주는 정보입니다.

## 기본 예제

```sql
CREATE INDEX idx_students_email
ON students(email);
```

## AI 활용 실습

```text
students 테이블에서 email 컬럼으로 자주 검색할 때 필요한 인덱스를 PostgreSQL 기준으로 제안해 주세요.
인덱스의 장단점도 함께 설명해 주세요.
```

## 검토 질문

- 자주 검색하는 컬럼에 인덱스가 생성되었는가?
- 데이터 변경이 많은 테이블에 인덱스를 너무 많이 만들지 않았는가?
- EXPLAIN 결과를 확인했는가?

## 자주 하는 실수

- 모든 컬럼에 인덱스를 만들려고 한다.
- 인덱스 생성 후 실행 계획을 확인하지 않는다.
- 데이터가 적은 상황에서 성능 차이를 과장한다.

## 정리

인덱스는 검색 성능을 높일 수 있지만 저장 공간과 쓰기 비용이 증가합니다. AI가 추천한 인덱스도 실제 쿼리와 실행 계획을 기준으로 검토해야 합니다.
