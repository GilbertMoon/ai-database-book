## 목적

Chapter 05를 단순한 엔터티·관계 소개에서 **업무 요구사항을 근거로 데이터 모델과 ERD를 만드는 장**으로 재구성한다.

명사 찾기에만 의존하지 않고 업무 사실, 업무 규칙, 확정·미확정 정책, 관계 문장, 카디널리티, 선택성과 요구사항 추적을 포함한다. SQL 실행 구조도 Chapter 04와 동일한 안전 원칙으로 정리한다.

## 4. SQL 구조 변경

### 기존

```text
library_schema.sql
- 자동 DROP
- CREATE TABLE
- 샘플 INSERT
- JOIN 검증
- FK 오류 예시
```

### 변경

```text
library_schema.sql
- 현재 DB·스키마 확인
- IDENTITY 기반 테이블 생성

library_seed.sql
- 명시적 실습 ID 샘플 입력

library_validation.sql
- 행 수, NULL, 1:N 관계와 최소 JOIN 확인

reset_library.sql
- 필요할 때만 자식→부모 순서로 테이블 삭제
```

### 안전성 개선

```text
- 생성 파일에서 자동 DROP 제거
- SERIAL을 IDENTITY로 변경
- 자동 증가 값 1, 2, 3을 가정하지 않음
- 부모 ID 101~103, 도서 ID 201~203, 대여 ID 1001~1004 사용
- 외래키 오류 예시는 Chapter 06으로 이동
```

## 7. 정합성 기준

| 항목 | 기준 |
| --- | --- |
| 테이블 | `members`, `books`, `loans` |
| PK 방식 | `GENERATED BY DEFAULT AS IDENTITY` |
| 외래키 | `loans.member_id → members.id`, `loans.book_id → books.id` |
| 관계 | 부모 `1`, 자식 `0..N` |
| 선택 속성 | `returned_at` NULL 허용 |
| 샘플 데이터 | 회원 3명, 도서 3건, 대여 4건 |
| 명시적 ID | 101~103, 201~203, 1001~1004 |
| JOIN | 구조 연결 확인용 최소 범위 |
| FK 오류 | Chapter 06으로 이동 |
