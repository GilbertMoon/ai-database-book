# Chapter 05 전체 점검·반영 기록

## Chapter

```text
Chapter 05. 요구사항에서 데이터 모델과 ERD 만들기
```

## 점검 기준

Chapter 05를 단순 ERD 기호 학습이 아니라 다음 흐름으로 검토했다.

```text
요구사항 읽기
→ 사실·규칙·미확정 질문 구분
→ 엔터티·속성·사건 도출
→ 테이블별 한 행 의미
→ 양방향 관계 문장
→ 카디널리티·선택성
→ N:M 해소
→ ERD
→ PostgreSQL 최소 구조
→ 작은 정상 시나리오 검증
→ AI 초안 재검토
```

본문뿐 아니라 워크북, SQL, 호환 파일, 초기화, 이미지, 이론·실습 강의안, 실제 발표 HTML, 발표자 스크립트, 의미 단위 내비게이션, TTS와 자동 검증까지 서로 대조했다.

## 1. 본문 구조와 핵심 모델

본문은 17개 절 구조를 유지한다.

```text
1. 요구사항에서 데이터 구조를 만드는 이유
2. 이 장에서 완성할 설계 산출물
3. 요구사항과 모델의 범위 정하기
4. 업무 사실·규칙·미확정 질문 구분하기
5. 엔터티·속성·사건 찾기
6. 테이블별 한 행의 의미 정하기
7. 식별자와 기본키 후보 정하기
8. 관계를 양방향 문장으로 표현하기
9. 카디널리티와 선택성 판단하기
10. N:M 관계를 사건 테이블로 풀기
11. ERD 표기와 텍스트 초안
12. 도서 대여 시스템 ERD
13. 요구사항 추적표로 누락 확인하기
14. ERD를 PostgreSQL 구조로 변환하기
15. 작은 샘플 시나리오로 구조 검증하기
16. AI가 만든 모델 검토하기
17. 자주 하는 실수·스스로 확인하기·핵심 정리
```

핵심 한 행 의미는 다음으로 통일한다.

```text
members 한 행 = 회원 한 명
books 한 행 = 이 장에서 대여 대상으로 관리하는 도서 한 건
loans 한 행 = 특정 회원이 특정 도서를 대여한 사건 한 건
```

`books`를 제목·판본·실제 복본까지 완전히 분리한 운영 모델처럼 설명하지 않는다. 동일 ISBN 복본 구분과 여러 저자는 후속 확장 과제로 남긴다.

## 2. 확정·미확정 정책 구분

본문·워크북·강의자료에서 다음 원칙을 유지한다.

```text
확정
→ 요구사항 근거가 있으므로 구조에 반영

미확정
→ 추가 질문으로 관리

가정
→ 현재 모델 범위를 설명하기 위해 명시

범위 제외
→ 이번 장에서 구현하지 않음
```

특히 다음 정책은 Chapter 05에서 임의 확정하지 않는다.

```text
members.email UNIQUE
books.isbn UNIQUE
최대 대여 권수
삭제 정책
날짜 선후 CHECK
동시 활성 대여 차단
```

이 제약은 Chapter 06에서 정규화·무결성·제약조건 관점으로 이어진다.

## 3. 현재 PostgreSQL 구조 기준

세 자료에서 사용하는 DDL을 다음으로 통일했다.

```sql
CREATE TABLE public.members (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    joined_at DATE NOT NULL
);

CREATE TABLE public.books (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    author VARCHAR(100) NOT NULL,
    published_year INTEGER,
    isbn VARCHAR(20) NOT NULL
);

CREATE TABLE public.loans (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    member_id INTEGER NOT NULL REFERENCES public.members(id),
    book_id INTEGER NOT NULL REFERENCES public.books(id),
    borrowed_at DATE NOT NULL,
    due_at DATE NOT NULL,
    returned_at DATE
);
```

이메일·ISBN은 필수 저장값이지만 고유성은 미확정이므로 `UNIQUE`를 적용하지 않는다.

## 4. 샘플 기준 상태 통일

본문과 실제 SQL의 샘플 상태는 다음이다.

```text
members = 3
books = 3
loans = 4
미반납 = 3
회원 101 대여 이력 = 2
도서 201 대여 이력 = 2
회원 참조 고아 행 = 0
도서 참조 고아 행 = 0
도서 201 시간 순서 오류 = 0
```

기존 실습 강의안의 다음 오래된 기준을 제거했다.

```text
members 2
books 2
loans 3
```

실습 강의안은 이제 SQL과 같은 `3 / 3 / 4 / 미반납 3`을 완료 기준으로 사용한다.

## 6. 01 생성 파일의 부분 생성 방지

`01_library_schema.sql`과 `library_schema.sql`을 보강했다.

```text
현재 DB 확인
→ 읽기 전용 여부 확인
→ public 스키마 존재 확인
→ 세 테이블 미존재 확인
→ BEGIN
→ members → books → loans 생성
→ 세 테이블 존재·0행 확인
→ COMMIT
```

세 테이블 생성 도중 오류가 발생했을 때 일부 테이블만 남은 상태로 완료되지 않도록 하나의 트랜잭션으로 묶었다.

---

## 7. 02 입력 파일의 부분 입력 방지

`02_library_seed.sql`과 `library_seed.sql`도 하나의 트랜잭션으로 묶었다.

```text
현재 DB·쓰기 상태 확인
→ 세 테이블 존재·0행 확인
→ BEGIN
→ members 3행
→ books 3행
→ loans 4행
→ IDENTITY 다음 값 104·204·1005
→ 3/3/4 검증
→ 미반납 3 검증
→ 회원 101 대여 2 검증
→ 도서 201 대여 2 검증
→ COMMIT
```

중간 INSERT 또는 IDENTITY 조정에서 오류가 발생했을 때 일부 샘플만 남지 않도록 했다.

## 8. 03 검증 파일 강화

`03_library_validation.sql`과 호환 검증 파일은 다음을 자동 판정한다.

```text
members = 3
books = 3
loans = 4
미반납 = 3
회원 101 대여 = 2
도서 201 대여 = 2
고아 회원 참조 = 0
고아 도서 참조 = 0
도서 201 시간 순서 오류 = 0
```

통과 메시지:

```text
Chapter 05 library model validation passed
```

JOIN은 관계 연결을 검증하는 최소 용도로만 사용하며 상세 JOIN 학습은 Chapter 08로 남긴다.

## 남은 실제 확인

다음 항목은 실제 실행·렌더링 전에는 통과로 표시하지 않는다.

```text
1. PostgreSQL에서 reset → 01 → 02 → 03 순차 실행
2. 01 중간 실패 시 부분 테이블 미생성 확인
3. 02 중간 실패 시 부분 샘플 미입력 확인
4. 3/3/4·미반납 3·회원101 2·도서201 2 실제 확인
5. 고아 참조 0·시간 순서 오류 0 실제 확인
6. 잘못된 DB·읽기 전용 연결 보호 확인
7. 이론·실습 발표 HTML 직접 렌더링
8. 의미 단위 이전/다음 및 화면 포커스 확인
9. 발표자 스크립트와 장표 창 동기화 확인
10. TTS 발음과 script_content_enhancer 결과 확인
11. SVG 8개와 Mermaid 원본 대응 확인
12. Word·PDF·eBook 최종 렌더링
```

실행하지 않은 항목은 검토 기록에서 실제 통과로 과장하지 않는다.
