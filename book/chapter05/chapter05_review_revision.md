## 개편 목적

Chapter 05를 ERD 기호와 PostgreSQL 구현 세부를 많이 소개하는 장이 아니라, 요구사항에서 데이터 구조의 근거를 도출하고 검증하는 첫 설계 장으로 정리했다.

```text
요구사항 읽기
→ 사실·규칙·미확정 질문 구분
→ 엔터티·속성·사건 도출
→ 한 행 의미 작성
→ 양방향 관계 문장
→ 카디널리티·선택성
→ ERD
→ 추적표와 시나리오 검증
```

기존 17개의 세부 학습 결과는 독자가 직접 판단할 수 있는 완료 기준으로 압축했다.

## 2. 본문 구조 25절에서 17절로 정리

최종 본문은 다음 17개 절로 구성한다.

```text
1. 요구사항에서 데이터 구조를 만드는 이유
2. 이 장에서 완성할 설계 산출물
3. 요구사항과 모델의 범위 정하기
4. 업무 사실·규칙·미확정 질문 구분하기
5. 엔터티·속성·사건 찾기
6. 테이블별 한 행의 의미 정하기
7. 식별자와 기본키 후보 정하기
8. 관계를 양방향 문장으로 표현하기
9. 카디널리티와 선택성 판단하기
10. N:M 관계를 사건 테이블로 풀기
11. ERD 표기와 텍스트 초안
12. 도서 대여 시스템 ERD
13. 요구사항 추적표로 누락 확인하기
14. ERD를 PostgreSQL 구조로 변환하기
15. 작은 샘플 시나리오로 구조 검증하기
16. AI가 만든 모델 검토하기
17. 자주 하는 실수·스스로 확인하기·핵심 정리
```

권장 분량은 24~28페이지에서 21~24페이지로 조정했다.

## 3. 설계 산출물 명확화

ERD 그림만 만들고 설계를 완료했다고 오해하지 않도록 다음 산출물을 장 초반에 제시했다.

```text
요구사항 목록
미확정 질문 목록
테이블별 한 행 의미
엔터티·속성·사건 후보표
양방향 관계 문장
ERD 초안
요구사항 추적표
작은 검증 시나리오
PostgreSQL DDL 초안
```

각 결과물이 앞 단계의 판단 근거를 보존하도록 구성했다.

---

## 4. 테이블별 한 행 의미 강화

다음 내용을 별도 절과 표로 강화했다.

```text
members 한 행 = 회원 한 명
books 한 행 = 이 장에서 대여 대상으로 관리하는 도서 한 건
loans 한 행 = 특정 회원이 특정 도서를 대여한 사건 한 건
```

열 위치와 관계 설계가 한 행 의미에서 도출되도록 설명했다.

---

## 5. 모델 범위와 가정 명시

`books`의 의미가 도서 제목·판본·실제 복본 중 무엇인지 혼동되지 않도록 단순화 범위를 명시했다.

```text
books 한 행을 대여 대상 한 건으로 취급
동일 ISBN 실제 복본 미구분
여러 저자 미지원
샘플에서 동시 미반납 대여 미생성
이메일·ISBN 고유성 미확정
```

확정·미확정·가정·범위 제외를 서로 다른 상태로 관리한다.

---

## 6. 관계와 시간 기반 업무 규칙 구분

다음 두 개념을 분리했다.

```text
books 1 : N loans
→ 시간 전체에 걸친 반복 대여 이력

동시 미반납 대여 금지
→ 특정 시점의 활성 대여 수를 제한하는 별도 업무 제약
```

ERD의 카디널리티만으로 동시성 정책이 자동 보장되지 않음을 명시하고, 실제 구현은 Chapter 06으로 연결했다.

## 7. 요구사항 추적표 단순화

추적표 형식을 다음으로 통일했다.

```text
ID | 요구사항 또는 질문 | 상태 | 반영 위치 | 검증 시나리오
```

상태:

```text
확정
미확정
가정
범위 제외
```

단순 열·테이블 매핑뿐 아니라 정상 시나리오로 확인할 수 있도록 변경했다.

---

## 8. 정상 시나리오 기반 검증

행 수 확인 외에 다음 시나리오를 모델 검증 기준으로 추가했다.

```text
대여 이력 없는 신규 회원
대여 이력 없는 신규 도서
회원 한 명의 반복 대여
도서 한 건의 시간별 이력
returned_at NULL인 미반납 상태
모든 대여의 회원·도서 참조
```

샘플 검증 요약은 다음으로 통일했다.

```text
members = 3
books = 3
loans = 4
미반납 = 3
고아 회원 참조 = 0
고아 도서 참조 = 0
도서 201 대여 이력 = 2
시간 순서 오류 = 0
```

## 9. 선택·심화 학습 분리

### 선택 학습

```text
개념·논리·물리 모델
1:1 관계와 구현 조건
텍스트 ERD
PostgreSQL DDL 변환
최소 JOIN
AI ERD 초안
```

### 심화 학습

```text
복합키·대체키
복본과 판본 분리
여러 저자 모델
동시 활성 대여 제약
IDENTITY 다음 값 조정
ALTER TABLE과 데이터 마이그레이션
```

1:1의 `UNIQUE` 외래키와 공유 PK, IDENTITY 재시작 상세를 핵심 흐름에서 분리했다.

## 11. 워크북 개편

```text
핵심 활동
```

## 14. 초기화 파일 수정

기존 `current_schema() = public` 강제 조건을 제거했다.

현재 기준:

```text
현재 DB가 ai_database_book인지 확인
public 스키마 존재 확인
읽기 전용 연결이 아닌지 확인
current_schema와 관계없이 public.loans → books → members 삭제
```

모든 삭제 대상을 스키마 한정 이름으로 명확히 지정했다.
