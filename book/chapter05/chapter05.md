# Chapter 05. 데이터 모델링과 ERD

> 상태: 초안

## 이 장에서 배울 내용

이 장에서는 서비스 요구사항을 데이터베이스 구조로 바꾸는 방법을 배웁니다.

- 엔티티와 속성
- 테이블 후보 찾기
- 1:N, N:M 관계
- ERD 작성
- AI 생성 ERD 검토

## 왜 이 내용을 배우는가

좋은 SQL은 좋은 테이블 설계에서 시작됩니다. 테이블 구조가 잘못되면 이후 쿼리, 성능, 정합성, 웹 구현이 모두 어려워집니다.

## 핵심 개념

### 엔티티

엔티티는 관리해야 할 데이터의 대상입니다. 예를 들어 학생, 강의, 강사, 수강신청은 엔티티가 될 수 있습니다.

### 관계

관계는 엔티티 사이의 연결입니다. 한 학생은 여러 강의를 신청할 수 있고, 한 강의도 여러 학생이 신청할 수 있습니다.

## AI 활용 실습

```text
온라인 강의 수강신청 시스템의 요구사항을 바탕으로 ERD 초안을 작성해 주세요.
학생, 강의, 강사, 수강신청 정보를 포함해 주세요.
```

## 검토 질문

- N:M 관계가 연결 테이블로 분리되었는가?
- 각 테이블에 기본키가 있는가?
- 관계를 표현하는 외래키가 적절한가?

## 자주 하는 실수

- 하나의 테이블에 모든 정보를 넣는다.
- N:M 관계를 직접 컬럼으로 처리한다.
- 관계는 있는데 외래키를 만들지 않는다.

## 정리

데이터 모델링은 요구사항을 테이블과 관계로 바꾸는 과정입니다. ERD는 이 구조를 시각적으로 표현하는 도구입니다.

## 연습 문제

3. [응용] 도서 대여 시스템의 엔티티를 4개 이상 찾아 보세요.
4. [심화] AI가 만든 ERD에서 N:M 관계 처리 오류를 찾아 보세요.
