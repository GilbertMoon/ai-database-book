# Chapter 05 독자 워크북

## 요구사항에서 데이터 모델과 ERD 만들기

> 이 워크북은 Chapter 05를 읽은 뒤 요구사항을 데이터 구조로 바꾸는 사고 과정을 직접 기록하기 위한 선택형 보조 자료입니다. ERD를 예쁘게 그리는 것보다 각 테이블과 관계의 근거를 설명하는 데 집중합니다.

## 1. 워크북 활용 방법

이 장의 핵심 흐름은 다음과 같습니다.

```text
요구사항 읽기
→ 업무 사실·규칙 구분
→ 확정·미확정 규칙 분리
→ 엔터티와 속성 찾기
→ 관계 문장 작성
→ 카디널리티와 선택성 결정
→ PK·FK 후보 정리
→ ERD 초안
→ 요구사항 추적표
→ 작은 데이터로 구조 확인
```

다음 파일을 참고할 수 있습니다.

```text

```

외래키 오류와 참조 무결성 실습은 Chapter 06에서 진행하고, JOIN 문법의 상세 학습은 Chapter 08에서 진행합니다.

## 2. 요구사항 읽기

다음 요구사항을 읽습니다.

```text
1. 도서관은 회원을 관리한다.
2. 회원은 이름, 이메일, 가입일을 가진다.
3. 도서는 제목, 저자, 출판연도, ISBN을 가진다.
4. 회원은 여러 권의 책을 대여할 수 있다.
5. 책은 시간에 따라 여러 번 대여될 수 있다.
6. 대여 기록에는 대여일, 반납예정일, 실제반납일을 저장한다.
7. 아직 반납되지 않은 대여 기록은 실제반납일이 비어 있을 수 있다.
```

요구사항을 자신의 말로 한 문장으로 요약합니다.

```text
이 시스템은 ________________________________________________을 관리한다.
```

## 10. N:M 관계를 사건 테이블로 풀기

회원과 도서의 관계를 직접 표현하면 N:M입니다.

```text
members N : M books
```

이를 `loans`로 풀어 씁니다.

```text
members 1 : N loans
books   1 : N loans
```

다음을 설명합니다.

```text
loans가 단순 연결 테이블이 아니라 업무·사건 테이블인 이유:

loans에 member_id와 book_id 외에 날짜 열이 필요한 이유:
```

- book_id FK -> books.id
- borrowed_at
- due_at
- returned_at
