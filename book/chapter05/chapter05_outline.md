## 이 장의 역할

Chapter 05는 ERD 도구의 사용법이나 기호를 많이 암기하는 장이 아니다. 요구사항에서 관리 대상·사건·속성·관계를 도출하고, 각 테이블의 한 행 의미와 요구사항 근거를 설명할 수 있는 모델을 만드는 장이다.

```text
요구사항 읽기
→ 업무 사실·규칙·미확정 질문 구분
→ 엔터티·속성·사건 도출
→ 한 행 의미 결정
→ 양방향 관계 문장 작성
→ 카디널리티·선택성 판단
→ ERD 작성
→ 추적표와 샘플 시나리오로 검증
```

## 핵심 메시지

```text
각 테이블의 한 행은 무엇을 의미하며,
그 테이블·열·관계가 어느 요구사항에서 나왔는지 설명할 수 있어야 한다.
```

## 이 장을 마치면

독자는 다음 작업을 수행할 수 있다.

- 요구사항에서 관리 대상, 속성과 업무 규칙을 구분한다.
- 확정 규칙과 미확정 정책을 분리한다.
- 각 테이블의 한 행 의미를 작성한다.
- 기본키와 업무상 고유값 후보를 구분한다.
- 관계를 양방향 문장으로 작성한다.
- 카디널리티와 선택성을 판단한다.
- N:M 관계를 연결 테이블로 풀고, 사건 속성이 있는 연결 엔터티를 설명한다.
- ERD와 작은 샘플 시나리오로 요구사항 반영 여부를 확인한다.

## 범위 가정

```text
books 한 행을 대여 대상으로 취급하는 간소화된 도서 항목 한 건으로 정의한다.
실제 복본(copy)은 별도 엔터티로 모델링하지 않아 같은 ISBN의 여러 실물 책을 구분하지 않는다.
한 도서의 여러 저자 구조는 다루지 않는다.
샘플에서는 같은 도서의 동시 미반납 상태를 만들지 않는다.
동시 대여 차단의 DB 구현은 Chapter 06으로 이동한다.
이메일과 ISBN의 고유성은 미확정이므로 Chapter 05에서는 UNIQUE를 적용하지 않는다. ISBN 존재 여부도 미확정이므로 isbn은 NULL을 허용한다.
최대 대여 권수, 연체와 삭제 정책은 다루지 않는다.
```

## 테이블별 한 행 의미

| 테이블 | 한 행의 의미 |
| --- | --- |
| `members` | 회원 한 명 |
| `books` | 대여 대상으로 취급하는 간소화된 도서 항목 한 건 |
| `loans` | 특정 회원이 특정 도서를 대여한 사건 한 건 |

## 요구사항

```text
R-01. 도서관은 회원을 관리한다.
R-02. 회원은 이름, 이메일, 가입일을 가진다.
R-03. 도서는 제목과 저자를 관리하며, 출판연도와 ISBN 정보도 저장할 수 있다.
R-04. 회원은 여러 권의 책을 대여할 수 있다.
R-05. 책은 시간에 따라 여러 번 대여될 수 있다.
R-06. 대여 기록에는 대여일, 반납예정일, 실제반납일을 저장한다.
R-07. 아직 반납되지 않은 대여 기록은 실제반납일이 비어 있을 수 있다.
```

## 관계 문장

```text
한 회원은 0개 이상의 대여 기록을 가질 수 있다.
하나의 대여 기록은 정확히 한 회원을 참조한다.
한 도서는 0개 이상의 대여 기록을 가질 수 있다.
하나의 대여 기록은 정확히 한 도서를 참조한다.
```

## 정상 검증 시나리오

| 시나리오 | 구조가 표현해야 할 상태 |
| --- | --- |
| 신규 회원 | 대여 기록 없이 회원만 저장 가능 |
| 신규 도서 | 대여 이력 없이 도서만 저장 가능 |
| 반복 대여 | 같은 회원이 여러 대여 기록 보유 |
| 도서 이력 | 같은 도서가 시간에 따라 여러 번 대여됨 |
| 미반납 상태 | `returned_at`이 `NULL` |
| 관계 연결 | 모든 대여가 특정 회원과 도서를 참조 |

## 편집 원칙

- ERD 도구 사용법보다 설계 근거를 중심으로 설명한다.
- 명사뿐 아니라 동사와 수량 표현을 분석한다.
- 모든 테이블의 한 행 의미를 명시한다.
- 관계를 양방향 자연어 문장으로 먼저 작성한다.
- 카디널리티와 시간 기반 업무 제약을 구분한다.
- 미확정 정책은 질문으로 남기고 임의 제약조건을 만들지 않는다.
- PostgreSQL 예제는 `public.table_name`처럼 스키마를 명시한다.
- `current_schema() = public`을 실행 전제 조건으로 강제하지 않는다.
- 정규화와 제약조건 실패 실습은 Chapter 06으로 이동한다.
- JOIN은 구조 연결 확인용 최소 예제만 유지한다.
- 본문, 워크북, SQL, 코드 README와 검수 문서를 동기화한다.
