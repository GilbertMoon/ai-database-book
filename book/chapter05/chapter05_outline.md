# Chapter 05 구성안

## 제목

요구사항에서 데이터 모델과 ERD 만들기

## 권장 분량

24~28페이지

## 이 장의 역할

업무 요구사항을 읽고 관리 대상, 사건, 속성, 관계와 업무 규칙을 도출하여 검토 가능한 데이터 모델과 ERD 초안을 만든다.

이 장은 명사만 찾아 테이블을 만드는 방식에 머물지 않는다. 요구사항의 동사와 수량 표현에서 관계를 찾고, 확정된 규칙과 미확정 규칙을 구분하며, 관계를 양방향 문장으로 작성한 뒤 ERD와 PostgreSQL 구조로 변환한다.

개념 엔터티와 PostgreSQL 테이블을 같은 수준의 개념으로 취급하지 않고, 개념 모델 → 논리 모델 → 물리 모델의 흐름을 짧게 설명한다. 상세 정규화, `UNIQUE`, `CHECK`, 외래키 오류와 동시 대여 차단은 Chapter 06, JOIN 문법과 다양한 결합 방식은 Chapter 08로 연결한다.

## 독자가 얻게 될 것

- 개념 모델, 논리 모델과 PostgreSQL 물리 모델을 구분할 수 있다.
- 업무 사실, 속성과 업무 규칙을 구분할 수 있다.
- 확정된 규칙과 미확정 규칙을 분리할 수 있다.
- 엔터티 후보를 판단 근거와 함께 도출할 수 있다.
- 엔터티와 속성을 구분할 수 있다.
- 기본키와 업무상 고유값 후보를 구분할 수 있다.
- 고유값 후보와 실제 `UNIQUE` 제약조건을 구분할 수 있다.
- 관계를 양방향 문장으로 작성할 수 있다.
- 1:1, 1:N, N:M 관계를 구분할 수 있다.
- 1:1 구현에 `UNIQUE` 또는 공유 PK가 필요함을 설명할 수 있다.
- `0..1`, `1`, `0..N`, `1..N` 선택성을 설명할 수 있다.
- N:M 관계를 중간 테이블 또는 사건·업무 테이블로 풀 수 있다.
- PK·FK 위치를 업무 관계에서 도출할 수 있다.
- 요구사항 ID와 상태가 포함된 추적표로 설계 누락을 확인할 수 있다.
- ERD를 스키마가 명시된 PostgreSQL DDL 초안으로 바꿀 수 있다.
- 명시적 ID 입력 뒤 IDENTITY 다음 값을 조정할 수 있다.
- AI가 만든 ERD의 임의 가정, 누락과 샘플 모순을 검토할 수 있다.

## 샘플 데이터 기준

```text
members: 101, 102, 103
books: 201, 202, 203
loans: 1001, 1002, 1003, 1004
```

| 대여 ID | 도서 ID | 대여일 | 실제반납일 | 상태 |
| ---: | ---: | --- | --- | --- |
| 1001 | 201 | 2026-04-01 | 2026-04-02 | 반납 완료 |
| 1002 | 202 | 2026-04-02 | NULL | 미반납 |
| 1003 | 201 | 2026-04-03 | NULL | 미반납 |
| 1004 | 203 | 2026-04-05 | NULL | 미반납 |

도서 201은 첫 대여가 반납된 다음 날 다시 대여되어 시간에 따른 이력은 표현하되 동시 활성 대여는 만들지 않는다.

## IDENTITY 기준

명시적 ID 입력 뒤 다음 자동 값을 조정한다.

```text
members: RESTART WITH 104
books: RESTART WITH 204
loans: RESTART WITH 1005
```

## 요구사항 추적표 기준

```text
ID | 요구사항·가정 | 상태 | 반영 구조 | 확인 방법
```

상태는 `확정`, `미확정`, `가정`, `범위 제외`로 구분한다. 이메일·ISBN의 고유성은 미확정 상태로 기록한다.

## AI 활용 원칙

- 개념 엔터티와 PostgreSQL 테이블 후보를 구분하도록 요청한다.
- 요구사항에 없는 정책을 임의로 확정하지 않도록 요청한다.
- 가정, 미확정 질문과 범위 제외를 별도로 출력하도록 요청한다.
- 각 테이블과 열의 요구사항 ID를 표시하도록 요청한다.
- 관계를 양방향 문장으로 설명하도록 요청한다.
- 필수·선택 관계와 1:1 구현 조건을 구분하도록 요청한다.
- AI 결과는 요구사항 추적표와 작은 샘플 데이터로 검증한다.
- 샘플 데이터가 범위 가정과 충돌하지 않는지 확인한다.

## 편집 원칙

- Chapter 02의 PK·FK 개념은 관계 설계에 필요한 수준으로만 연결한다.
- Chapter 04의 스키마 명시, `SHOW search_path`, 자동 커밋과 보호 초기화 원칙을 유지한다.
- 이메일과 ISBN 고유성을 요구사항 없이 `UNIQUE`로 확정하지 않는다.
- 정규화, 날짜 `CHECK`, 동시 대여와 FK 오류 실습은 Chapter 06으로 이동한다.
- JOIN은 구조 확인용 최소 예제만 유지하고 상세 문법은 Chapter 08로 이동한다.
- 생성·샘플 파일에 자동 `DROP TABLE`을 포함하지 않는다.
- 명시적인 실습 ID를 사용한 뒤 IDENTITY 다음 값을 조정한다.
- 샘플 데이터는 동일 도서의 동시 미반납 상태를 만들지 않는다.
- 본문, 워크북, SQL, 코드 README와 리뷰 문서의 규칙을 동기화한다.
