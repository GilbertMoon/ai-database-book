## 1. 워크북 활용 방법

Chapter 01에서는 파일, 엑셀, 관계형 데이터베이스가 각각 어떤 상황에 적합한지 살펴보았습니다. 이 워크북에서는 실제 서비스 사례를 기준으로 저장 방식을 선택하고, ChatGPT의 추천을 검토합니다.

핵심은 하나의 정답을 맞히는 것이 아닙니다. 다음 기준을 근거로 자신의 선택을 설명하는 것이 중요합니다.

```text
데이터 양과 증가 속도
변경 빈도
여러 사용자의 동시 접근
데이터 사이의 관계
검색과 집계
정확성과 일관성
권한, 보안, 백업과 복구
향후 기능 확장 가능성
```

## 3. 사례별 저장 방식 판단하기

### 사례 1. 개인 독서 기록

한 사람이 책 제목, 저자, 읽은 날짜, 짧은 메모를 기록합니다. 한 달에 3~5개의 기록이 추가되고 다른 사람과 공유하지 않습니다.

| 항목 | 나의 판단 |
| --- | --- |
| 추천 저장 방식 |  |
| 선택 이유 |  |
| 데이터베이스가 꼭 필요한가? |  |
| 기능이 늘어나면 판단이 달라지는가? |  |

### 사례 2. 카페 메뉴 소개 웹사이트

메뉴 이름, 가격, 설명을 보여 주는 웹사이트입니다. 메뉴는 10개 정도이고 가격은 1년에 한두 번 변경됩니다.

| 항목 | 나의 판단 |
| --- | --- |
| 추천 저장 방식 |  |
| 선택 이유 |  |
| 데이터베이스가 꼭 필요한가? |  |
| 온라인 주문 기능이 추가되면 무엇이 달라지는가? |  |

### 사례 3. 온라인 강의 신청 서비스

회원은 여러 강의를 신청할 수 있고, 하나의 강의에도 여러 회원이 등록할 수 있습니다. 신청 상태, 결제 상태, 강사 정보, 강의평을 관리해야 합니다.

| 항목 | 나의 판단 |
| --- | --- |
| 추천 저장 방식 |  |
| 데이터베이스가 필요한 핵심 이유 |  |
| 중요한 데이터 관계 |  |
| 반드시 정확해야 하는 상태 |  |

### 사례 4. 쇼핑몰 주문·결제·재고

회원이 상품을 주문하고 결제합니다. 결제가 완료되면 재고가 차감되어야 하며, 여러 사용자가 동시에 같은 상품을 주문할 수 있습니다.

| 항목 | 나의 판단 |
| --- | --- |
| 추천 저장 방식 |  |
| 정합성이 중요한 부분 |  |
| 동시에 주문할 때 발생할 수 있는 문제 |  |
| 보존해야 할 이력 |  |

### 사례 5. 문서 의미 검색 서비스

사용자가 여러 문서를 업로드하고 질문하면, 같은 단어가 없어도 의미가 비슷한 문서를 찾아 답변에 활용합니다.

| 항목 | 나의 판단 |
| --- | --- |
| 추천 저장 방식 |  |
| 일반 키워드 검색만으로 부족한 이유 |  |
| 관계형 DB가 함께 필요한 데이터 |  |
| Vector DB가 맡을 역할 |  |
