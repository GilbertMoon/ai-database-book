# Chapter 01 구성안

## 제목

AI 시대에 데이터베이스를 왜 배워야 하는가

## 권장 분량

15~20페이지

## 이 장의 역할

데이터베이스를 처음 배우는 독자가 “AI가 SQL을 작성해 주는데도 왜 DB를 배워야 하는가?”라는 질문에 답할 수 있도록 안내한다. 데이터베이스 정의를 길게 설명하기보다 AI 결과 검증, 데이터 오류의 파급, 업무 관계 표현, 원본과 파생 데이터 구분을 통해 책 전체의 문제의식을 제시한다.

Chapter 01은 데이터베이스 개념을 모두 설명하는 장이 아니다. 데이터·DBMS·테이블·행·열·스키마 등의 상세 정의는 Chapter 02로 넘기고, 이 장에서는 학습 동기와 판단 기준에 집중한다.

## 핵심 메시지

```text
AI는 데이터베이스의 초안을 빠르게 만들 수 있지만,
무엇을 저장하고 어떻게 연결하며 결과를 믿어도 되는지는 사람이 판단해야 한다.
```

## 독자가 얻게 될 것

- AI가 SQL을 작성해도 DB를 이해해야 하는 이유를 설명할 수 있다.
- 실행되는 SQL과 올바른 SQL의 차이를 구분할 수 있다.
- 잘못된 데이터가 AI 분석과 의사결정에 미치는 영향을 설명할 수 있다.
- 현실의 업무를 데이터와 관계로 표현해야 하는 이유를 이해할 수 있다.
- 파일, 스프레드시트와 데이터베이스를 선택하는 기준을 제시할 수 있다.
- 원본 데이터와 파생 데이터를 구분할 수 있다.
- 비전공자와 개발자에게 필요한 DB 역량을 자신의 역할과 연결할 수 있다.
- 이 책의 AI 활용·검증 중심 학습 흐름을 이해할 수 있다.

## 주요 개념

- AI 생성 결과 검증
- 실행 성공과 결과 정확성의 차이
- 데이터 중복·누락·관계 오류
- 업무 규칙과 데이터 관계
- 파일·스프레드시트·데이터베이스 선택 기준
- 원본 데이터와 파생 데이터
- 데이터 품질과 분석 결과
- AI와 사람의 역할 분담

## 본문 구성

3. AI가 만든 테이블도 구조적으로 틀릴 수 있다
4. 잘못된 데이터는 AI의 오류로 이어진다
5. 현실의 업무는 데이터와 관계로 표현된다
6. AI 기능도 결국 데이터를 저장해야 한다
7. 비전공자도 데이터베이스를 알아야 하는 이유
8. 파일, 스프레드시트와 데이터베이스 중 무엇을 선택할까
9. 데이터베이스를 배워야 하는 다섯 가지 근본 이유
10. 원본 데이터와 파생 데이터를 구분한다
11. AI가 잘하는 일과 사람이 확인할 일

- 온라인 강의 서비스의 잘못된 단일 테이블 사례
- 파일·스프레드시트·데이터베이스 비교
- AI 결과를 직접 실행하고 검증해야 한다는 메시지

- 데이터 오류가 AI 분석과 의사결정으로 전파되는 흐름
- 기획자·운영자·분석가·개발자 등 역할별 DB 필요성
- AI 서비스의 사용자·권한·상태·실행 이력·검토 기록
- 원본 데이터와 파생 데이터의 구분
- SQL 데이터 분석과 Python 확장으로 이어지는 학습 경로

## 독자 참여 요소

- DB를 배워야 하는 다섯 가지 이유를 자신의 언어로 정리한다.
- 파일·스프레드시트·관계형 DB 중 적절한 저장 방식을 판단한다.
- 잘못된 데이터가 SQL·AI 분석·의사결정에 미치는 영향을 추적한다.
- AI가 작성한 JOIN과 집계 SQL의 누락·중복 가능성을 검토한다.
- 원본 데이터와 파생 데이터를 구분한다.
- 자신의 역할에서 DB를 알아야 하는 이유를 정리한다.

## AI 활용 포인트

- ChatGPT로 서비스 요구사항과 데이터 후보를 정리한다.
- AI가 추천한 저장 방식이 현재 요구사항과 맞는지 검토한다.
- AI가 생성한 SQL을 정답이 아닌 초안으로 다룬다.
- JOIN, 필터, NULL, 집계 기준과 예상 결과를 사람이 확인한다.
- AI 답변에서 타당한 부분과 수정한 부분을 기록한다.

## 독자가 직접 정리할 내용

- 데이터베이스 필요 여부와 선택 근거
- 데이터 오류가 결과에 미치는 영향
- 원본 데이터와 파생 데이터 구분
- AI 답변에서 타당한 부분과 수정한 부분
- 자신의 역할과 관심 분야에서 필요한 DB 역량
