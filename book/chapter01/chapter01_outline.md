# Chapter 01 구성안

## 제목

AI 시대에 데이터베이스를 왜 배워야 하는가

## 권장 분량

15~20페이지

## 이 장의 역할

데이터베이스를 처음 배우는 독자가 “AI가 SQL을 작성해 주는데도 왜 DB를 배워야 하는가?”라는 질문에 답할 수 있도록 안내한다.

Chapter 01은 데이터·DBMS·테이블·행·열·스키마를 상세하게 정의하는 장이 아니다. 다음 두 가지에 집중한다.

```text
왜 데이터베이스를 배워야 하는가?
AI가 만든 구조·SQL·숫자에서 무엇을 검증해야 하는가?
```

정확한 데이터베이스 용어와 PostgreSQL 계층 구조는 Chapter 02에서 다룬다.

## 핵심 메시지

```text
AI는 데이터베이스의 초안을 빠르게 만들 수 있지만,
무엇을 저장하고 어떻게 연결하며 결과를 믿어도 되는지는 사람이 판단해야 한다.
```

## 독자가 얻게 될 것

- AI가 SQL을 작성해도 DB를 이해해야 하는 이유를 설명할 수 있다.
- 실행되는 SQL과 요구사항에 맞는 SQL을 구분할 수 있다.
- 잘못된 데이터·JOIN·필터·집계가 AI 분석에 미치는 영향을 설명할 수 있다.
- 현실의 업무를 데이터와 관계로 표현해야 하는 이유를 이해할 수 있다.
- 파일·스프레드시트·DBMS 중심 관리 방식을 선택하는 기준을 제시할 수 있다.
- 기준 데이터, 결정적 파생 데이터와 AI 생성 결과를 구분할 수 있다.
- 신청 당시 기록 금액과 실제 결제 완료·환불·매출 지표를 구분해야 하는 이유를 설명할 수 있다.
- AI 결과를 실행·비교·수정·기록하는 책의 학습 흐름을 이해할 수 있다.

## 핵심 SQL 사례

### 잘못된 접근

```sql
SELECT COUNT(*) AS student_count
FROM students AS s
INNER JOIN questions AS q
    ON q.student_id = s.id;
```

검토 기준:

```text
기준 테이블
한 행의 의미
질문 없는 학생 누락
질문 여러 건에 따른 학생 중복
업무 상태 필터
예상 결과와 기준 행 비교
```

### 전체 학생 수의 축약 예제

```sql
SELECT COUNT(*) AS student_count
FROM students;
```

가정:

```text
students 한 행 = 학생 한 명
중복·병합 행 없음
비활성·탈퇴 제외 조건 없음
```

본문 SQL은 개념 설명용이며 실제 실행 환경은 Chapter 03~04에서 만든다.

## 기준 데이터·파생 데이터·AI 결과

```text
기준 데이터
→ 업무 판단의 근거

결정적 파생 데이터
→ 동일한 기준 데이터·계산식·기준 시점이면 재생성 가능

AI 생성 결과
→ 모델·입력·지시문·실행 조건에 따라 달라질 수 있음
→ 실행 맥락과 승인 결과 보존 필요
```

AI 실행 맥락 예:

```text
모델 식별자
입력 데이터 기준 시점
프롬프트 템플릿 버전
실행 ID·시각
결과 상태
검토·승인 상태
보존 기간과 민감정보 여부
```

## 독자 참여 요소

본문에서는 온라인 강의 사례 한 개만 짧게 판단한다. 반복·확장 활동은 워크북으로 이동한다.

워크북 활동:

- DB를 배워야 하는 다섯 가지 이유 정리
- 파일·스프레드시트·DBMS 중심 관리 비교
- 독서 기록·행사 명단·온라인 강의·쇼핑몰 사례 판단
- 잘못된 `INNER JOIN`과 우연히 같은 숫자 검토
- 중복·누락·`NULL` 오류의 파급 추적
- 기준 데이터·결정적 파생·AI 생성 결과 구분
- AI 실행 맥락 설계
- 자신의 서비스 검토 메모
- 통합 권장 해설

## AI 활용 포인트

- ChatGPT로 서비스 요구사항과 데이터 후보를 정리한다.
- AI가 추천한 저장 방식이 현재 요구사항과 맞는지 검토한다.
- AI가 생성한 SQL을 정답이 아니라 변경 후보로 다룬다.
- `JOIN`, 필터, `NULL`, 집계 기준과 예상 결과를 사람이 확인한다.
- AI 답변에서 신청 금액·결제·환불·매출 의미가 섞이지 않았는지 확인한다.
- 타당한 부분과 수정한 부분을 기록한다.
