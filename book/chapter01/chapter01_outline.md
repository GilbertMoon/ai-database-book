# Chapter 01 구성안

## 제목

AI 시대에 데이터베이스를 왜 배워야 하는가

## 권장 분량

15~18페이지

## 대상 독자

- 데이터베이스를 처음 배우는 독자
- 프로그래밍이나 SQL 경험이 없는 비전공자
- AI가 만든 데이터 구조와 SQL을 이해하고 검증하려는 독자
- 자신의 속도에 맞춰 개념과 실습을 진행하려는 독자

## 선수 지식

필수 선수 지식은 없다. Chapter 01의 SQL은 실행보다 의미를 이해하기 위한 축약 예제로 사용한다. 실제 PostgreSQL 환경은 Chapter 03에서 준비하고 첫 테이블과 기본 SQL은 Chapter 04에서 다룬다.

## 이 장의 역할

데이터베이스를 처음 배우는 독자가 다음 질문에 답할 수 있도록 안내한다.

```text
AI가 SQL을 작성해 주는데도 왜 데이터베이스를 배워야 하는가?
AI가 만든 구조·SQL·숫자에서 사람은 무엇을 확인해야 하는가?
```

Chapter 01은 데이터·DBMS·테이블·행·열·스키마를 상세하게 정의하는 장이 아니다. 학습 동기와 최소 판단 기준을 제공하고 정확한 기본 용어는 Chapter 02로 넘긴다.

## 핵심 메시지

```text
AI는 데이터베이스의 초안을 빠르게 만들 수 있지만,
무엇을 저장하고 어떻게 연결하며 결과를 믿어도 되는지는 사람이 판단해야 한다.
```

## 이 장을 마치면

독자는 다음 내용을 자신의 말로 설명할 수 있다.

- AI가 SQL을 만들어도 데이터베이스 지식이 필요한 이유
- 실행 성공과 결과 정확성이 서로 다른 이유
- 파일·스프레드시트·DBMS 중심 관리 방식을 선택하는 기준
- AI가 만든 데이터 구조와 SQL에서 사람이 확인해야 할 항목

책 전체의 핵심·선택·심화 학습 표시는 Overview에서 먼저 안내한다. Chapter 01에서는 필요한 선택 학습 표시만 사용하고 책 전체 사용법을 다시 설명하지 않는다.

## 핵심 SQL 사례

### 잘못된 접근

```sql
SELECT COUNT(*) AS student_count
FROM students AS s
INNER JOIN questions AS q
    ON q.student_id = s.id;
```

검토 기준은 다음 네 질문으로 압축한다.

```text
무엇을 세거나 조회하려는가?
결과의 한 행은 무엇을 의미하는가?
누락되거나 중복되는 데이터는 없는가?
작은 예제의 예상 결과와 일치하는가?
```

### 전체 학생 수의 축약 예제

```sql
SELECT COUNT(*) AS student_count
FROM students;
```

가정:

```text
students 한 행 = 학생 한 명
중복 행 없음
비활성·탈퇴 제외 조건 없음
```

## 기준 데이터·파생 데이터·AI 결과

```text
기준 데이터
→ 특정 업무 판단에서 공식 기준으로 삼는 데이터

파생 데이터
→ 기준 데이터를 정해진 방식으로 계산한 결과

AI 생성 결과
→ 모델·입력 데이터·지시에 따라 달라질 수 있는 결과
```

중요한 AI 결과는 어떤 데이터와 지시를 사용했는지 확인할 수 있어야 한다는 수준만 본문에 유지한다. 상세 실행 맥락과 승인 절차는 Chapter 13으로 이동한다.

## AI 활용 포인트

- 서비스 요구사항과 데이터 후보를 AI에게 정리하도록 요청한다.
- AI가 추천한 저장 방식이 실제 요구사항과 맞는지 검토한다.
- AI가 생성한 SQL을 정답이 아니라 변경 후보로 다룬다.
- 기준 행, 누락, 중복과 예상 결과를 확인한다.
- 세부 운영 기록보다 먼저 데이터 의미와 결과 정확성을 확인한다.
- 타당한 부분과 수정한 부분을 자신의 말로 정리한다.

## 편집 원칙

- 일반 독자가 혼자 읽고 따라갈 수 있는 표현을 사용한다.
- 특정 교육 일정, 평가와 운영 방식에 연결되는 표현을 사용하지 않는다.
- 고급 내용을 삭제하기보다 선택·심화 학습으로 분리한다.
- 도입부에서는 용어와 운영 항목을 과도하게 나열하지 않는다.
- 같은 메시지는 도입, 검증 사이클과 핵심 정리에서만 명시적으로 반복한다.
- 본문·구성안·워크북·검수 기록의 절 번호와 용어를 동기화한다.
