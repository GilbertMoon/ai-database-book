## 1. 활동 개요

이 활동 자료는 Chapter 07의 중간 프로젝트를 수행하기 위한 안내서입니다.

학습자는 온라인 강의 수강신청 시스템을 대상으로 요구사항을 분석하고, ERD를 작성하고, PostgreSQL SQL 파일을 작성한 뒤, 샘플 데이터와 CRUD SQL로 설계를 검증합니다.

이 프로젝트는 Chapter 01~06에서 배운 내용을 종합합니다.

```text

데이터 모델링과 ERD
정규화와 좋은 테이블 설계
AI 생성 결과 검토
```

## 2. 프로젝트 주제

```text

```

기본 시나리오는 다음과 같습니다.

```text
온라인 강의 서비스에는 학생, 강사, 강의, 수강신청 정보가 필요합니다.
학생은 여러 강의를 신청할 수 있고, 하나의 강의에도 여러 학생이 등록할 수 있습니다.
강사는 여러 강의를 개설할 수 있고, 하나의 강의는 한 명의 강사가 담당합니다.
```

## 4. 기본 요구사항

다음 요구사항을 기준으로 데이터베이스를 설계하세요.

```text
1. 학생은 이름, 이메일, 가입일을 가진다.
2. 강사는 이름, 이메일, 전문분야를 가진다.
3. 강의는 제목, 설명, 난이도, 수강료, 개설일을 가진다.
4. 하나의 강의는 한 명의 강사가 담당한다.
5. 한 명의 강사는 여러 강의를 개설할 수 있다.
6. 학생은 여러 강의를 수강신청할 수 있다.
7. 하나의 강의에는 여러 학생이 수강신청할 수 있다.
8. 수강신청 정보에는 신청일, 수강상태, 결제금액을 저장한다.
9. 수강상태는 신청, 수강중, 완료, 취소 중 하나로 관리한다.
10. 학생 이메일과 강사 이메일은 중복될 수 없다.
```

```text
students
- id PK
- name
- email
- joined_at

instructors
- id PK
- name
- email
- specialty

courses
- id PK
- instructor_id FK -> instructors.id
- title
- description
- level
- price
- opened_at

enrollments
- id PK
- student_id FK -> students.id
- course_id FK -> courses.id
- enrolled_at
- status
- paid_amount

관계:
instructors 1:N courses
students 1:N enrollments
courses 1:N enrollments
students N:M courses는 enrollments로 해소
```

| 정규화 검토가 형식적임 | -5 ~ -10 |
| AI 답변을 그대로 붙여 넣고 검토가 없음 | -10 ~ -20 |
| 필수 산출물 누락 | -3 ~ -10 |

---

## 21. 피드백 코멘트 예시

### 우수한 경우

```text
요구사항에서 students, instructors, courses, enrollments 엔터티를 정확히 도출했고,
students와 courses의 N:M 관계를 enrollments 테이블로 적절히 해소했습니다.
SQL도 실행 가능하며, JOIN 결과로 수강신청 현황을 검증한 점이 좋습니다.
AI 결과를 그대로 사용하지 않고 외래키와 정규화 관점에서 수정한 점도 우수합니다.
```

### 보완이 필요한 경우

```text
학생과 강의 엔터티는 잘 찾았지만, 수강신청을 별도 테이블로 분리하지 않아 여러 학생이 여러 강의를 신청하는 구조를 표현하기 어렵습니다.
N:M 관계는 직접 연결하기보다 enrollments 같은 중간 테이블로 풀어야 합니다.
또한 SQL 실행 결과와 AI 검토 기록이 부족하므로 보완이 필요합니다.
```

## 23. 핵심 정리

이 활동의 핵심은 중간 프로젝트를 통해 1~6장의 내용을 실제 설계로 연결하는 것입니다.

```text
요구사항은 엔터티와 속성으로 바뀐다.
엔터티는 테이블이 된다.
관계는 외래키가 된다.
N:M 관계는 중간 테이블로 풀어야 한다.
SQL은 설계를 검증하는 도구이다.
AI는 초안을 만들 수 있지만, 최종 검토는 사람이 해야 한다.
```
