# Chapter 07 편집 구성안

## 제목
실전 프로젝트 1: 온라인 강의 수강신청 데이터베이스 설계

## 권장 분량
20~25페이지

## 장의 역할
앞 장에서 살펴본 DBMS, PostgreSQL, SQL, 데이터 모델링, ERD, 정규화 개념을 하나의 작은 서비스에 적용한다. 시험이나 평가를 위한 장이 아니라, 요구사항을 실제 데이터베이스 구조와 실행 가능한 SQL로 바꾸는 전 과정을 경험하는 실전 프로젝트 장으로 구성한다.

## 핵심 질문

```text
서비스 설명에서 어떤 데이터를 찾아야 하는가?
무엇을 테이블로 만들고 무엇을 열로 두어야 하는가?
학생과 강의의 N:M 관계를 어떻게 표현할 것인가?
ERD가 실제 PostgreSQL에서도 정상적으로 동작하는가?
샘플 데이터와 JOIN으로 설계를 어떻게 검증할 것인가?
AI가 만든 설계에서 무엇을 직접 확인해야 하는가?
```

## 프로젝트 주제
온라인 강의 수강신청 시스템

## 독자가 완성하게 될 것

- 요구사항에서 엔터티와 속성을 도출한 분석 기록
- `students`, `instructors`, `courses`, `enrollments` 중심의 ERD
- 기본키, 외래키, 제약조건을 포함한 PostgreSQL DDL
- 관계를 확인할 수 있는 샘플 데이터
- JOIN과 기본 CRUD를 활용한 검증 SQL
- 정규화와 데이터 정합성 관점의 자체 검토
- AI 제안과 최종 설계의 차이를 설명하는 기록

## 편집 원칙

- `중간 프로젝트`, `중간 평가`, `제출`, `배점`, `감점` 표현을 본문에서 사용하지 않는다.
- 결과물은 제출물이 아니라 독자가 완성하는 프로젝트 기록 또는 포트폴리오로 표현한다.
- 평가 기준은 점수표가 아니라 완성도 점검 기준으로 바꾼다.
- 정답 구조를 제시하되 다른 설계 가능성과 선택의 근거도 설명한다.
- SQL의 양보다 요구사항·관계·제약조건·검증 과정의 중요성을 강조한다.
- AI는 설계를 대신 결정하는 도구가 아니라 초안 작성과 검토 질문을 돕는 도구로 다룬다.
- 프로젝트 운영 시간, 파일명 규칙, 채점 루브릭과 교수자 팁은 출간 본문에서 제외한다.
