## 의미와 용어 변경

### 금액 열

```text
paid_amount
→ recorded_amount
```

변경 이유:

- 실제 결제·환불을 프로젝트 범위에서 제외함
- paid라는 이름이 결제 승인 완료 금액으로 해석될 수 있음
- 신청 행에 기록된 금액과 실제 결제 거래를 구분할 필요가 있음

```text
courses.price
→ 현재 강의 기준 가격

enrollments.recorded_amount
→ 신청 시 기록 금액

payments·refunds
→ 실제 결제·환불 거래, 범위 제외
```

### 금액 타입

```text
INTEGER
→ NUMERIC(12, 0)
```

원 단위의 정확한 금액을 저장하고 Chapter 04의 데이터 타입 원칙과 맞췄습니다.

## SQL 실행 안전성

### 01 스키마

- 네 테이블이 모두 비어 있을 때만 입력
- 입력·IDENTITY 조정·완료 검사를 하나의 트랜잭션으로 실행

- 기본 3/2/3/4행 상태 자동 검사
