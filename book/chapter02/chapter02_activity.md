## 1. 워크북 활용 방법

Chapter 02에서는 데이터베이스, DBMS, 테이블, 행, 열, 기본키, 외래키, 관계, SQL, CRUD, 제약조건을 살펴보았습니다.

이 개념들은 각각 따로 외우기보다 하나의 데이터 구조 안에서 연결해 보는 편이 이해하기 쉽습니다.

```text
데이터는 테이블에 저장된다.
테이블의 한 줄은 하나의 행이다.
각 항목은 열로 표현한다.
기본키는 행을 구분한다.
외래키는 다른 테이블과 연결한다.
제약조건은 잘못된 데이터를 막는다.
SQL은 데이터를 생성·조회·수정·삭제한다.
```

이 워크북의 핵심은 정답을 빨리 찾는 것이 아니라, 선택한 구조가 왜 적절한지 설명해 보는 것입니다.

## 4. 안정적인 기본키 선택하기

다음 후보가 기본키로 적합한지 판단해 보세요.

| 테이블 | 후보 열 | 적합 여부 | 판단 이유 |
| --- | --- | --- | --- |
| students | name |  |  |
| students | email |  |  |
| students | id |  |  |
| courses | title |  |  |
| courses | id |  |  |
| members | phone_number |  |  |
| orders | order_id |  |  |

기본키 후보는 다음 기준으로 검토할 수 있습니다.

```text
중복되지 않는가?
비어 있을 가능성이 없는가?
값이 자주 바뀌지 않는가?

```

이메일이나 전화번호는 고유할 수 있지만 변경될 가능성이 있습니다. 그래서 실제 시스템에서는 별도의 숫자형 또는 UUID 식별자를 기본키로 두고, 이메일과 전화번호에는 UNIQUE 제약조건을 적용하는 방식이 자주 사용됩니다.

## 6. 관계 유형 구분하기

다음 관계가 1:1, 1:N, N:M 중 무엇에 해당하는지 판단해 보세요.

| 사례 | 관계 유형 | 판단 이유 |
| --- | --- | --- |
| 한 강사는 여러 강의를 담당할 수 있다. |  |  |
| 한 학생은 여러 강의를 신청하고, 한 강의에도 여러 학생이 등록할 수 있다. |  |  |
| 한 회원은 여러 주문을 할 수 있다. |  |  |
| 한 주문에는 여러 상품이 포함되고, 한 상품도 여러 주문에 포함될 수 있다. |  |  |
| 한 사용자에게 하나의 상세 프로필만 연결된다. |  |  |

```text
1:1  하나의 데이터가 다른 데이터 하나와 연결된다.
1:N  하나의 데이터가 여러 데이터와 연결된다.
N:M  양쪽의 여러 데이터가 서로 연결된다.
```

N:M 관계는 보통 중간 연결 테이블을 통해 구현합니다. 학생과 강의 사이에는 `enrollments`, 주문과 상품 사이에는 `order_items` 같은 테이블을 둘 수 있습니다.

## 7. 서비스 기능을 CRUD로 분류하기

다음 기능을 CRUD 중 하나로 분류하고, 연결되는 SQL 명령어를 적어 보세요.

| 서비스 기능 | CRUD | SQL 명령어 |
| --- | --- | --- |
| 학생을 새로 등록한다. |  |  |
| 학생 목록을 조회한다. |  |  |
| 학생 이메일을 수정한다. |  |  |
| 학생 정보를 삭제한다. |  |  |
| 강의를 새로 개설한다. |  |  |
| 수강신청 상태를 `대기`에서 `신청완료`로 바꾼다. |  |  |
| 결제 내역을 조회한다. |  |  |

### CRUD 기본 대응

| CRUD | 의미 | 대표 SQL |
| --- | --- | --- |
| Create | 데이터 생성 | `INSERT` |
| Read | 데이터 조회 | `SELECT` |
| Update | 데이터 수정 | `UPDATE` |
| Delete | 데이터 삭제 | `DELETE` |

실제 서비스에서는 삭제 기능을 `DELETE`로 바로 구현하지 않고, `is_deleted`나 `status` 값을 바꾸는 방식으로 기록을 남기기도 합니다. 어떤 방식을 선택할지는 데이터의 성격과 보존 정책에 따라 달라집니다.

## 8. 상황에 맞는 제약조건 선택하기

다음 상황에 적합한 제약조건을 선택해 보세요.

| 상황 | 적합한 제약조건 | 이유 |
| --- | --- | --- |
| 학생 id는 각 학생을 고유하게 구분해야 한다. |  |  |
| 학생 이름은 비어 있으면 안 된다. |  |  |
| 이메일은 중복되면 안 된다. |  |  |
| `student_id`는 실제 학생의 id여야 한다. |  |  |
| 상품 가격은 0보다 작으면 안 된다. |  |  |
| 등록일을 입력하지 않으면 현재 시간이 들어가야 한다. |  |  |

사용할 수 있는 대표 제약조건은 다음과 같습니다.

```text
PRIMARY KEY
FOREIGN KEY
NOT NULL
UNIQUE
CHECK
DEFAULT
```

제약조건은 입력 화면의 검증을 대신하는 기능이 아닙니다. 애플리케이션에서도 값을 확인해야 하지만, 데이터베이스에 제약조건을 두면 잘못된 데이터가 최종 저장되는 것을 한 번 더 막을 수 있습니다.

## 13. 핵심 정리

```text
기본키는 한 테이블의 행을 구분한다.
외래키는 서로 다른 테이블을 연결한다.
관계는 데이터가 어떤 방식으로 이어지는지 표현한다.
제약조건은 잘못된 데이터가 저장되는 것을 막는다.
CRUD는 서비스의 기본 데이터 처리 기능과 연결된다.
AI의 설계는 완성본이 아니라 검토해야 할 초안이다.
```
