## 14. 권장 해설

### DBMS·데이터베이스·스키마·테이블

```text
PostgreSQL
→ 데이터베이스를 관리하고 SQL을 실행하는 DBMS

ai_database_book
→ PostgreSQL 안에 만든 데이터베이스

public, course_project
→ 데이터베이스 안의 이름 공간

students, courses
→ 스키마 안의 테이블
```

### 테이블 행 순서

테이블에는 스프레드시트처럼 고정된 첫 번째 행이 있다고 가정하지 않습니다. 결과 순서가 필요하면 `ORDER BY`를 사용합니다. 셀도 화면 위치가 아니라 행 조건과 열 이름으로 다룹니다.

### 기본키와 외래키

```text
기본키
→ 자신의 테이블에서 행을 고유하게 구분
→ 중복과 NULL 불가

외래키
→ 다른 행을 참조
→ 1:N 관계에서는 같은 값 반복 가능
→ NULL 허용 여부는 NOT NULL로 별도 결정
```

### 관계 모델과 업무 관계

릴레이션은 관계 모델의 테이블에 가까운 구조입니다. 업무 관계는 학생과 질문처럼 데이터가 연결되는 규칙이며, 카디널리티는 1:1·1:N·N:M처럼 연결 가능한 최대 개수를 표현합니다.

### CRUD Delete

```text
물리 삭제
→ DELETE로 행 제거

상태 기반 삭제
→ 취소·비활성 상태 또는 deleted_at 기록
→ 과거 이력 보존 가능
```

### 일반 VIEW와 저장된 결과

일반 VIEW는 SQL 조회 정의를 저장하고 호출할 때 원본을 조회합니다. Materialized View, 집계 테이블과 캐시는 결과를 별도로 저장할 수 있으므로 갱신 기준이 필요합니다.

### 데이터 구조 유형과 저장소

정형·반정형·비정형은 데이터의 모양과 구조를 설명합니다. RDBMS·문서형 DB·파일·객체 저장소는 저장 방식을 설명합니다. PostgreSQL도 JSONB로 반정형 데이터를 저장할 수 있으므로 두 분류를 일대일로 연결하지 않습니다.

### 기준 데이터와 AI 결과

```text
기준 데이터
→ 업무 판단과 재생성의 기준

결정적 파생 데이터
→ 같은 기준 데이터·계산식·기준 시점이면 재생성 가능

AI 생성 결과
→ 모델·입력·지시문·실행 조건에 따라 달라질 수 있음
```

### 신청 금액과 결제·매출

```text
신청 당시 기록 금액
≠ 결제 완료 금액
≠ 환불 반영 순금액
≠ 회계 매출
```

실제 결제 분석에는 결제 상태, 실패, 환불과 기준 시점이 필요합니다.
