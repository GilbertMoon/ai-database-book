## 1. 활동 개요

이 활동 자료는 Chapter 02의 내용을 바탕으로, 학습자가 **DBMS 기본 용어와 테이블 구조**를 직접 구분하고 설명할 수 있도록 돕는 보조 자료입니다.

## 8. 활동 5: 관계 유형 판단하기

다음 관계가 1:1, 1:N, N:M 중 무엇인지 판단하세요.

| 사례 | 관계 유형 | 이유 |
| --- | --- | --- |
| 한 명의 강사는 여러 강의를 담당할 수 있다. |  |  |
| 한 학생은 여러 강의를 신청할 수 있고, 한 강의에도 여러 학생이 등록할 수 있다. |  |  |
| 한 회원은 여러 주문을 할 수 있다. |  |  |
| 한 주문에는 여러 상품이 포함될 수 있고, 한 상품도 여러 주문에 포함될 수 있다. |  |  |
| 한 사용자에게 하나의 상세 프로필만 연결된다. |  |  |

### 힌트

```text
1:1 = 하나와 하나가 연결
1:N = 하나가 여러 개와 연결
N:M = 여러 개와 여러 개가 서로 연결
```

## 16. 피드백 코멘트 예시

### 우수한 경우

```text
DBMS 기본 용어를 단순 정의가 아니라 학생-강의-수강신청 예제와 연결해 잘 설명했습니다.
특히 enrollments 테이블이 학생과 강의의 N:M 관계를 연결하는 역할을 한다는 점을 정확히 이해했습니다.
AI가 생성한 student_courses 테이블의 문제점도 기본키, 외래키, 중복 데이터 관점에서 구체적으로 지적했습니다.
```

### 보완이 필요한 경우

```text
기본 용어 설명은 대체로 작성되었지만, 기본키와 외래키의 차이가 아직 명확하지 않습니다.
기본키는 한 테이블 안에서 각 행을 구분하는 값이고, 외래키는 다른 테이블의 기본키를 참조해 관계를 만드는 값입니다.
예제 테이블에서 students.id와 enrollments.student_id의 역할을 다시 비교해 보면 좋겠습니다.
```

## 18. 핵심 정리

이 활동의 핵심은 용어를 외우는 것이 아니라, **테이블 구조 안에서 개념의 역할을 찾는 것**입니다.

```text
기본키는 행을 구분하고,
외래키는 테이블을 연결하며,
제약조건은 잘못된 데이터를 막고,
CRUD는 실제 서비스 기능과 연결된다.
```
