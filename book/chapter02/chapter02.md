## 1. 왜 DBMS 기본 개념을 먼저 배워야 하는가

데이터베이스를 처음 배우면 SQL 문법부터 빨리 실습하고 싶을 수 있습니다.

```sql
SELECT * FROM students;
```

이 SQL은 students 테이블의 데이터를 조회합니다. 하지만 이 문장을 제대로 이해하려면 먼저 다음 질문에 답할 수 있어야 합니다.

```text
students는 무엇인가?
테이블은 무엇인가?
테이블 안의 한 줄은 무엇을 의미하는가?
id 컬럼은 왜 필요한가?
학생과 수강신청은 어떻게 연결되는가?
```

SQL은 데이터베이스에 명령을 내리는 언어입니다. 그런데 데이터베이스의 구조를 이해하지 못하면 SQL이 무엇을 대상으로 동작하는지 알기 어렵습니다.

특히 AI 시대에는 이 기본 개념이 더 중요합니다. ChatGPT나 Codex는 테이블 생성 SQL을 빠르게 만들어 줄 수 있습니다. 하지만 그 결과가 좋은 구조인지 판단하려면 기본 개념을 알아야 합니다.

예를 들어 AI가 다음과 같은 테이블을 만들었다고 가정해 보겠습니다.

```sql
CREATE TABLE students (
    name VARCHAR(50),
    course_name VARCHAR(100),
    instructor_name VARCHAR(50)
);
```

초급자는 이 구조를 보고 “학생, 강의, 강사 정보가 있으니 괜찮다”고 생각할 수 있습니다. 하지만 DBMS 기본 개념을 알고 나면 다음 문제가 보입니다.

```text
- 각 학생을 구분할 기본키가 없다.
- 강의 정보가 학생 테이블에 섞여 있다.
- 강사 정보도 학생 테이블에 섞여 있다.
- 학생이 여러 강의를 들으면 같은 학생 이름이 반복된다.
- 강의명이 바뀌면 여러 행을 수정해야 한다.
```

따라서 이 장의 목표는 SQL을 많이 작성하는 것이 아니라, SQL과 테이블 설계를 이해하기 위한 기본 언어를 익히는 것입니다.

## 2. 데이터베이스와 DBMS

### 2.1 데이터베이스란 무엇인가

데이터베이스(Database)는 데이터를 체계적으로 저장한 공간입니다.

예를 들어 학교에서 학생, 강의, 수강신청 정보를 관리한다고 생각해 보겠습니다. 이 데이터가 엑셀 파일 여러 개에 흩어져 있다면 관리가 어려울 수 있습니다. 반면 데이터베이스에 구조적으로 저장하면 필요한 정보를 안정적으로 조회하고 수정할 수 있습니다.

쉽게 말하면 데이터베이스는 다음과 같은 역할을 합니다.

```text
- 데이터를 저장한다.
- 데이터를 찾을 수 있게 한다.
- 데이터를 수정할 수 있게 한다.
- 잘못된 데이터가 들어가지 않도록 돕는다.
- 여러 데이터 사이의 관계를 관리한다.
```

### 2.2 DBMS란 무엇인가

DBMS(Database Management System)는 데이터베이스를 관리하는 소프트웨어입니다.

데이터베이스가 데이터를 담는 공간이라면, DBMS는 그 공간을 만들고 관리하고 사용할 수 있게 해 주는 프로그램입니다.

대표적인 DBMS는 다음과 같습니다.

| DBMS | 설명 |
| --- | --- |
| PostgreSQL | 오픈소스 관계형 DBMS, 이 책의 기본 실습 DB |
| MySQL | 웹 서비스에서 많이 사용되는 관계형 DBMS |
| MariaDB | MySQL에서 파생된 오픈소스 DBMS |
| Oracle Database | 기업용 시스템에서 많이 사용하는 상용 DBMS |
| SQL Server | Microsoft 계열의 상용 DBMS |
| SQLite | 파일 기반의 경량 관계형 DBMS |

이 책에서는 PostgreSQL을 기본 DBMS로 사용합니다.

### 2.3 데이터베이스와 DBMS의 차이

두 용어는 자주 섞여 쓰이지만 엄밀히 말하면 다릅니다.

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| 데이터베이스 | 실제 데이터가 저장된 공간 | `school_db`, `shop_db` |
| DBMS | 데이터베이스를 관리하는 소프트웨어 | PostgreSQL, MySQL |

예를 들어 PostgreSQL이라는 DBMS 안에 `school_db`라는 데이터베이스를 만들 수 있습니다. 그리고 그 데이터베이스 안에 `students`, `courses`, `enrollments` 같은 테이블을 만들 수 있습니다.

```text
PostgreSQL(DBMS)
└── school_db(데이터베이스)
    ├── students(테이블)
    ├── courses(테이블)
    └── enrollments(테이블)
```

이 구조를 이해하면 이후 DBeaver에서 접속 정보를 볼 때 혼동이 줄어듭니다.

## 3. 테이블, 행, 열

관계형 데이터베이스에서 가장 기본이 되는 구조는 테이블입니다.

### 3.1 테이블이란 무엇인가

테이블(Table)은 데이터를 행과 열로 정리한 구조입니다. 엑셀 시트와 비슷하게 생각할 수 있습니다.

예를 들어 학생 정보를 저장하는 students 테이블은 다음과 같이 표현할 수 있습니다.

| id | name | email | major |
| ---: | --- | --- | --- |
| 1 | 김민지 | minji@example.com | 컴퓨터공학 |
| 2 | 이준호 | junho@example.com | 데이터사이언스 |
| 3 | 박서연 | seoyeon@example.com | 경영학 |

이 표 전체가 하나의 테이블입니다.

### 3.2 행(Row)

행(Row)은 테이블 안의 한 줄입니다. 하나의 행은 하나의 데이터 기록을 의미합니다.

students 테이블에서 다음 한 줄은 한 명의 학생 정보를 의미합니다.

| id | name | email | major |
| ---: | --- | --- | --- |
| 1 | 김민지 | minji@example.com | 컴퓨터공학 |

이 한 줄 전체가 하나의 행입니다.

### 3.3 열(Column)

열(Column)은 테이블에서 데이터의 항목을 의미합니다.

students 테이블의 열은 다음과 같습니다.

```text
id
name
email
major
```

각 열은 저장할 데이터의 종류를 나타냅니다.

| 열 이름 | 의미 |
| --- | --- |
| id | 학생을 구분하는 번호 |
| name | 학생 이름 |
| email | 이메일 주소 |
| major | 전공 |

### 3.4 테이블, 행, 열을 구분하는 이유

테이블, 행, 열은 매우 기본적인 용어이지만 이후 모든 장에서 계속 사용됩니다.

예를 들어 다음 문장을 이해하려면 이 세 용어가 필요합니다.

```text
students 테이블에서 major 컬럼이 '컴퓨터공학'인 행만 조회한다.
```

이 문장을 SQL로 쓰면 다음과 같습니다.

```sql
SELECT *
FROM students
WHERE major = '컴퓨터공학';
```

따라서 SQL 문법을 배우기 전에 테이블, 행, 열의 의미를 정확히 알아야 합니다.

## 4. 기본키(PK)

### 4.1 기본키란 무엇인가

기본키(Primary Key, PK)는 테이블에서 각 행을 구분하는 고유한 값입니다.

학생 테이블에 이름이 같은 학생이 두 명 있을 수 있습니다. 이메일이 바뀔 수도 있습니다. 전공도 바뀔 수 있습니다. 따라서 이름, 이메일, 전공만으로 학생을 안정적으로 구분하기는 어렵습니다.

그래서 보통 다음과 같이 `id` 컬럼을 둡니다.

| id | name | email |
| ---: | --- | --- |
| 1 | 김민지 | minji@example.com |
| 2 | 김민지 | minji2@example.com |

위 표에서는 이름이 같아도 `id`가 다르기 때문에 두 학생을 구분할 수 있습니다.

### 4.2 기본키의 특징

기본키는 다음 특징을 가져야 합니다.

| 특징 | 설명 |
| --- | --- |
| 고유성 | 같은 값이 중복되면 안 됨 |
| 필수성 | 비어 있으면 안 됨 |
| 안정성 | 자주 바뀌지 않는 값이어야 함 |
| 식별성 | 각 행을 명확히 구분할 수 있어야 함 |

PostgreSQL에서는 다음과 같이 기본키를 지정할 수 있습니다.

```sql
CREATE TABLE students (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL
);
```

여기서 `id SERIAL PRIMARY KEY`는 `id` 컬럼을 자동 증가하는 기본키로 사용하겠다는 의미입니다.

### 4.3 이름을 기본키로 쓰면 안 되는 이유

초급자가 자주 하는 실수 중 하나는 이름을 기본키처럼 사용하는 것입니다.

```text
학생 이름은 사람을 구분할 수 있으니 name을 기본키로 쓰면 되지 않을까?
```

하지만 이름은 기본키로 적합하지 않습니다.

```text
- 같은 이름을 가진 사람이 있을 수 있다.
- 이름이 변경될 수 있다.
- 오타가 발생할 수 있다.
- 영문명, 한글명, 별칭 등 표기 방식이 달라질 수 있다.
```

따라서 실무에서는 보통 별도의 `id`를 만들어 기본키로 사용합니다.

## 5. 외래키(FK)

### 5.1 외래키란 무엇인가

외래키(Foreign Key, FK)는 다른 테이블의 기본키를 참조하는 컬럼입니다.

외래키는 테이블과 테이블을 연결하는 역할을 합니다.

예를 들어 수강신청 정보를 저장하려면 학생과 강의를 연결해야 합니다.

```text
어떤 학생이 어떤 강의를 신청했는가?
```

이를 위해 다음 세 테이블을 사용할 수 있습니다.

```text
students
courses
enrollments
```

students 테이블:

| id | name |
| ---: | --- |
| 1 | 김민지 |
| 2 | 이준호 |

courses 테이블:

| id | title |
| ---: | --- |
| 10 | 데이터베이스 입문 |
| 20 | 파이썬 기초 |

수강신청 테이블인 enrollments는 학생과 강의를 연결합니다.

| id | student_id | course_id |
| ---: | ---: | ---: |
| 1 | 1 | 10 |
| 2 | 1 | 20 |
| 3 | 2 | 10 |

여기서 `student_id`는 students 테이블의 `id`를 참조합니다. `course_id`는 courses 테이블의 `id`를 참조합니다. 이런 컬럼이 외래키입니다.

### 5.2 외래키가 필요한 이유

외래키가 없으면 데이터 사이의 연결이 약해집니다.

예를 들어 수강신청 테이블에 학생 이름과 강의명을 직접 저장하면 다음과 같은 문제가 생깁니다.

| student_name | course_title |
| --- | --- |
| 김민지 | 데이터베이스 입문 |
| 김민지 | 파이썬 기초 |
| 이준호 | 데이터베이스 입문 |

이 구조는 처음에는 쉬워 보이지만 다음 문제가 있습니다.

```text
- 학생 이름이 바뀌면 여러 행을 수정해야 한다.
- 강의명이 바뀌면 여러 행을 수정해야 한다.
- 같은 이름의 학생을 구분하기 어렵다.
- 실제 students 테이블에 없는 학생 이름이 들어갈 수 있다.
```

반면 외래키를 사용하면 학생과 강의를 안정적으로 연결할 수 있습니다.

### 5.3 외래키 SQL 예시

PostgreSQL에서는 다음과 같이 외래키를 지정할 수 있습니다.

```sql
CREATE TABLE enrollments (
    id SERIAL PRIMARY KEY,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    enrolled_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (student_id) REFERENCES students(id),
    FOREIGN KEY (course_id) REFERENCES courses(id)
);
```

이 구조에서는 `student_id`가 students 테이블에 실제로 존재하는 id를 참조해야 합니다. `course_id`도 courses 테이블에 실제로 존재하는 id를 참조해야 합니다.

## 6. 관계란 무엇인가

관계(Relationship)는 테이블과 테이블 사이의 연결입니다.

관계형 데이터베이스라는 이름에서 알 수 있듯이, RDBMS는 데이터를 여러 테이블로 나누고 그 테이블 사이의 관계를 관리하는 방식에 강합니다.

### 6.1 1:1 관계

1:1 관계는 한 데이터가 다른 데이터 하나와 연결되는 관계입니다.

예를 들어 한 사용자가 하나의 프로필 상세 정보를 가진다고 가정할 수 있습니다.

```text
users 1명 ↔ user_profiles 1개
```

1:1 관계는 실무에서 자주 등장하지만, 초급 단계에서는 1:N과 N:M 관계가 더 중요합니다.

### 6.2 1:N 관계

1:N 관계는 하나의 데이터가 여러 데이터와 연결되는 관계입니다.

예를 들어 강사 한 명은 여러 강의를 담당할 수 있습니다.

```text
instructors 1명 → courses 여러 개
```

courses 테이블에는 `instructor_id` 외래키가 들어갑니다.

```sql
CREATE TABLE courses (
    id SERIAL PRIMARY KEY,
    instructor_id INT NOT NULL,
    title VARCHAR(100) NOT NULL,
    FOREIGN KEY (instructor_id) REFERENCES instructors(id)
);
```

### 6.3 N:M 관계

N:M 관계는 여러 데이터가 여러 데이터와 서로 연결되는 관계입니다.

학생과 강의는 대표적인 N:M 관계입니다.

```text
학생 한 명은 여러 강의를 신청할 수 있다.
강의 하나에도 여러 학생이 등록할 수 있다.
```

이 관계를 직접 students 테이블이나 courses 테이블에 넣기는 어렵습니다. 그래서 중간에 연결 테이블을 만듭니다.

```text
students ↔ enrollments ↔ courses
```

연결 테이블인 enrollments는 학생과 강의를 연결하는 역할을 합니다.

### 6.4 관계를 이해해야 하는 이유

관계를 이해하지 못하면 모든 데이터를 하나의 테이블에 넣으려고 하거나, 연결 테이블 없이 N:M 관계를 표현하려고 합니다.

이런 구조는 처음에는 편해 보이지만 데이터가 늘어나면 큰 문제가 됩니다.

```text
- 중복 데이터가 많아진다.
- 수정해야 할 데이터가 여러 곳에 흩어진다.
- JOIN이 어려워진다.
- 데이터 정합성을 유지하기 어렵다.
```

## 7. SQL과 CRUD

### 7.1 SQL이란 무엇인가

SQL(Structured Query Language)은 데이터베이스에 명령을 내리는 언어입니다.

SQL을 사용하면 다음 작업을 할 수 있습니다.

```text
- 테이블을 만든다.
- 데이터를 추가한다.
- 데이터를 조회한다.
- 데이터를 수정한다.
- 데이터를 삭제한다.
- 데이터를 집계한다.
```

SQL은 이후 Chapter 04부터 본격적으로 실습합니다. 이 장에서는 SQL이 무엇을 하는 언어인지 큰 그림만 이해하면 됩니다.

### 7.2 CRUD란 무엇인가

CRUD는 데이터 처리의 가장 기본적인 네 가지 작업입니다.

| 약어 | 의미 | SQL 예시 |
| --- | --- | --- |
| C | Create, 생성 | `INSERT` |
| R | Read, 조회 | `SELECT` |
| U | Update, 수정 | `UPDATE` |
| D | Delete, 삭제 | `DELETE` |

예를 들어 학생 관리 시스템의 기본 기능은 대부분 CRUD로 설명할 수 있습니다.

| 기능 | CRUD | 설명 |
| --- | --- | --- |
| 학생 등록 | Create | 새 학생을 추가함 |
| 학생 목록 조회 | Read | 저장된 학생을 확인함 |
| 학생 정보 수정 | Update | 이메일이나 전공을 수정함 |
| 학생 삭제 | Delete | 학생 정보를 삭제함 |

웹 서비스를 만들 때도 CRUD는 가장 기본적인 구조입니다. 최종 프로젝트에서는 데이터베이스 설계를 실제 웹 CRUD와 연결해 보게 됩니다.

## 8. 제약조건

### 8.1 제약조건이란 무엇인가

제약조건(Constraint)은 잘못된 데이터가 들어가지 않도록 막는 규칙입니다.

데이터베이스는 단순히 데이터를 저장하는 공간이 아닙니다. 데이터가 정확하게 유지되도록 관리하는 역할도 합니다.

예를 들어 학생 이메일은 비어 있으면 안 되고, 같은 이메일이 두 번 들어가면 안 된다고 가정해 보겠습니다. 이런 규칙을 테이블에 지정할 수 있습니다.

```sql
CREATE TABLE students (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL
);
```

위 SQL에는 다음 제약조건이 포함되어 있습니다.

| 제약조건 | 의미 |
| --- | --- |
| PRIMARY KEY | 각 행을 고유하게 구분 |
| NOT NULL | 비어 있는 값을 허용하지 않음 |
| UNIQUE | 중복 값을 허용하지 않음 |

### 8.2 주요 제약조건

대표적인 제약조건은 다음과 같습니다.

| 제약조건 | 설명 | 예시 |
| --- | --- | --- |
| PRIMARY KEY | 기본키 지정 | 학생 id |
| FOREIGN KEY | 다른 테이블 참조 | 수강신청의 student_id |
| NOT NULL | 빈 값 금지 | 학생 이름 |
| UNIQUE | 중복 금지 | 이메일 |
| CHECK | 조건 검증 | 가격은 0 이상 |
| DEFAULT | 기본값 지정 | 등록일 기본값 |

### 8.3 제약조건이 없으면 생기는 문제

제약조건이 없으면 다음과 같은 데이터가 들어갈 수 있습니다.

```text
- 이름이 없는 학생
- 같은 이메일을 가진 여러 학생
- 존재하지 않는 강의를 신청한 수강신청 기록
- 음수 가격의 상품
- 결제 상태가 이상한 값인 데이터
```

이런 문제는 나중에 서비스 오류나 데이터 분석 오류로 이어질 수 있습니다.

## 9. 작은 예제: 학생과 수강신청 구조

| 개념 | 예시 |

| 데이터베이스 | 온라인 강의 서비스 DB |
| 테이블 | students, courses, enrollments |

## 10. AI 활용 실습: 테이블 구조 생성하고 검토하기

이제 ChatGPT를 활용해 간단한 테이블 구조를 생성해 보겠습니다.

다음 프롬프트를 입력해 보세요.

```text
학생, 강의, 수강신청 정보를 저장하는 데이터베이스 테이블을 설계해 주세요.
각 테이블의 기본키와 외래키를 표시해 주세요.
PostgreSQL 기준으로 설명해 주세요.
```

AI가 답변을 생성하면 바로 정답으로 받아들이지 말고 다음 기준으로 검토합니다.

| 검토 항목 | 확인 질문 |
| --- | --- |
| 테이블 분리 | 학생, 강의, 수강신청이 적절히 분리되었는가? |
| 기본키 | 각 테이블에 기본키가 있는가? |
| 외래키 | 수강신청 테이블에 학생과 강의를 참조하는 외래키가 있는가? |
| 중복 | 학생 이름이나 강의명이 여러 곳에 반복 저장되지 않는가? |
| 제약조건 | NOT NULL, UNIQUE 같은 기본 제약조건이 있는가? |
| PostgreSQL 문법 | SERIAL, VARCHAR, TIMESTAMP 등이 적절히 사용되었는가? |

### 10.1 AI 답변 검토 예시

AI가 다음과 같은 구조를 제안했다고 가정해 보겠습니다.

```sql
CREATE TABLE enrollments (
    id SERIAL PRIMARY KEY,
    student_name VARCHAR(50),
    course_title VARCHAR(100),
    enrollment_date DATE
);
```

이 구조는 수강신청 정보를 저장할 수는 있지만, 좋은 구조라고 보기 어렵습니다.

문제점은 다음과 같습니다.

```text
- student_name은 students 테이블의 id를 참조하지 않는다.
- course_title은 courses 테이블의 id를 참조하지 않는다.
- 같은 학생 이름과 강의 제목이 반복 저장된다.
- 이름이나 강의명이 바뀌면 여러 행을 수정해야 한다.
- 학생과 강의의 관계가 외래키로 관리되지 않는다.
```

더 나은 구조는 다음과 같습니다.

```sql
CREATE TABLE enrollments (
    id SERIAL PRIMARY KEY,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    enrolled_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(20) DEFAULT '신청완료',
    FOREIGN KEY (student_id) REFERENCES students(id),
    FOREIGN KEY (course_id) REFERENCES courses(id)
);
```

이렇게 하면 수강신청 테이블이 학생과 강의를 안정적으로 연결할 수 있습니다.

## 11. 자주 하는 실수

### 실수 1. 기본키를 만들지 않는다

기본키가 없으면 각 행을 안정적으로 구분하기 어렵습니다. 이름이나 제목만으로 데이터를 구분하려고 하면 중복 문제가 생깁니다.

### 실수 2. 외래키 없이 텍스트로 관계를 표현한다

수강신청 테이블에 `student_name`, `course_title`을 직접 저장하는 방식은 처음에는 쉬워 보입니다. 하지만 데이터가 늘어나면 중복과 수정 문제가 생깁니다.

### 실수 3. 하나의 테이블에 모든 정보를 넣는다

학생, 강의, 강사, 수강신청, 결제 정보를 하나의 테이블에 모두 넣으면 구조가 복잡해지고 중복이 많아집니다.

### 실수 4. 제약조건을 생략한다

NOT NULL, UNIQUE, FOREIGN KEY 같은 제약조건을 생략하면 잘못된 데이터가 들어가기 쉽습니다.

### 실수 5. AI가 만든 테이블을 그대로 사용한다

AI가 만든 테이블 구조는 초안입니다. 반드시 기본키, 외래키, 관계, 중복, 제약조건 관점에서 검토해야 합니다.

## 15. 정리

이번 장에서는 DBMS의 기본 개념을 학습했습니다.

핵심 내용을 정리하면 다음과 같습니다.

```text
1. 데이터베이스는 데이터를 체계적으로 저장한 공간이다.
2. DBMS는 데이터베이스를 관리하는 소프트웨어이다.
3. 테이블은 데이터를 행과 열로 정리한 구조이다.
4. 행은 하나의 데이터 기록이고, 열은 데이터의 항목이다.
5. 기본키는 각 행을 구분하는 고유한 값이다.
6. 외래키는 다른 테이블의 기본키를 참조하여 테이블 간 관계를 만든다.
7. 관계에는 1:1, 1:N, N:M 관계가 있다.
8. SQL은 데이터베이스에 명령을 내리는 언어이다.
9. CRUD는 생성, 조회, 수정, 삭제를 의미한다.
10. 제약조건은 잘못된 데이터가 들어가지 않도록 돕는 규칙이다.
```

이 장에서 가장 중요한 문장은 다음입니다.

```text
좋은 데이터베이스 설계는 테이블, 기본키, 외래키, 관계를 정확히 이해하는 것에서 시작한다.
```
