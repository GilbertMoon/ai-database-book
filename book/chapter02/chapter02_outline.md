# Chapter 02 구성안

## 제목

DBMS 기본 개념

## 권장 분량

15~20페이지

## 이 장의 역할

데이터베이스를 처음 접하는 독자가 이후 장에서 반복해서 만나게 될 핵심 용어를 하나의 서비스 사례 안에서 자연스럽게 이해하도록 한다. 용어를 사전식으로 나열하기보다, 데이터가 테이블에 저장되고 기본키와 외래키로 연결되는 과정을 중심으로 설명한다.

이 장의 핵심 질문은 다음과 같다.

```text
데이터베이스와 DBMS는 어떻게 다른가?
테이블의 행과 열은 각각 무엇을 의미하는가?
기본키와 외래키는 왜 필요한가?
여러 테이블은 어떤 방식으로 연결되는가?
SQL과 CRUD는 실제 서비스 기능과 어떻게 이어지는가?
AI가 만든 테이블 구조는 무엇을 기준으로 검토해야 하는가?
```

## 독자가 얻게 될 것

- 데이터베이스와 DBMS의 차이를 구분할 수 있다.
- 테이블, 행, 열의 의미를 실제 데이터와 연결해 이해할 수 있다.
- 기본키와 외래키의 역할을 설명할 수 있다.
- 1:1, 1:N, N:M 관계의 기본 구조를 구분할 수 있다.
- SQL과 CRUD를 서비스 기능과 연결해 이해할 수 있다.
- 대표적인 제약조건이 필요한 이유를 판단할 수 있다.
- AI가 생성한 테이블 구조에서 기본적인 문제를 찾을 수 있다.

## 주요 개념

- 데이터베이스
- DBMS
- 테이블
- 행(Row)
- 열(Column)
- 기본키(Primary Key, PK)
- 외래키(Foreign Key, FK)
- 관계(Relationship)
- SQL
- CRUD
- 제약조건(Constraint)

## 본문 흐름

1. SQL보다 먼저 데이터 구조를 이해해야 하는 이유
2. 데이터베이스와 DBMS의 차이
3. 테이블, 행, 열
4. 기본키와 외래키
5. 1:1, 1:N, N:M 관계
6. SQL과 CRUD
7. 제약조건이 필요한 이유
8. 학생·강의·수강신청 사례로 개념 연결하기
9. AI에게 테이블 설계를 요청하고 검토하기
10. 자주 발생하는 설계 실수
11. 직접 확인하고 설계해 보기
12. 핵심 정리와 다음 장 연결

## 독자 참여 요소

- 예제 테이블에서 행, 열, 기본키, 외래키 찾기
- 여러 후보 중 안정적인 기본키 선택하기
- 서비스 기능을 CRUD로 분류하기
- 상황에 맞는 제약조건 선택하기
- AI가 만든 단일 테이블 설계의 문제점 찾기
- 도서 대여 시스템의 테이블 구조 초안 만들기

## AI 활용 포인트

- ChatGPT에 학생·강의·수강신청 테이블 초안을 요청한다.
- 생성된 결과를 테이블 분리, PK, FK, 관계, 중복, 제약조건 관점에서 검토한다.
- AI 답변을 그대로 사용하는 대신, 수정 이유를 자신의 언어로 설명한다.

## 편집 원칙

- 직접적인 강의 운영 표현은 본문에서 사용하지 않는다.
- 학생 관리 시스템은 교육 상황이 아니라 관계형 데이터 구조를 설명하기 위한 대표 서비스 사례로 다룬다.
- 설명을 먼저 제시하고, 표·SQL·그림이 설명을 보조하도록 구성한다.
- 별도 활동 자료는 필수 수행 항목이 아닌 선택형 `독자 워크북`으로 제공한다.
- PostgreSQL 설치 전 단계이므로 SQL은 구조를 이해할 수 있는 최소 범위에서만 제시한다.
