# Chapter 02 구성안

## 제목

데이터와 DBMS의 기본 개념

## 권장 분량

12~16페이지

## 이 장의 역할

데이터베이스를 처음 접하는 독자가 PostgreSQL 실습을 시작하기 전에 필요한 기본 구조와 공통 용어를 이해하도록 한다. 상세 설계와 SQL 문법을 미리 가르치기보다, DBMS·데이터베이스·스키마·테이블·행·열·키가 어떤 계층과 역할로 연결되는지 설명하는 데 집중한다.

이 장의 핵심 질문은 다음과 같다.

```text
데이터, 데이터베이스와 DBMS는 어떻게 다른가?
DBeaver와 PostgreSQL은 각각 어떤 역할을 하는가?
데이터베이스, 스키마와 테이블은 어떻게 포함되는가?
테이블의 한 행과 열은 각각 무엇을 의미하는가?
기본키와 외래키는 왜 필요한가?
DBMS는 데이터의 정확성과 안전성을 어떻게 지원하는가?
원본 데이터와 파생 데이터는 어떻게 다른가?
AI가 만든 구조에서 어떤 기본 문제를 찾을 수 있는가?
```

## 독자가 얻게 될 것

- 데이터, 데이터베이스와 DBMS의 차이를 구분할 수 있다.
- DBeaver가 클라이언트 도구이고 PostgreSQL이 DBMS임을 설명할 수 있다.
- 서버, 데이터베이스, 스키마와 테이블의 계층을 설명할 수 있다.
- 테이블, 행, 열, 셀과 데이터 타입의 의미를 구분할 수 있다.
- 기본키와 외래키의 핵심 역할을 설명할 수 있다.
- 1:1, 1:N, N:M 관계의 의미를 간단히 구분할 수 있다.
- SQL과 CRUD의 기본 관계를 이해할 수 있다.
- 정형·반정형·비정형 데이터를 구분할 수 있다.
- 원본 데이터와 파생 데이터의 차이를 설명할 수 있다.
- AI가 만든 구조를 한 행의 의미, 키, 데이터 혼합 관점에서 검토할 수 있다.

## AI 활용 포인트

- AI가 제안한 테이블에서 한 행이 무엇을 나타내는지 확인한다.
- 기본키가 존재하는지 확인한다.
- 서로 다른 성격의 데이터가 한 테이블에 섞였는지 확인한다.
- 다른 테이블을 참조해야 할 값이 이름이나 문자열로 반복되는지 확인한다.
- 상세한 관계·제약조건 문제는 후속 장의 기준으로 다시 검토한다.

## 편집 원칙

- Chapter 02는 설계를 완성하는 장이 아니라 기본 구조를 읽는 장으로 제한한다.
- PostgreSQL 설치 전 단계이므로 SQL은 구조 이해를 위한 최소 예제만 제시한다.
- DBeaver를 DBMS로 오해하지 않도록 역할을 명확히 구분한다.
- PostgreSQL의 `public` 스키마를 Chapter 03의 실제 화면과 연결한다.
- 관계·제약조건·CRUD의 상세 설명은 후속 장과 중복하지 않는다.
- 별도 활동 자료는 선택형 독자 워크북으로 제공한다.
