# Chapter 02 구성안

## 제목

데이터와 DBMS의 기본 개념

## 권장 분량

16~20페이지

## 이 장의 역할

데이터베이스를 처음 접하는 독자가 PostgreSQL 실습을 시작하기 전에 필요한 기본 구조와 공통 용어를 이해하도록 한다. 상세 설계와 SQL 문법을 미리 가르치기보다 DBMS·데이터베이스·스키마·테이블·행·열·키가 어떤 계층과 역할로 연결되는지 설명하는 데 집중한다.

Chapter 01의 학습 동기와 판단 기준을 이어받되, Chapter 02에서는 정확한 용어와 구조 읽기를 담당한다.

```text
Chapter 01
→ 왜 DB를 배우고 AI 결과를 검증해야 하는가

Chapter 02
→ 데이터·DB·DBMS와 PostgreSQL 구조를 어떻게 읽는가
```

## 핵심 질문

```text
데이터, 데이터베이스와 DBMS는 어떻게 다른가?
DBeaver와 PostgreSQL은 각각 어떤 역할을 하는가?
데이터베이스, 스키마와 테이블은 어떻게 포함되는가?
테이블의 한 행과 열은 각각 무엇을 의미하는가?
테이블 조회 결과의 순서는 왜 자동으로 보장되지 않는가?
릴레이션, 업무 관계와 카디널리티는 어떻게 다른가?
기본키와 외래키는 왜 필요하며 무엇이 다른가?
외래키의 중복·NULL 허용 여부는 어떻게 결정되는가?
CRUD Delete와 SQL DELETE는 항상 같은가?
기준 데이터·결정적 파생 데이터·AI 생성 결과는 어떻게 다른가?
일반 VIEW와 결과를 저장하는 객체는 어떻게 다른가?
AI가 만든 구조에서 어떤 기본 문제를 찾을 수 있는가?
```

## 독자가 얻게 될 것

- 데이터, 데이터베이스와 DBMS의 차이를 구분할 수 있다.
- DBeaver가 클라이언트이고 PostgreSQL이 DBMS임을 설명할 수 있다.
- 서버, 데이터베이스, 스키마와 테이블의 계층을 설명할 수 있다.
- Chapter 03·04·07에서 어떤 객체가 생성되는지 구분할 수 있다.
- 테이블, 행, 열, 셀과 데이터 타입의 의미를 구분할 수 있다.
- `ORDER BY`가 없으면 조회 순서가 보장되지 않는다고 설명할 수 있다.
- 릴레이션, 업무 관계와 카디널리티를 구분할 수 있다.
- 기본키와 외래키의 역할을 설명할 수 있다.
- 외래키 값의 반복·NULL 가능성을 이해할 수 있다.
- CRUD Delete와 물리적·상태 기반 삭제를 구분할 수 있다.
- 데이터 구조 유형과 저장 방식 유형을 구분할 수 있다.
- 기준 데이터, 결정적 파생 데이터와 AI 생성 결과를 구분할 수 있다.
- 일반 VIEW가 결과 자체를 저장하지 않는다고 설명할 수 있다.
- AI가 만든 구조를 한 행의 의미, 키, 데이터 타입과 필수 여부 관점에서 검토할 수 있다.

## AI 활용 포인트

- AI가 제안한 테이블에서 한 행이 무엇을 나타내는지 확인한다.
- 기본키가 존재하는지 확인한다.
- 서로 다른 성격의 데이터가 한 테이블에 섞였는지 확인한다.
- 다른 테이블을 참조해야 할 값이 문자열로 반복되는지 확인한다.
- 데이터 타입이 값의 의미와 맞는지 확인한다.
- 필수값과 선택값을 구분했는지 확인한다.
- 상세 관계와 제약조건 문제는 Chapter 05~06의 기준으로 다시 검토한다.
