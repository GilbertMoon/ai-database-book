# Chapter 12. NoSQL 이해와 선택 기준

## 이 장에서 배울 내용

이 장에서는 관계형 DBMS와 다른 방식으로 데이터를 저장하는 NoSQL의 기본 개념을 학습합니다.

- NoSQL의 필요성
- Key-Value DB
- Document DB
- Column-Family DB
- Graph DB
- DB 선택 기준

## 왜 이 내용을 배우는가

모든 데이터를 관계형 DBMS에 저장해야 하는 것은 아닙니다. 캐시, 로그, 문서형 데이터, 관계 분석 등에는 다른 방식의 DB가 더 적합할 수 있습니다.

## 핵심 개념

### NoSQL

NoSQL은 전통적인 테이블 중심 구조와 다른 방식으로 데이터를 저장하는 데이터베이스 계열입니다.

### Document DB

Document DB는 JSON과 비슷한 문서 형태로 데이터를 저장합니다.

각 데이터에 적합한 DBMS 또는 NoSQL 종류를 추천하고 이유를 설명해 주세요.

## 검토 질문

- 정합성이 중요한 데이터에 NoSQL을 무리하게 추천하지 않았는가?
- 캐시나 로그처럼 NoSQL이 적합한 경우를 구분했는가?
- 데이터 구조와 조회 패턴을 함께 고려했는가?

## 자주 하는 실수

- NoSQL이 RDBMS보다 항상 좋다고 생각한다.
- NoSQL은 스키마가 전혀 필요 없다고 오해한다.
- 서비스 핵심 거래 데이터에 정합성 검토 없이 NoSQL을 사용한다.

## 정리

DB 선택은 기술 유행이 아니라 데이터의 성격과 사용 방식에 따라 결정해야 합니다. AI가 추천한 DB도 정합성, 확장성, 조회 패턴을 기준으로 검토해야 합니다.
