# Chapter 14 리뷰 체크리스트

## 대상 Chapter

```text
Chapter 14. Vector DB와 RAG 기초
```

## 리뷰 목적

Chapter 14가 Vector DB와 RAG의 기본 개념을 입문 독자에게 충분히 설명하는지 점검합니다.

또한 본문, 실습 SQL, 활동 자료, 도식, 리뷰 기록이 일관되게 연결되어 있는지 확인합니다.

## 2. 개념 정확성 점검

| 점검 항목 | 상태 | 리뷰 의견 |
| --- | --- | --- |
| 임베딩 개념이 명확한가 | 통과 | 텍스트 의미를 숫자 벡터로 표현하는 과정으로 설명함 |
| 벡터와 유사도 검색이 입문 독자 수준으로 설명되었는가 | 통과 | 2차원 좌표와 3차원 샘플 벡터로 직관적으로 설명함 |
| Vector DB의 역할이 정확한가 | 통과 | 벡터 저장과 유사도 검색을 위한 저장소로 설명함 |
| Vector DB를 RDBMS 대체재로 오해하지 않도록 설명했는가 | 통과 | 관계형 DB, 문서 저장소, Vector DB의 역할 분리를 명확히 제시함 |
| RAG 개념이 명확한가 | 통과 | 검색된 문서를 근거로 LLM이 답변하는 흐름으로 설명함 |
| RAG의 한계가 포함되었는가 | 통과 | 검색 품질이 나쁘면 답변도 틀릴 수 있으며 근거성 검토가 필요하다고 설명함 |

## 3. 검색 방식 비교 점검

| 점검 항목 | 상태 | 리뷰 의견 |
| --- | --- | --- |
| SQL 검색의 장점이 설명되었는가 | 통과 | 이메일, 상태값, LIKE 조건 등 정형 조건 검색 예시 포함 |

| 키워드 검색과 의미 기반 검색의 차이가 표로 정리되었는가 | 통과 | 검색 방식, 찾는 기준, 예시로 구분함 |
| 입문 독자가 혼동하기 쉬운 부분을 보완했는가 | 통과 | Vector DB는 의미 기반 검색에 유용하지만 모든 검색을 대체하지 않는다는 관점 포함 |

## 6. RAG 답변 검토 기준 점검

| 점검 항목 | 상태 | 리뷰 의견 |
| --- | --- | --- |
| 검색 적합성 검토가 포함되었는가 | 통과 | 검색된 문서가 질문과 관련 있는지 확인하도록 제시함 |
