## 리뷰 목적

Chapter 08이 입문 독자가 정규화된 여러 테이블을 JOIN으로 연결하고, GROUP BY와 집계 함수로 분석 가능한 결과를 만드는 흐름을 충분히 설명하는지 점검합니다.

## 2. JOIN 설명 점검

| 점검 항목 | 상태 | 리뷰 의견 |
| --- | --- | --- |
| JOIN 필요성이 설명되었는가 | 통과 | 정규화로 나뉜 테이블을 다시 연결해야 하는 이유를 설명함 |
| INNER JOIN 설명이 정확한가 | 통과 | 양쪽 조건이 일치하는 행만 조회된다고 설명함 |
| LEFT JOIN 설명이 정확한가 | 통과 | 왼쪽 테이블의 모든 행을 유지하고 없는 값은 NULL로 표시된다고 설명함 |
| 여러 테이블 JOIN 경로가 명확한가 | 통과 | enrollments → students/courses → instructors 경로가 설명됨 |
| 테이블 별칭 사용이 포함되었는가 | 통과 | students=s, instructors=i, courses=c, enrollments=e 권장 별칭 포함 |
| JOIN 조건 누락 위험을 설명했는가 | 통과 | ON 조건 누락 시 결과 행이 비정상적으로 많아질 수 있음을 설명함 |

## 3. 집계 쿼리 설명 점검

| 점검 항목 | 상태 | 리뷰 의견 |
| --- | --- | --- |
| 주요 집계 함수가 포함되었는가 | 통과 | COUNT, SUM, AVG, MIN, MAX 포함 |
| GROUP BY 규칙을 설명했는가 | 통과 | SELECT의 일반 컬럼은 GROUP BY에 포함되어야 한다고 설명함 |
| 강의별 수강생 수 예제가 있는가 | 통과 | courses와 enrollments를 JOIN한 뒤 COUNT 사용 |
| 강의별 매출 예제가 있는가 | 통과 | SUM과 COALESCE 사용 예제 포함 |
| 강사별 강의 수 예제가 있는가 | 통과 | instructors와 courses를 LEFT JOIN하여 집계 |
| HAVING 설명이 정확한가 | 통과 | 집계 결과를 기준으로 필터링한다고 설명함 |
| WHERE와 HAVING 차이를 설명했는가 | 통과 | 실행 시점과 예시를 비교함 |
