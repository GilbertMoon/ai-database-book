# SVG 제작 공통 가이드

이 문서는 이 저장소의 모든 SVG 도식에 공통으로 적용하는 디자인 및 내용 기준을 정의합니다.

---

## 1. 기본 목적

SVG는 장식이 아니라 독자가 개념, 구조, 관계 또는 흐름을 빠르게 이해하도록 돕는 설명 도구로 사용합니다.

```text
- 하나의 SVG는 하나의 핵심 메시지를 전달한다.
- 본문만으로 이해하기 어려운 구조, 비교, 관계 또는 순서를 시각화한다.
- 본문 내용을 그대로 반복하지 않고 이해를 돕는 정보만 남긴다.
- 도식에 포함된 내용은 본문 설명과 정확히 일치해야 한다.
```

---

## 2. 내용 구성 원칙

### 2.1 같은 계층에는 같은 분류 기준을 사용한다

하나의 행이나 동일한 계층에 배치되는 항목은 같은 기준으로 분류해야 합니다.

```text
올바른 구성
- 저장 형태끼리 비교
- 데이터베이스 유형끼리 비교
- 제품 예시끼리 비교
- 활용 사례끼리 비교

피해야 할 구성
- 저장 형태, 제품명, 기술 유형, 활용 사례를 같은 계층에 혼합
```

분류 기준이 다른 정보는 다음처럼 계층을 분리합니다.

```text
상위 개념
→ 유형 또는 방식
→ 대표 기술·제품 예시
→ 활용 사례
```

### 2.2 범주와 예시를 구분한다

`관계형 데이터베이스`와 같은 범주, `PostgreSQL`과 같은 제품 예시, `주문 관리`와 같은 활용 사례를 서로 구분해 표현합니다.

색상, 행, 그룹 상자 또는 제목을 사용해 각 역할을 명확히 구분합니다.

### 2.3 관계를 명확하게 표현한다

독자가 각 항목이 어디에 속하고 무엇과 연결되는지 바로 알 수 있어야 합니다.

```text
- 부모와 자식 관계는 연결선으로 표시한다.
- 활용 사례가 어느 기술에 해당하는지 시각적으로 연결한다.
- 단순히 가까이 배치하는 것만으로 관계를 표현하지 않는다.
- 연결 방향은 한 도식 안에서 일관되게 유지한다.
```

### 2.4 정보량을 제한한다

하나의 SVG에 너무 많은 내용을 넣지 않습니다.

```text
- 핵심 개념만 남긴다.
- 긴 설명은 본문으로 이동한다.
- 상자 안 문장은 짧은 명사구 또는 짧은 문장으로 작성한다.
- 한 상자 안의 텍스트는 가능하면 1~2줄 이내로 제한한다.
- 항목 수가 많아지면 여러 개의 도식으로 분리한다.
```

### 2.5 의사결정 흐름은 논리적으로 완결되어야 한다

판단형·선택형 도식은 독자가 어떤 경로를 선택하더라도 결론에 자연스럽게 도달해야 합니다.

```text
- 중요한 판단 조건을 확인하기 전에 너무 일찍 결론을 내리지 않는다.
- 질문은 선행 조건, 핵심 조건, 보조 조건 순으로 배치한다.
- 예/아니오 또는 선택지의 의미가 서로 겹치지 않도록 한다.
- 가능한 모든 경로가 다음 질문이나 명확한 결과로 이어져야 한다.
- 같은 조건을 다른 위치에서 중복 질문하지 않는다.
- 결과를 결정하는 데 필요하지 않은 질문은 제거한다.
```

하나의 조건만으로 결과를 확정하기 어려운 경우에는 이후 핵심 조건을 계속 확인하도록 구성합니다.

### 2.6 대안과 추가 확장을 구분한다

서로 대체하는 선택지와 기본 선택 이후 추가로 적용하는 기능을 같은 단계에 놓지 않습니다.

```text
대안 관계
- A 또는 B 가운데 하나를 선택

순차·확장 관계
- A를 먼저 검토
- 조건이 충족되면 B를 추가 검토
```

순차 관계를 병렬 상자로 배치하여 둘 중 하나를 고르는 것처럼 보이게 하지 않습니다.

### 2.7 의미가 중복되는 단계는 합친다

연속된 노드가 사실상 같은 판단이나 결론을 반복한다면 하나의 단계로 통합합니다.

```text
- 같은 의미를 표현만 바꾸어 연속 배치하지 않는다.
- 중간 노드가 새로운 정보나 판단을 추가하지 않으면 제거한다.
- 결과 상자와 그 바로 다음 상자가 같은 결론을 반복하면 하나로 합친다.
- 단계 수를 늘리기보다 독자가 실제로 내려야 하는 판단만 남긴다.
```

## 3. 레이아웃 원칙

### 3.1 시각적 계층을 명확히 한다

독자가 위에서 아래 또는 왼쪽에서 오른쪽으로 자연스럽게 읽을 수 있도록 구성합니다.

권장 순서는 다음과 같습니다.

```text
제목
→ 핵심 개념 또는 시작점
→ 세부 유형·단계
→ 기술 예시 또는 결과
→ 활용 사례
→ 핵심 메시지
```

### 3.2 정렬과 간격을 통일한다

```text
- 같은 단계의 상자는 같은 높이와 크기를 우선 사용한다.
- 같은 행의 상자는 기준선에 맞춰 정렬한다.
- 상자 사이의 가로·세로 간격을 일정하게 유지한다.
- 좌우 여백과 상하 여백을 균형 있게 배치한다.
- 불필요하게 큰 빈 공간은 줄인다.
```

### 3.3 영역 간 시각적 균형을 맞춘다

분기별 단계 수가 다르더라도 전체 도식이 한쪽으로 지나치게 무겁거나 비어 보이지 않도록 조정합니다.

```text
- 좌우 또는 상하 영역의 폭, 여백과 정보 밀도를 함께 검토한다.
- 한쪽 분기만 지나치게 많은 상자와 긴 문장을 갖지 않도록 한다.
- 단계 수가 많은 분기는 그룹으로 묶거나 별도 도식으로 분리한다.
- 빈 공간을 채우기 위해 불필요한 내용을 추가하지 않는다.
- 중요한 결과가 주변 요소보다 지나치게 작게 보이지 않도록 한다.
```

### 3.4 겹침과 잘림을 허용하지 않는다

다음 요소는 서로 겹치거나 SVG 영역 밖으로 잘려서는 안 됩니다.

```text
- 상자와 상자
- 텍스트와 상자 테두리
- 텍스트와 연결선
- 연결선과 화살표
- 핵심 메시지와 하단 테두리
```

모든 텍스트에는 충분한 내부 여백을 확보합니다.

### 3.5 핵심 메시지 영역

도식 하단에 핵심 메시지를 둘 경우 다음 원칙을 따릅니다.

```text
- 본문에서 기억해야 할 결론만 작성한다.
- 긴 문장은 2줄 이하로 나눈다.
- 텍스트가 테두리에 닿지 않도록 충분한 내부 여백을 둔다.
- 메시지 상자 높이는 실제 줄 수에 맞게 확보한다.
- 마지막 줄의 기준선과 하단 테두리 사이에 충분한 여백을 둔다.
- 다른 요소보다 과도하게 크거나 강하게 강조하지 않는다.
```

### 3.6 노드의 역할을 시각적으로 구분한다

시작점, 질문, 중간 결과, 최종 결과와 선택 확장은 같은 모양으로 표현하지 않습니다.

```text
- 시작점: 흐름의 출발임을 알 수 있도록 강조
- 질문·판단: 중립적인 스타일 사용
- 중간 결과: 다음 단계로 이어지는 상태임을 표시
- 최종 결과: 도착점임을 명확히 강조
- 선택 확장: 기본 결과와 구분되는 보조 스타일 사용
```

색상뿐 아니라 제목, 위치, 상자 형태 또는 테두리 차이도 함께 사용합니다.

## 4. 연결선과 화살표 원칙

```text
- 연결선은 가능한 한 수직선과 수평선을 우선 사용한다.
- 여러 대각선이 교차하는 구조는 피한다.
- 선이 교차해야 한다면 배치를 먼저 다시 검토한다.
- 화살표 방향은 정보 흐름과 일치해야 한다.
- 같은 의미의 연결선은 동일한 굵기와 스타일을 사용한다.
- 연결선이 상자나 텍스트를 통과하지 않도록 한다.
- 시작점과 도착점이 어느 상자인지 명확하게 보이도록 연결한다.
```

복잡한 다중 분기 구조에서는 공통 중심점, 그룹 상자 또는 세로 열 구조를 사용해 선의 교차를 줄입니다.

### 4.1 분기 라벨을 일관되게 배치한다

```text
- 예/아니오, 성공/실패와 같은 분기 라벨을 모든 판단선에 표시한다.
- 같은 의미의 라벨은 도식 전체에서 같은 방향과 위치를 우선 사용한다.
- 라벨이 어느 선에 속하는지 모호하지 않도록 선 가까이에 배치한다.
- 라벨이 상자, 화살표 또는 다른 연결선과 겹치지 않도록 한다.
```

### 4.2 같은 결과로 이어지는 선은 합류시킨다

여러 조건이 동일한 결과로 이어질 때는 각 선을 길게 우회시키지 않습니다.

```text
- 공통 합류선 또는 중간 합류점을 사용한다.
- 같은 결과 상자로 연결되는 긴 평행선을 반복하지 않는다.
- 합류선 때문에 흐름의 방향이 역전되거나 혼동되지 않도록 한다.
- 합류 구조가 더 복잡해지면 질문 수나 배치를 다시 단순화한다.
```

### 4.3 연결선은 실제 노드 경계에 정확히 닿아야 한다

연결선이나 화살표가 빈 공간에서 시작하거나 끝나면 흐름이 끊어진 것으로 보입니다.

```text
- 시작선은 출발 노드의 경계에서 시작한다.
- 화살표 끝은 도착 노드의 경계에 정확히 닿도록 한다.
- 상자의 중심 좌표와 연결선 좌표를 함께 검토한다.
- 노드를 이동하거나 크기를 바꾼 뒤 연결선 좌표도 반드시 다시 확인한다.
- 연결선이 상자 앞에서 멈추거나 상자를 지나쳐 들어가지 않도록 한다.
```

### 4.4 분기는 공통 분기점에서 시작한다

하나의 질문에서 여러 결과로 갈라질 때는 분기 구조가 명확하게 보여야 합니다.

```text
- 가능하면 질문 노드의 한 지점에서 공통 분기선으로 나눈다.
- 각 화살표가 임의의 서로 다른 지점에서 시작하지 않도록 한다.
- 분기 라벨은 공통 분기점 이후 각 선에 배치한다.
- 분기점과 각 결과 상자 사이의 간격을 균형 있게 유지한다.
```

## 5. 텍스트 가독성 원칙

```text
- 전자책 화면에서 축소되어도 읽을 수 있는 크기를 사용한다.
- 제목, 상위 분류, 세부 항목, 보조 설명의 글자 크기에 차이를 둔다.
- 제목은 가장 크게, 보조 설명은 가장 작게 작성한다.
- 지나치게 작은 글자로 많은 정보를 넣지 않는다.
- 한글과 영문이 함께 사용될 때 글꼴 크기와 정렬을 일관되게 유지한다.
- 전문 용어, 제품명과 약어의 표기를 본문과 일치시킨다.
```

권장 글꼴 계열은 다음 순서를 기본으로 사용합니다.

```css
font-family: "Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", Arial, sans-serif;
```

## 6. 색상 사용 원칙

색상은 장식이 아니라 정보의 역할을 구분하기 위해 사용합니다.

```text
- 같은 역할의 요소에는 같은 색상을 사용한다.
- 범주, 예시, 활용 사례 등 서로 다른 역할을 색상으로 구분할 수 있다.
- 한 SVG 안에서 사용하는 주요 색상 수를 최소화한다.
- 배경과 텍스트의 명도 대비를 충분히 확보한다.
- 색상만으로 의미를 전달하지 않고 위치, 제목 또는 테두리를 함께 사용한다.
- 서로 다른 SVG에서도 같은 의미의 색상은 가능한 한 동일하게 유지한다.
```

기본 배경은 흰색을 사용합니다.

## 7. 상자와 그룹 표현 원칙

```text
- 같은 역할의 상자는 동일한 모양과 테두리 스타일을 사용한다.
- 상자 크기는 텍스트 길이를 고려하되 같은 계층에서는 가능한 한 통일한다.
- 둥근 모서리, 선 굵기와 내부 여백을 일관되게 유지한다.
- 여러 항목이 하나의 그룹에 속하면 그룹 배경이나 그룹 제목을 사용한다.
- 가까이 배치했다는 이유만으로 같은 그룹이라고 가정하지 않는다.
```

### 7.1 상자 크기는 가장 긴 텍스트를 기준으로 정한다

텍스트를 억지로 작은 상자에 넣기 위해 글자 크기를 줄이지 않습니다.

```text
- 상자 폭은 내부의 가장 긴 제목이나 문장을 기준으로 확보한다.
- 좌우와 상하 내부 여백을 일정하게 유지한다.
- 긴 제품명이나 기술명은 충분한 폭을 확보하거나 자연스럽게 줄을 나눈다.
- 같은 행의 상자는 필요한 최소 폭을 만족한 뒤 가능한 한 크기를 맞춘다.
- 텍스트가 테두리에 가까우면 상자를 넓히고, 글자 크기 축소는 마지막 수단으로 사용한다.
```

## 8. SVG 화면 영역 원칙

```text
- width, height와 viewBox의 비율을 일치시킨다.
- 모든 요소가 viewBox 안에 포함되어야 한다.
- 외곽 요소가 테두리에 지나치게 가까이 붙지 않도록 여백을 둔다.
- 불필요하게 넓거나 높은 viewBox를 사용하지 않는다.
- 브라우저, GitHub 미리보기와 전자책 변환 결과에서 잘림이 없는지 확인한다.
```

### 8.1 전자책에 적합한 종횡비를 사용한다

```text
- 기본적으로 가로형 또는 지나치게 길지 않은 세로형 구성을 우선한다.
- 긴 세로 흐름은 전자책에서 축소될 때 글자가 작아질 수 있음을 고려한다.
- 세로 단계가 많으면 2열, 지그재그가 아닌 그룹형 가로 배치 또는 여러 도식으로 분리한다.
- 한 화면에서 전체 구조와 글자를 동시에 파악할 수 있는 크기를 목표로 한다.
```

세로형 구성이 내용상 반드시 필요한 경우에는 글자 크기를 줄이는 대신 도식을 나누는 방식을 우선 검토합니다.

## 9. 본문과의 일치 원칙

```text
- SVG 제목은 본문의 그림 캡션과 의미가 일치해야 한다.
- 그림 번호와 파일 경로가 본문 참조와 일치해야 한다.
- 본문에서 설명하지 않는 기술이나 제품을 도식에 임의로 추가하지 않는다.
- 본문에서 변경된 용어는 SVG 내부 텍스트에도 반영한다.
- 강의, 시험, 제출, 평가와 같은 운영 표현은 일반 독자용 본문 목적에 맞게 제거하거나 바꾼다.
```

## 10. 최종 점검 체크리스트

SVG를 완료하기 전에 다음 항목을 확인합니다.

```text
[ ] 하나의 핵심 메시지가 분명한가?
[ ] 같은 계층에 같은 분류 기준을 사용했는가?
[ ] 범주, 제품 예시와 활용 사례가 구분되는가?
[ ] 각 항목의 연결 관계가 명확한가?
[ ] 의사결정 흐름이 너무 일찍 결론을 내리지 않는가?
[ ] 모든 분기 경로가 다음 질문 또는 명확한 결과로 이어지는가?
[ ] 의미가 중복되는 연속 단계가 없는가?
[ ] 대안 선택과 순차·추가 확장이 구분되는가?
[ ] 예/아니오 등 분기 라벨의 방향과 위치가 일관되는가?
[ ] 분기가 공통 분기점에서 명확하게 갈라지는가?
[ ] 같은 결과로 이어지는 연결선이 불필요하게 반복되지 않는가?
[ ] 모든 연결선이 출발·도착 노드의 경계에 정확히 닿는가?
[ ] 연결선과 화살표가 불필요하게 교차하지 않는가?
[ ] 시작점, 질문, 중간 결과와 최종 결과가 시각적으로 구분되는가?
[ ] 좌우·상하 영역의 정보 밀도와 여백이 균형적인가?
[ ] 상자 폭과 높이가 내부 텍스트에 충분한가?
[ ] 상자, 텍스트와 연결선이 겹치지 않는가?
[ ] 모든 텍스트가 상자와 viewBox 안에서 잘리지 않는가?
[ ] 축소된 전자책 화면에서도 읽을 수 있는가?
[ ] 도식의 종횡비가 전자책 화면에 적합한가?
[ ] 색상이 정보 역할에 맞게 일관되게 사용되었는가?
[ ] 불필요한 빈 공간이나 과도한 정보가 없는가?
[ ] 핵심 메시지의 마지막 줄과 하단 테두리 사이 여백이 충분한가?
[ ] SVG 내용이 본문과 캡션에 정확히 일치하는가?
[ ] 브라우저와 GitHub 미리보기에서 정상 표시되는가?
```
