# SVG 제작 공통 가이드

이 문서는 이 저장소의 모든 SVG 도식에 공통으로 적용하는 디자인 및 내용 기준을 정의합니다.

---

## 1. 기본 목적

SVG는 장식이 아니라 독자가 개념, 구조, 관계 또는 흐름을 빠르게 이해하도록 돕는 설명 도구로 사용합니다.

```text
- 하나의 SVG는 하나의 핵심 메시지를 전달한다.
- 본문만으로 이해하기 어려운 구조, 비교, 관계 또는 순서를 시각화한다.
- 본문 내용을 그대로 반복하지 않고 이해에 필요한 정보만 남긴다.
- 도식의 내용, 용어와 결론은 본문 설명과 정확히 일치해야 한다.
```

---

## 2. 내용 구성 원칙

### 2.1 같은 계층에는 같은 분류 기준을 사용한다

```text
올바른 구성
- 저장 형태끼리 비교
- 데이터베이스 유형끼리 비교
- 제품 예시끼리 비교
- 활용 사례끼리 비교

피해야 할 구성
- 저장 형태, 제품명, 기술 유형과 활용 사례를 같은 계층에 혼합
```

분류 기준이 다른 정보는 다음처럼 계층을 분리합니다.

```text
상위 개념
→ 유형 또는 방식
→ 대표 기술·제품 예시
→ 활용 사례
```

### 2.2 범주와 예시를 구분한다

범주, 제품·도구 예시와 활용 사례를 색상, 행, 그룹 상자 또는 제목으로 명확히 구분합니다.

### 2.3 관계를 명확하게 표현한다

```text
- 부모와 자식 관계는 연결선으로 표시한다.
- 활용 사례가 어느 범주나 기술에 속하는지 명확히 연결한다.
- 단순히 가까이 배치하는 것만으로 관계를 표현하지 않는다.
- 연결 방향은 하나의 도식 안에서 일관되게 유지한다.
```

### 2.4 정보량을 제한한다

```text
- 핵심 개념만 남긴다.
- 긴 설명은 본문으로 이동한다.
- 상자 안 문장은 짧은 명사구 또는 짧은 문장으로 작성한다.
- 한 상자 안의 텍스트는 가능하면 1~2줄 이내로 제한한다.
- 항목 수가 많아지면 여러 도식으로 분리한다.
```

### 2.5 의사결정 흐름은 논리적으로 완결되어야 한다

```text
- 중요한 판단 조건을 확인하기 전에 너무 일찍 결론을 내리지 않는다.
- 질문은 선행 조건, 핵심 조건, 보조 조건 순으로 배치한다.
- 예/아니오 또는 선택지의 의미가 서로 겹치지 않도록 한다.
- 가능한 모든 경로가 다음 질문이나 명확한 결과로 이어져야 한다.
- 같은 조건을 다른 위치에서 중복 질문하지 않는다.
- 결과 결정에 필요하지 않은 질문은 제거한다.
```

### 2.6 대안과 추가 확장을 구분한다

서로 대체하는 선택지와 기본 선택 이후 추가하는 기능을 같은 단계에 놓지 않습니다.

```text
대안 관계: A 또는 B 가운데 하나를 선택
순차·확장 관계: A를 먼저 적용하고 조건이 충족되면 B를 추가
```

### 2.7 의미가 중복되는 단계는 합친다

```text
- 같은 의미를 표현만 바꾸어 연속 배치하지 않는다.
- 중간 노드가 새로운 정보나 판단을 추가하지 않으면 제거한다.
- 결과 상자와 바로 다음 상자가 같은 결론을 반복하면 하나로 합친다.
- 단계 수보다 독자가 실제 수행하거나 판단해야 하는 내용을 우선한다.
```

### 2.8 작업 단계와 도구 이름을 구분한다

작업 흐름 도식의 중심은 도구가 아니라 사용자가 수행하는 행동과 결과입니다.

```text
권장
- 핵심 규칙 정리 — ChatGPT 보조
- DDL·SQL 초안 생성 — Codex 보조
- SQL 실행과 결과 확인 — PostgreSQL·DBeaver 사용

피해야 할 구성
- ChatGPT → Codex → PostgreSQL → DBeaver처럼 도구 이름만 나열
- 하나의 작업을 DBMS와 클라이언트 도구 이름 때문에 불필요하게 두 단계로 분리
```

도구 이름은 배지, 부제 또는 보조 설명으로 표시합니다. 단, 도구 자체를 비교하거나 설명하는 도식에서는 도구명을 주요 노드로 사용할 수 있습니다.

### 2.9 반복·피드백 흐름은 수정과 재검증 경로를 표시한다

```text
- 문제 발견 조건과 완료 조건을 분리한다.
- 문제가 있으면 무엇을 수정하는지 명시한다.
- 수정 후 어느 단계로 돌아가는지 화살표로 표시한다.
- 되돌아가는 단계는 문제 원인과 논리적으로 연결되어야 한다.
- 수정 후 반드시 실행과 검증 단계를 다시 거치도록 표현한다.
- 문제가 없을 때 도달하는 최종 결과 또는 기록 단계를 명확히 표시한다.
```

### 2.10 같은 장의 여러 도식은 서로 보완한다

```text
- 같은 장 안의 여러 도식이 거의 같은 흐름을 반복하지 않도록 한다.
- 전체 흐름 도식과 세부 검증 도식은 역할을 분리한다.
- 같은 개념을 다시 다룰 때는 관점, 범위 또는 질문을 명확히 달리한다.
- 본문 순서, 그림 번호, 대체 텍스트와 도식 제목이 서로 맞아야 한다.
```

### 2.11 데이터 관계 도식은 작업 순서와 구분한다

```text
- 엔터티 관계는 작업 흐름 화살표처럼 표현하지 않는다.
- 관계선 양쪽에는 1, N, 0..1 같은 카디널리티를 표시한다.
- 관계선은 실제 엔터티 상자 경계에 닿아야 한다.
- PK와 FK는 색상, 굵기 또는 라벨로 시각적으로 구분한다.
- 관계 라벨은 선이나 필드 텍스트를 가리지 않는 위치에 둔다.
```

### 2.12 매트릭스는 축과 선택 기준을 분리한다

```text
- 축의 최소값, 최대값과 증가 방향을 명확히 표시한다.
- 사분면 제목과 사례 점, 사례 라벨이 겹치지 않도록 배치한다.
- 사분면의 모든 선택지는 같은 분류 기준을 사용한다.
- 두 축만으로 설명하기 어려운 특수 목적 기술은 보조 영역으로 분리한다.
- 기본 선택과 선택 이후 추가 검토 대상을 혼합하지 않는다.
```

## 3. 레이아웃 원칙

### 3.1 시각적 계층을 명확히 한다

독자가 위에서 아래 또는 왼쪽에서 오른쪽으로 자연스럽게 읽도록 구성합니다.

```text
제목
→ 시작점 또는 핵심 개념
→ 세부 단계·유형
→ 판단 또는 결과
→ 핵심 메시지
```

### 3.2 정렬과 간격을 통일한다

```text
- 같은 단계의 상자는 같은 높이와 크기를 우선 사용한다.
- 같은 행의 상자는 기준선에 맞춰 정렬한다.
- 상자 사이의 가로·세로 간격을 일정하게 유지한다.
- 좌우 여백과 상하 여백을 균형 있게 배치한다.
- 불필요하게 큰 빈 공간은 줄인다.
```

### 3.3 영역 간 시각적 균형을 맞춘다

```text
- 좌우 또는 상하 영역의 폭, 여백과 정보 밀도를 함께 검토한다.
- 한쪽 분기만 지나치게 많은 상자와 긴 문장을 갖지 않도록 한다.
- 단계가 많은 분기는 그룹으로 묶거나 별도 도식으로 분리한다.
- 빈 공간을 채우기 위해 불필요한 내용을 추가하지 않는다.
- 중요한 결과가 주변 요소보다 지나치게 작게 보이지 않도록 한다.
```

### 3.4 겹침과 잘림을 허용하지 않는다

```text
- 상자와 상자
- 텍스트와 상자 테두리
- 텍스트와 연결선
- 연결선과 화살표
- 핵심 메시지와 외곽 테두리
```

모든 텍스트에 충분한 내부 여백을 확보합니다.

### 3.5 노드의 역할을 시각적으로 구분한다

```text
- 시작점: 흐름의 출발임을 알 수 있도록 강조
- 작업 단계: 일관된 중립 스타일 사용
- AI 보조 단계: 작업 노드 형태를 유지하면서 보조 색상이나 배지 사용
- 질문·판단: 중립 또는 판단 전용 스타일 사용
- 수정 단계: 주의·재작업 색상 사용
- 최종 결과: 도착점임을 명확히 강조
```

색상뿐 아니라 제목, 위치, 상자 형태와 테두리 차이도 함께 사용합니다.

### 3.6 핵심 메시지 영역

```text
- 본문에서 기억해야 할 결론만 작성한다.
- 긴 문장은 2줄 이하로 나눈다.
- 텍스트가 테두리에 닿지 않도록 충분한 내부 여백을 둔다.
- 메시지 상자 높이는 실제 줄 수에 맞게 확보한다.
- 마지막 줄의 기준선과 하단 테두리 사이에 충분한 여백을 둔다.
- 다른 요소보다 과도하게 크거나 강하게 강조하지 않는다.
```

## 4. 연결선과 화살표 원칙

```text
- 연결선은 가능한 한 수직선과 수평선을 우선 사용한다.
- 여러 대각선이 교차하는 구조는 피한다.
- 화살표 방향은 정보 흐름과 일치해야 한다.
- 같은 의미의 연결선은 동일한 굵기와 스타일을 사용한다.
- 연결선이 상자나 텍스트를 통과하지 않도록 한다.
```

### 4.1 분기 라벨을 일관되게 배치한다

```text
- 예/아니오, 성공/실패와 같은 라벨을 모든 판단선에 표시한다.
- 같은 의미의 라벨은 같은 방향과 위치를 우선 사용한다.
- 라벨이 어느 선에 속하는지 모호하지 않게 선 가까이에 배치한다.
- 라벨이 상자, 화살표 또는 다른 연결선과 겹치지 않도록 한다.
```

### 4.2 같은 결과로 이어지는 선은 합류시킨다

```text
- 공통 합류선 또는 중간 합류점을 사용한다.
- 같은 결과로 가는 긴 평행선을 반복하지 않는다.
- 합류 구조 때문에 흐름 방향이 역전되거나 혼동되지 않도록 한다.
```

### 4.3 연결선은 실제 노드 경계에 정확히 닿아야 한다

```text
- 시작선은 출발 노드의 경계에서 시작한다.
- 화살표 끝은 도착 노드의 경계에 정확히 닿도록 한다.
- 노드를 이동하거나 크기를 바꾼 뒤 연결선 좌표를 다시 확인한다.
- 선이 상자 앞에서 멈추거나 상자를 지나쳐 들어가지 않도록 한다.
```

### 4.4 분기는 공통 분기점에서 시작한다

```text
- 질문 노드의 한 지점에서 공통 분기선으로 나눈다.
- 각 화살표가 임의의 서로 다른 지점에서 시작하지 않도록 한다.
- 분기 라벨은 공통 분기점 이후 각 선에 배치한다.
- 분기점과 결과 상자 사이의 간격을 균형 있게 유지한다.
```

### 4.5 피드백 루프는 주 흐름과 구분한다

```text
- 정상 진행 흐름은 짧고 직접적인 선으로 표시한다.
- 수정·재검증 선은 외곽을 이용해 주 흐름과 겹치지 않게 한다.
- 되돌아가는 선에는 재검증, 수정 후 반복 등 의미를 표시한다.
- 반복선이 여러 단계를 가로지르면 어느 단계로 돌아가는지 명확히 한다.
```

## 5. 텍스트 가독성 원칙

```text
- 전자책 화면에서 축소되어도 읽을 수 있는 크기를 사용한다.
- 제목, 단계명, 보조 설명의 글자 크기에 차이를 둔다.
- 지나치게 작은 글자로 많은 정보를 넣지 않는다.
- 한글과 영문이 함께 사용될 때 글꼴 크기와 정렬을 일관되게 유지한다.
- 전문 용어, 제품명과 약어의 표기를 본문과 일치시킨다.
```

```css
font-family: "Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", Arial, sans-serif;
```

## 6. 색상 사용 원칙

```text
- 색상은 장식이 아니라 정보의 역할을 구분하기 위해 사용한다.
- 같은 역할의 요소에는 같은 색상을 사용한다.
- 한 SVG 안에서 사용하는 주요 색상 수를 최소화한다.
- 배경과 텍스트의 명도 대비를 충분히 확보한다.
- 색상만으로 의미를 전달하지 않고 제목, 위치 또는 테두리를 함께 사용한다.
- 서로 다른 SVG에서도 같은 의미의 색상은 가능한 한 동일하게 유지한다.
```

기본 배경은 흰색을 사용합니다.

---

## 7. 상자와 그룹 표현 원칙

```text
- 같은 역할의 상자는 동일한 모양과 테두리 스타일을 사용한다.
- 상자 크기는 가장 긴 텍스트를 기준으로 확보한다.
- 글자 크기를 줄이기 전에 상자 폭과 높이를 먼저 조정한다.
- 둥근 모서리, 선 굵기와 내부 여백을 일관되게 유지한다.
- 여러 항목이 하나의 그룹에 속하면 그룹 배경이나 제목을 사용한다.
- 배지는 도구, 상태 또는 보조 정보를 짧게 표시할 때만 사용한다.
```

## 8. SVG 화면 영역과 접근성 원칙

```text
- width, height와 viewBox의 비율을 일치시킨다.
- 모든 요소가 viewBox 안에 포함되어야 한다.
- 외곽 요소가 테두리에 지나치게 가까이 붙지 않도록 여백을 둔다.
- 불필요하게 넓거나 높은 viewBox를 사용하지 않는다.
- 기본적으로 가로형 또는 지나치게 길지 않은 세로형 구성을 우선한다.
- 브라우저, GitHub 미리보기와 전자책 변환 결과에서 잘림을 확인한다.
- 의미 있는 SVG에는 role, title과 desc를 제공한다.
```

한 화면에서 전체 구조와 글자를 동시에 파악할 수 있는 크기를 목표로 합니다.

### 8.1 실제 렌더링으로 최종 확인한다

```text
- SVG 코드만 보고 완료로 판단하지 않는다.
- PNG 또는 브라우저 렌더링 결과를 실제로 확인한다.
- 한글 글꼴 렌더링 후의 실제 텍스트 폭을 기준으로 상자 크기를 조정한다.
- 100% 화면뿐 아니라 전자책에서 축소될 상황도 함께 고려한다.
- 검토용 PNG, 캐시, 빌드 산출물은 저장소에 커밋하지 않는다.
```

## 9. SVG와 원본 파일 동기화 원칙

Mermaid 원본이 존재하는 경우 SVG와 함께 관리합니다.

```text
- SVG를 수정하면 같은 이름의 .mmd 원본도 동일한 논리로 수정한다.
- 파일명, 제목, 단계명과 분기 라벨을 원본과 결과물에서 일치시킨다.
- 원본으로 다시 렌더링했을 때 이전 내용으로 되돌아가지 않도록 한다.
- 직접 작성한 SVG의 세부 스타일은 SVG에 유지하되 흐름 논리는 원본에도 반영한다.
```

## 10. 본문과의 일치 원칙

```text
- SVG 제목은 본문의 그림 캡션과 의미가 일치해야 한다.
- 그림 번호와 파일 경로가 본문 참조와 일치해야 한다.
- 본문에서 설명하지 않는 기술이나 제품을 임의로 추가하지 않는다.
- 본문에서 변경된 용어는 SVG 내부 텍스트와 이미지 README에도 반영한다.
- 강의, 시험, 제출, 평가와 같은 운영 표현은 일반 독자용 목적에 맞게 바꾼다.
```
