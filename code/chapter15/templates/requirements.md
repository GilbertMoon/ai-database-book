# 요구사항 정의서

## 확정 요구사항

| ID | 요구사항 | DB 반영 | 검증 방법 |
|---|---|---|---|
| REQ-01 | 학생은 질문을 등록할 수 있다 | `questions.student_id` FK | JOIN |
| REQ-02 | 학생 이메일은 중복될 수 없다 | `students.email` UNIQUE | 중복 INSERT |
| REQ-03 | 튜터 이메일은 중복될 수 없다 | `tutors.email` UNIQUE | 중복 INSERT |
| REQ-04 | 질문 상태는 허용 값만 사용한다 | `questions.status` CHECK | 잘못된 상태 INSERT |
| REQ-05 | 질문에는 여러 답변이 가능하다 | `questions` 1:N `answers` | 답변 집계 |
| REQ-06 | 답변은 튜터와 연결된다 | `answers.tutor_id` FK | JOIN/FK 확인 |
| REQ-07 | 질문과 학습 자료는 N:M이다 | `question_materials` | 관계 조회 |
| REQ-08 | 질문이 없는 학생도 조회할 수 있다 | LEFT JOIN | 0건 집계 |
| REQ-09 | 연결되지 않은 자료를 찾을 수 있다 | LEFT JOIN | 누락 조회 |
| REQ-10 | 실제 개인정보를 사용하지 않는다 | 가상 seed 데이터 | 샘플 검토 |

## 아직 결정하지 않은 업무 규칙

| 질문 | 상태 | 처리 |
|---|---|---|
| 같은 튜터가 한 질문에 여러 답변을 작성할 수 있는가? | 미확정 | UNIQUE 제약 추가 금지 |
| 답변 등록 시 질문 상태를 자동으로 `answered`로 바꾸는가? | 정책 필요 | 애플리케이션 또는 트리거 검토 |
| `closed` 질문에도 답변을 허용하는가? | 미확정 | 애플리케이션 규칙 검토 |
| 학생 삭제 시 질문을 함께 삭제하는가? | 미확정 | CASCADE 사용 금지 |
| 자료 연결 순서 중복을 허용하는가? | 미확정 | 요구사항 확인 |
| 질문·답변 보관 기간은 얼마인가? | 정책 필요 | 임의 삭제 금지 |

## 이번 예제에서 사용하는 단순화 가정

- 질문 상태는 `open`, `answered`, `closed`만 사용합니다.
- 이메일 중복은 허용하지 않습니다.
- 한 질문에 여러 답변이 가능합니다.
- 질문과 학습 자료는 연결 테이블로 관리합니다.
- 삭제 정책은 명시하지 않았으므로 `ON DELETE CASCADE`를 사용하지 않습니다.
- 실제 개인정보가 아닌 가상 데이터를 사용합니다.

## 선택 확장 검토

| 확장 | 현재 버전 포함 여부 | 판단 기준 |
|---|---|---|
| 웹 CRUD/API | 제외 | 화면 입력과 조회 검증이 필요할 때 |
| NoSQL | 제외 | 캐시, 문서, 이벤트 저장 특성이 필요할 때 |
| Vector DB/RAG | 제외 | 학습 자료 의미 검색과 근거 기반 답변이 필요할 때 |
| 클라우드 배포 | 제외 | 공유와 운영 검증이 필요할 때 |
