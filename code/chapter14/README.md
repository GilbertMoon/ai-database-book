# Chapter 14 실습 코드

## Vector DB와 RAG 기초

이 폴더는 Chapter 14의 Vector DB와 RAG 기초 실습 파일을 관리합니다.

핵심은 임베딩, 벡터, 유사도 검색, 문서 청킹, 검색 로그, RAG 답변 검토 흐름을 입문 독자가 직접 확인하는 것입니다.

## 실행 전 주의 사항

```text
- 이 파일은 실습용 예제입니다.
- 운영 데이터베이스에서 실행하지 않습니다.
- 실제 개인정보나 민감 문서를 사용하지 않습니다.
- pgvector가 설치되어 있으면 Section A를 참고할 수 있습니다.
- pgvector가 없어도 Section B의 3차원 벡터 실습은 실행할 수 있습니다.
```

---

## 권장 실행 환경

```text
- PostgreSQL
- DBeaver Community Edition
- ai_database_book 실습 데이터베이스
```

pgvector 실습을 진행하려면 PostgreSQL에 `vector` 확장이 설치되어 있어야 합니다.

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

확장이 없는 환경에서는 `embedding_x`, `embedding_y`, `embedding_z` 컬럼으로 벡터 개념을 대체 실습합니다.

---

## 주요 실습 항목

```text
- 문서 청크 테이블 생성
- 3차원 샘플 임베딩 벡터 저장
- 질문 벡터와 문서 벡터 간 거리 계산
- Top-k 유사 문서 검색
- 검색 로그 저장
- 검색 결과와 원문 문서 연결
- RAG 답변 검토 테이블 생성
- 답변이 검색 문서에 근거했는지 점검
- 검색 문서에 없는 내용을 답변에 추가했는지 확인
```

---

## 실습 진행 팁

입문 독자는 다음 순서로 진행하는 것을 권장합니다.

```text
1. 임베딩과 벡터를 3차원 좌표로 단순화해 설명한다.
2. simple_document_chunks 테이블의 문서 조각을 확인한다.
3. 질문 벡터를 바꿔 가며 검색 결과가 달라지는 것을 확인한다.
4. distance 값이 작을수록 더 유사한 문서라는 점을 설명한다.
5. RAG 검색 로그가 왜 필요한지 설명한다.
6. generated_answer와 evidence_chunk_id를 비교하며 근거성 검토를 진행한다.
7. 검색 문서에 없는 내용을 답변에 추가하는 환각 사례를 확인한다.
```

---

## 핵심 포인트

```text
Vector DB는 일반 데이터베이스의 대체재가 아니라 의미 기반 검색을 위한 보완적 저장소입니다.
RAG는 LLM이 바로 답하는 방식이 아니라 관련 문서를 검색한 뒤 그 문서를 근거로 답변하는 방식입니다.
RAG 품질은 문서 청킹, 임베딩, 검색 결과, 프롬프트, 답변 검토 전체 흐름에 의해 결정됩니다.
검색된 문서가 부정확하면 LLM 답변도 부정확해질 수 있습니다.
답변이 검색 문서에 없는 내용을 추가했는지 반드시 검토해야 합니다.
```
