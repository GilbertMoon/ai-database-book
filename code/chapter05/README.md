# Chapter 05 실습 코드

## 요구사항에서 데이터 모델과 ERD 만들기

이 폴더는 도서 대여 시스템의 데이터 모델을 PostgreSQL 구조와 작은 샘플 데이터로 확인하는 SQL 파일을 관리합니다.

---

## 파일 목록

| 파일 | 설명 |
| --- | --- |
| `library_schema.sql` | `public.members`, `public.books`, `public.loans` 테이블 생성 |
| `library_seed.sql` | 재현 가능한 명시적 ID 샘플 데이터 입력과 IDENTITY 다음 값 조정 |
| `library_validation.sql` | 행 수, NULL, 1:N 관계와 도서 대여 시간 순서 확인 |
| `reset_library.sql` | 현재 DB·스키마를 검증한 뒤 자식→부모 순서로 테이블 삭제 |

---

## 기본 실행 순서

1. DBeaver에서 `ai_database_book` 데이터베이스에 연결합니다.
2. 다음 SQL로 현재 위치를 확인합니다.

```sql
SELECT current_database();
SELECT current_schema();
SHOW search_path;
```

3. 자동 커밋 상태를 확인합니다.
4. `library_schema.sql`을 실행합니다.
5. `library_seed.sql`을 실행합니다.
6. `library_validation.sql`을 실행합니다.
7. 각 결과가 요구사항, 범위 가정과 ERD에 맞는지 확인합니다.

```text
library_schema.sql
→ library_seed.sql
→ library_validation.sql
```

자동 커밋 상태에서는 앞 테이블이나 일부 데이터만 반영된 뒤 뒤 문장에서 오류가 날 수 있습니다. 실행 후 반드시 `library_validation.sql`의 행 수와 관계 결과를 확인합니다.

JOIN 문법과 다양한 결합 방식은 Chapter 08에서 자세히 다룹니다. Chapter 05에서는 ERD 관계가 실제 데이터로 연결되는지만 확인합니다.

외래키 오류, 날짜 선후 관계, 동시 대여 방지와 고유성 제약조건 검증은 Chapter 06에서 진행합니다.

---

## 현재 범위와 미확정 정책

Chapter 05는 다음 범위를 사용합니다.

```text
books 한 행을 하나의 대여 대상 도서로 취급한다.
동일 ISBN의 실제 복본은 아직 분리하지 않는다.
샘플 데이터에서는 같은 한 권이 동시에 두 미반납 대여에 속하지 않는다.
```

다음 정책은 요구사항에서 확정되지 않았습니다.

```text
회원 이메일의 시스템 내 고유성
이메일 대소문자 처리
ISBN의 시스템 내 고유성
ISBN이 없는 도서 허용 여부
동일 ISBN 복본 관리
최대 대여 권수와 연체 정책
날짜 선후 관계와 동시 활성 대여 차단
```

따라서 Chapter 05의 `members.email`, `books.isbn`에는 아직 `UNIQUE`를 적용하지 않습니다. Chapter 06에서 요구사항을 확정한 뒤 제약조건 후보를 검토합니다.

---

## 테이블과 관계

```text
public.members 1 ─── 0..N public.loans
public.books   1 ─── 0..N public.loans
```

```text
public.loans.member_id → public.members.id
public.loans.book_id   → public.books.id
```

`loans`는 단순 연결 테이블이 아니라 대여일, 반납예정일과 실제반납일을 저장하는 사건·업무 테이블입니다.

---

## 샘플 ID와 IDENTITY

관계를 명확하게 재현하기 위해 실습용 ID를 명시합니다.

```text
members: 101, 102, 103
books: 201, 202, 203
loans: 1001, 1002, 1003, 1004
```

`GENERATED BY DEFAULT AS IDENTITY`는 명시적 ID 입력을 허용하지만, 명시한 값이 연결된 IDENTITY의 다음 값을 자동으로 바꾸지는 않습니다. 따라서 `library_seed.sql` 마지막에서 다음 시작값으로 조정합니다.

```text
members 다음 ID: 104
books 다음 ID: 204
loans 다음 ID: 1005
```

---

## 샘플 대여 상태

| 대여 ID | 회원 | 도서 | 대여일 | 실제반납일 | 상태 |
| ---: | ---: | ---: | --- | --- | --- |
| 1001 | 101 | 201 | 2026-04-01 | 2026-04-02 | 반납 완료 |
| 1002 | 101 | 202 | 2026-04-02 | NULL | 미반납 |
| 1003 | 102 | 201 | 2026-04-03 | NULL | 미반납 |
| 1004 | 103 | 203 | 2026-04-05 | NULL | 미반납 |

도서 201은 첫 대여가 반납된 다음 날 다시 대여됩니다. 같은 한 권이 동시에 두 회원에게 미반납 상태로 남지 않습니다.

---

## 초기화가 필요한 경우

`library_schema.sql`과 `library_seed.sql`에는 자동 `DROP TABLE`이 없습니다.

처음부터 다시 시작해야 할 때만 다음 파일을 사용합니다.

```text
reset_library.sql
```

이 파일은 하나의 보호 구문 안에서 다음을 확인합니다.

```text
current_database = ai_database_book
current_schema   = public
→ 조건이 맞을 때만 public.loans, public.books, public.members 삭제
```

외래키 관계 때문에 자식 테이블인 `public.loans`를 먼저 삭제합니다.

---

## 주의 사항

```text
- 파일 전체를 무조건 반복 실행하지 않습니다.
- 현재 데이터베이스·스키마·search_path를 확인합니다.
- 자동 커밋 상태와 일부 문장만 반영될 가능성을 확인합니다.
- 같은 seed 파일을 다시 실행하면 PK 중복 오류가 발생할 수 있습니다.
- 실제 서비스 데이터베이스에서는 DROP TABLE을 함부로 실행하지 않습니다.
- 비밀번호나 접속 URL을 SQL 파일에 기록하지 않습니다.
- 요구사항에 없는 UNIQUE, CHECK와 삭제 정책을 임의로 추가하지 않습니다.
- 검증 파일의 행 수, NULL, 관계와 시간 순서를 모두 확인합니다.
```
