# Chapter 13 실습 코드

## ChatGPT와 Codex로 DB 설계 검증하기

이 폴더는 Chapter 13의 AI 기반 데이터베이스 설계 검증 실습 파일을 관리합니다.

핵심은 AI가 만든 데이터베이스 설계와 SQL을 그대로 사용하지 않고, 사람이 요구사항, 정규화, 기본키, 외래키, 제약조건, 데이터 타입, 보안 관점에서 검토하고 수정하는 것입니다.

---

## 파일 목록

| 파일 | 설명 |
| --- | --- |
| `ai_db_design_review_practice.sql` | AI가 만든 나쁜 설계 예시와 사람이 보완한 좋은 설계를 비교하는 PostgreSQL 실습 SQL |

---

## 실행 전 주의 사항

```text
- 이 파일은 교육용 예제입니다.
- 운영 데이터베이스에서 실행하지 않습니다.
- DROP TABLE 구문은 실습 테이블 초기화를 위한 것입니다.
- 실제 개인정보, 실제 결제 정보, 실제 카드 정보를 사용하지 않습니다.
- AI가 만든 SQL은 실행 전 반드시 사람이 읽고 검토해야 합니다.
```

---

## 권장 실행 환경

```text
- PostgreSQL
- DBeaver Community Edition
- ai_database_book 실습 데이터베이스
```

---

## 주요 실습 항목

```text
- AI가 만든 나쁜 설계 예시 확인
- 하나의 테이블에 여러 역할이 섞인 문제 확인
- 모든 컬럼을 TEXT로 저장하는 문제 확인
- 중복 데이터 문제 확인
- 상태값 제약조건 누락 문제 확인
- 민감 정보 평문 저장 문제 확인
- 사람이 보완한 좋은 설계 예시 생성
- PK, FK, UNIQUE, CHECK, NOT NULL 확인
- 정규화된 테이블 구조 비교
- information_schema를 활용한 메타데이터 점검
- AI 설계 검토 체크 쿼리 실행
- AI 검토 프롬프트 작성 연습
```

---

## 실습 운영 팁

입문 독자는 다음 순서로 진행하는 것을 권장합니다.

```text
1. AI가 만든 나쁜 설계 예시를 먼저 보여 준다.
2. 왜 문제가 되는지 직접 표로 정리한다.
3. 좋은 설계 예시를 실행한다.
4. PK, FK, UNIQUE, CHECK 제약조건을 확인한다.
5. information_schema 조회 결과를 해석한다.
6. 일부 오류 확인 INSERT를 하나씩 주석 해제해 본다.
7. 오류 메시지를 Codex에 전달해 수정 요청하는 흐름을 연습한다.
8. 마지막으로 AI 설계 검토 프롬프트를 직접 작성한다.
```

---

## 학습 포인트

```text
AI가 생성한 DB 설계는 정답이 아니라 초안입니다.
SQL이 실행된다고 해서 좋은 설계는 아닙니다.
좋은 DB 설계는 PK, FK, 제약조건, 데이터 타입, 정규화, 보안을 함께 고려해야 합니다.
Codex는 SQL 파일 작성과 오류 수정에 유용하지만, 최종 판단은 사람이 해야 합니다.
AI 시대에는 SQL 작성 능력과 함께 SQL 검토 능력이 중요합니다.
```
